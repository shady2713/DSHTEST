## 问题

按用途选择模型与桌面手动更新必须保留质量、授权和持久任务状态。

## 提案

状态：产品设计提案；分项探针和原型工作不代表最终实现或验收通过。本文细化[总体设计](2026-09-28-web-testing-architecture.zh.md)的 I04、I05，并给出详细设计对应的验收场景；浏览器和执行见[接口与执行](2026-09-28-web-testing-design-execution.zh.md)，持久化和恢复见[数据与恢复](2026-09-28-web-testing-design-recovery.zh.md)。

阅读顺序：DD10 通用决策与适配 → DD11 模型路由 → DD12 发行与更新 → DD13 验证场景。基座、必要官方补丁和依赖版本统一由[基座与上游升级](../process/2026-09-28-web-testing-upstream-baseline.zh.md)维护；版本固定不等于运行验收通过。

**DD10：通用轻量决策与候选协议**

本节定义可替换的轻量结构化决策能力与领域格式，不绑定 Jev 或其他品牌。至少一种真实轻量模型完成所需候选选择／分类、中文、错误和替换对照；未配置轻量路线的普通用户仍可走合格通用模型，不等于产品可以只留未实现的适配桩。

| 领域对象 | 必需内容与规则 |
|---|---|
| ModelCapabilityDescriptor | 提供方／模型／可定位版本、支持模态与语言、selection／classification 及可选 ranking／scoring、输出约束方式、用量与置信字段语义。未知能力先验证，不能从模型名字推断。 |
| DecisionRequest | schemaVersion、taskKind、observationId、routeRevision、候选集修订、必要状态及完整候选或标签；含 none／reobserve 等退出。输入只保留任务所需材料，秘密不入提示。 |
| DecisionResult | 匹配的请求／观察身份、selected／classified／ranked／scored／abstain 判别、合法候选或标签、可用提供方元数据、原始响应证据引用；缺失结果不能补成成功。 |
| 可选置信信息 | 保留来源、数值范围和具体含义；缺失则 unknown。候选概率、评分、模型自报 confidence 和经验校准各自记录，不互换为正确率。 |
| RoutePolicyRevision | 按 taskKind 与实际能力选择主备路线；绑定编码／校验／校准版本。替换 适配器 或配置时不改变业务动作、断言及报告语义。 |

已有 DSH 适配器 能处理所选提供方时直接复用，由本应用将 DecisionRequest 编码成受支持请求，解析并严格校验输出。提供方若支持结构化输出，按实际接口使用；不支持强制 schema 时仍要完整解析校验并处理拒绝／格式错误，不能假称服务端保证。只有专有协议无法由已有 适配器 表达时才新增 LlmAdapter。自有 schema 留在领域包，不扩展 DSH 核心消息类型，也不搭建与 ctx.llm 平行的模型调用通道。

公共最小能力是有限候选选择和有限标签分类；排序、评分、概率输出均按选用能力启用，不强迫每个模型支持。模型只返回建议，执行器重验观察代次、完整动作候选、权限和目标；即使给出高 confidence 也不能跳过第三方授权或业务断言。能力不符在路由时拒绝，不能删掉图片等必要输入后冒充同一任务。

每次请求保存实际输入、选用 适配器／模型、输出、可用用量、取消和终止事实。辅助请求由 DD08 指定的唯一 Runtime 调度责任管理；不能假设调用一次 ctx.llm 就自动拥有 Agent（智能体） 日志和恢复。所选 DSH V4 支持身份化消息及 one-shot 用户输入，按当前公开构造器／RequestMessage 实现，不继续手造旧 tool-result 包装；purpose 仍只用于上游定义用途，taskKind 留在领域请求中。[当前消息](../../../../packages/llm/llm/src/message.ts)、[请求类型](../../../../packages/llm/llm/src/types.ts)

校验覆盖非法候选、缺标签、不支持模态、畸形 JSON、非有限数字、缺失用量和陈旧观察。替换能力先用不同输出特征的约定对照验证，再对实际采用的路线真实调用与校准；受控替身不能计作第二提供方已实测。不要求先采购两家服务，也不因一个品牌无凭证而阻塞可用替代。

**专有提供方的可选适配。** 优先使用所选基座已有 适配器；仅当候选的实际协议无法表达时，按官方 LlmAdapter／registerAdapter 约定新增。普通聊天选择器不能把仅支持有限决策的模型当作通用聊天替换。专有原语的字段、模型名和 HTTP 地址只进入该适配器的包文档与约定测试，不成为产品领域协议或首版品牌依赖。

适配器明确允许的模态、消息形态、输出约束和参数；不支持的图片、工具、多轮输入或采样参数返回明确错误，不静默删减输入。GenerateOptions.purpose 仅用于上游定义用途，业务 taskKind 留在 DecisionRequest；提供方／模型、sessionId 和 signal 使用 DSH 原字段。若通过单条 JSON 文本承载决策 envelope，先验证版本、候选与原值，不将任意聊天历史强拼成专有请求，也不向核心新增平行消息类型。

校验结果身份、候选集合修订、完整回答与输出类型；可选概率、分数及 confidence 保留各自量纲，不改名为正确率。非有限数字、缺必需答案、非法候选、越界或错误格式不能生成可执行决策。有前后依赖的问题分成不同调用，不假定批量接口自动按业务顺序推理。

提供方 HTTP 仅由 适配器 发送，重试归 DD08 指定的唯一所有者。非流式协议在完整响应验证后映射为 DSH 标准文本块、可用 usage 和 finish；不得伪造逐 token 流或思维块。replayState 使用当前上游允许的结构，保存适配版本、实际模型和可取得的请求身份；终止后不得再发 chunk。没有真实工具调用时不构造工具块。

用量仅映射有明确定义的字段，遵守 DSH 不重叠计数语义；不臆造缓存、推理或零 token。可靠输入／输出计数可求和，缺失标为 unavailable；计费规则与 token 统计分开。所有失败保留请求身份、可靠用量和可处理原因，不能因答案不可用抹去真实调用。

| 失败事实 | DSH 终止及本应用分类 | 后续处理 |
|---|---|---|
| 用户取消或所属任务失效 | aborted，保留取消原因 | 不切换模型重启被取消的工作。 |
| 网络断开、请求超时、HTTP 429／529、暂时性 5xx | error＋status／可用 requestId／providerRetryAfterMs | 由 DD08 的辅助请求恢复队列调度下一次 ctx.llm 调用或能力匹配的备用路由；不假定 Agent 重试插件会覆盖本调用。 |
| HTTP 401／403、缺少密钥 | error，凭证／授权分类 | 保留任务、会话提示修复，不持续重复相同请求。 |
| HTTP 400／422、未知模型、不支持参数或模态 | error，配置／输入分类 | 修正输入或选择合法路线；相同无效请求不无限重试。 |
| 响应字段缺失、概率或候选非法 | error，提供方协议分类 | 保存诊断，禁止执行结果；有限重试或转备用，持续错误等待处理。 |
| 响应完成但观察代次已陈旧 | 模型响应仍成功，业务决策 rejected-stale | 重新观察；不把模型接口成功计为动作成功。 |

失败通过 DSH 已有 LlmFailure／HarnessError 和标准 finish 语义暴露，保留原始事实与分类依据，不把 HTTP 错误当文本答案。具体错误码注册和官方 retry policy 的识别一并实现、验收；自定义不可重试错误不能落入默认“网络错误”的无限循环。提供方错误体字段没有稳定保证时只读取已校验的字段，敏感响应先脱敏。

请求超时与用户取消分别归类：超时是可恢复失败，取消是控制结果，不能只因二者都触发 AbortSignal 就统一标为 aborted。每次真实请求都有 requestAttemptId，等待及重试计数持久保存；采用答案前再次核验当前观察。响应校验失败但用量字段仍有可靠依据时，保留可确认用量和请求诊断，不能因答案不可用把已发生调用抹去。完整辅助请求记录和重试所有者以 DD07–DD08 为准。

**DD11：模型选择、阈值和性能验收**

模型接入先验证实际 Loader 的包清单，再以同一 profile、构建和模型配置对照不加载／加载 web-test 的普通请求。已定位的 REQUEST_EXTENSION 来自裸包名虽能经 tsconfig 加载、但 PluginPackages.packageOf 无法解析 manifest；源码与产物 file URL 的扩展准备对照均成功。这不属于网络瞬态错误，不能用无限重试掩盖；真实提供方请求与失败步骤续发仍需独立证据。所选基座已包含 #5214 多图映射批量删除修复，验证当前组合即可，不另行回移。

R56 的配置流程为：选择提供方与模型 → 专用控件输入或选择已有凭证引用 → 显示连接验证将产生的请求 → 验证连接及声明能力 → 保存有效配置／路由 → 在所属会话显示就绪或具体缺口。复用所选 DSH 的 提供方、配置及凭证机制，通过显式适配满足产品流程，不能另造与 ctx.llm 无关的配置通道。ConnectionProbeResult 记录配置版本、请求类型、时刻及结果，不保存明文密钥；HTTP 可达不等于模型和图片／文本能力可用，必要能力需实际请求验证。

能力就绪按当前任务判定：普通聊天、需求分析、视觉检查和轻量决策分别检查。一个模型可承担多种职责，不要求首启配置全部备用或轻量路线；未配置轻量路线时使用已配置且能力匹配的文本／多模态路线。没有视觉能力时仍可准备材料，但不能把布局检查悄悄降级为只读 DOM 后宣布完成。产品仍须通过 AC18、G05 的真实轻量路线验收；用户未配置与产品未实现是不同结论，不绑定品牌。

凭证新增／替换／删除使用专用敏感输入和受保护存储，不进入 Session 文本、路由输入、skill（技能） 或报告。已有凭证只显示掩码和引用；连接错误保留可处理原因，敏感响应先清理。删除或替换正在使用的配置先展示关联任务影响；新请求使用已生效配置，已发请求保留原 routeRevision 和结果归属。仅修复同一提供方凭证可唤醒任务，改变模型／能力则产生路由策略新版本并核对受影响工作，不能改写历史用量或静默热换整批规则。

官方模型配置控件及凭证服务直接复用；本应用补充用途路由、能力就绪状态和连接验证卡片。M1 验证已有编辑器能否按公开接口嵌入会话；不能直接嵌入时采用同一配置服务的薄适配，仍让用户通过对话与卡片完成首次配置，不复制一套 提供方 后端。官方账户引导和 Coding Tools 配置不能启用本应用禁止的写入工具。

RoutePolicyRevision 保存 taskKind、requiredCapabilities、主路由、备用路由、模型版本、输入生成版本、超时、验证器及晋级条件；运行引用固定策略，凭证修复不改变已记录的历史选择。所有新增模型请求经 ctx.llm，普通对话继续走原生 DSH Agent；不复制 agent-loop，不在 Browser Use 中启用另一个不可追踪的 AI 后端。

| taskKind | 默认能力 | 需要晋级的条件 |
|---|---|---|
| requirements／case-planning／change-impact | 有较强代码与业务推理能力的文本模型 | 源码或规则冲突需要用户确认，不靠换模型决定业务意图。 |
| candidate-selection／page-state-classification | 先匹配合格确定性 recipe；其余按 RouteBenefitDecision 采用已校准轻量或通用路线 | 目标歧义、状态变化、前置失败或模型未达到校准／收益条件时重新观察、晋级或等待，不重放历史成功。 |
| visual-inspection／coordinate-grounding | 具备图片理解的模型 | 图像不清楚或无法对应目标时重新观察或等待条件，不能让文本模型猜图。 |
| exact-value／file-content／numeric-check | 确定性解析与比较 | 语义未定义则询问；无需模型的任务不引入模型判断。 |
| defect-explanation／report-summary | 适合证据归纳的模型 | 输入只能来自已提交事实，输出不得改动计数和结论。 |
| skill-draft | 文本推理模型 | 用户确认差异后才采用。 |

轻量决策模型一次选择完整 actionCandidateId；候选绑定动作、目标、参数引用和观察代次，避免分别选择动作与元素后组合成从未批准的操作。候选由用例、页面观察和策略过滤生成；“确认支付”不因高置信度而绕过真实服务授权。结果只是一项建议，真正执行仍经 DD02、DD03 的校验。

稳定回归步骤可保存 ExecutionRecipeRevision：绑定用例／规则版本、结构化前置条件、语义定位与唯一匹配条件、参数来源、受控动作和确定性断言。每次从新观察解析实际目标，复核身份／环境／数据前置及策略，通过 Runtime 取得当前动作槽位后真实执行并采集新证据。它不保存可跨轮直接点击的旧坐标，不重放未知业务动作，不复用历史 passed；不是额外的 agent-loop 或浏览器控制栈。页面／语义变化、目标歧义或前置不满足时退出 recipe，重新分析或按现有规则等待。

RouteBenefitDecision 按任务类别及已验证分布选择默认路线。对照 A 为通用模型自适应路线，B 为确定性执行＋歧义时调用合格模型，C 为轻量决策参与路线；三组共享用例、必测断言、材料、执行器及授权，分别复位数据并记录顺序，分列首轮与回归轮。候选生成、强模型复核、重试、失败恢复和人工接管全部计入；B 不能因缓存结论跳过真实页面操作。

比较前冻结样本、重复次数、质量约束、主要收益指标和测量容差，独立保留集不参与阈值调优。C 只有在必检缺陷、正确对照、错误动作及未验证数量均满足同一质量门槛，且相对较优合格对照 A／B 的预登记主要指标有超过容差的改善、其他约束未超限时，才能成为对应任务的默认路线。证据不足／收益不成立则保留为已接通能力，默认使用合格的 A 或 B，报告无已证明收益；不为交付轻量能力强制每步多调用一次模型。模型、候选生成或业务分布变化需重验有效范围。

首次使用没有校准证据的模型／语言／动作类时，该路线可作辅助选择，不能凭随意设置的 0.8 就独立驱动业务变更。建立固定样本，选择能满足既定错误动作标准的阈值；达不到时使用强模型核对或确定性目标。校准结果版本化，改变候选生成、模型版本或输入语言需重新评估。高置信度不能替代证据核验，无法校准也不能阻止其他已配置路线继续测试。

缓存键包含输入摘要、模型实际版本、策略／schema 版本、用例与观察代次；缓存仅重用相同静态分析或完全相同决策输入。动态页面、业务状态和模态权限变化使缓存失效；不得用昨天某个按钮的选择结果点击今天页面。只有在查询缓存前能确定所请求的固定模型版本，才允许跨请求模型结果缓存；仅在上一次响应中看到了版本，不足以证明漂移别名今天仍指向它。版本不可固定时禁用这类缓存，记录实际响应版本及限制；同一已提交请求的幂等结果读取不受此限制。

DSH 的 toolUpdate 能力声明与本应用结果缓存是不同机制。只在模型／适配器 实际声明并通过协议对照后使用对应动态工具投影；声明缺失或不支持时走上游兼容路径，不能伪造能力换取缓存。能力声明不证明供应方实际命中缓存或总体节省；RouteBenefitDecision 分列输入、输出、可取得的缓存用量及未知项，把候选生成、复核、重试和恢复纳入相同基线。更换模型或 适配器 后重新核对，不能假定全部第三方模型共享同一收益。

图片文件失效的处理只在实际采用的 适配器 路径启用。使用 DeepSeek 文件上传映射时，P05／V10 覆盖多张图片同时过期、失效映射清理、重新上传和续发模型请求；所需上游修复按基座补丁策略评估。其他提供方按自身接口做等价输入恢复，不强加 DeepSeek 专有文件索引。重新发送前核对观察新鲜度；图像过期可更新同一仍有效观察的提供方引用，页面已经变化则建立新观察。不得重放为这些截图服务的已执行业务动作，也不把模型请求重发计作新业务 Attempt。

性能记录分开统计计划分析、模型等待、浏览器等待、真实业务等待、故障恢复及导出。按上述 A／B／C 三组比较同一用例集、相同断言和环境下的总耗时、全部已知输入／输出 token 及未知用量、调用、错误动作、缺陷检出、误报、未验证数量与用户活动时间；需要强模型复核的开销计入轻量路线。首版不预定“快多少倍／省多少百分比”，也不为达到速度指标删减输入法、原生窗口或流程验证。

**DD12：发行与更新**

基座及依赖版本以[基座与上游升级](../process/2026-09-28-web-testing-upstream-baseline.zh.md)的固定清单为真源，本文不维护第二份版本表。M0 核对真实检出、锁文件、必要官方补丁及 Loader 组合；M5 记录构建产物的 Electron／Chromium／Node、原生驱动、外部浏览器和 Host 协议实际版本。候选 Playwright 与所选模型由承担任务显式冻结，不把锁文件中其他工具的依赖版本当成本应用已经采用。

必要官方修复按明确提交和适用边界登记，完成上游要求及本应用故障对照后才进入可发行组合；禁止浮动跟随 master。工具结果补齐要求由 DD08／V05 规定，图片失效适配由 DD11／V10 规定。任何基础版本或补丁变更均需更新 BillOfMaterials 及受影响证据，不通过静默替换依赖规避基座约束。

用户已确认 C02：首版支持 Windows 10 22H2（build 19045）及以上，以及 Windows 11 x64；更早的 Windows 10、ARM64 不在首版。发行 manifest（元数据清单） 的 minimumWindowsBuild 设计值为 19045，安装前检查同一字段。Electron 44 的公开说明支持 Windows 10+，但这不能代替本应用原生依赖和完整交互的真实验证。[Electron 44 平台说明](https://github.com/electron/electron/blob/v44.0.0/README.md)

验证包含 Windows 10 build 19045 和代表性 Windows 11 x64 的 Home／Pro 环境，并记录完整系统构建与补丁；不能依赖仅 Pro 可用的隔离功能来满足 Home 的普通测试使用。未来若依赖升级要求更高系统版本，需明确提出支持范围变更，不静默提高安装门槛。

应用窗口采用官方桌面布局，目标网页视口独立于应用窗口大小。项目初始化时由用户选择实际要测的 viewport；原生验证记录显示器、缩放、DPR 和输入法。应用窗口适配至少覆盖 100%／125%／150%／200% 的缩放样本及多显示器切换；这些是设计验收样本，不替项目决定网页分辨率。

用户已确认 C03：个人使用首版采用上游提供的 Windows x64 unsigned 本地安装路线，手动安装更新，不启用自动更新。Windows 可能显示未知发布者提示；不关闭系统检查，不伪造签名或正式发布完成记录。未来正式签名发行再保持上游 EV 签名、发布检查和自有更新源要求；代码随官方升级的工程规则不因首版未签名而改变。[DSH 桌面发行要求](../../../../apps/desktop/README.zh.md)

桌面窗口、托盘、隐藏、标准退出确认和安装外壳继续复用官方实现；退出与更新事实由 Runtime 接入。拟定 PersistentActivitySnapshot 含 sampledAt、controlRootIdentity、runId／headRevision／status、未结算动作及恢复标记、读取完整性和错误；数据源为持久登记和各 RunHead，不是 Client 缓存或仅存活的 Agent。适配器只读汇总并调用既有生命周期入口，不把测试状态复制到桌面主进程。

退出查询失败时按可能有未保存／待恢复工作展示官方确认，不以零活动放行；用户明确退出仍停止派发并尽力保存，不能承诺强制终止或系统关机一定完成落盘。普通更新则必须取得完整一致的资格结果，缺失时拒绝覆盖。静态代码显示官方退出／更新检查的 live Agent／Job 范围不能覆盖所有冷会话及持久批次；V06／V14 要在无活跃 Agent 情况验证，不把该推断当作已运行复现。关闭主窗口保持官方隐藏行为，不误入更新或退出流程。

本应用须默认不采集产品使用统计。所选基座的 desktop 装配启用 desktop-product-telemetry 与 product-analytics，导出端默认值包含官方收集服务。本应用首次启动前，须通过自身装配／配置显式禁用采集及关联导出端，并验证生效 profile、目的地址、已排队事件与导出状态。禁止新采集不等于清空已有导出队列。Session 反馈遥测、模型请求和被测服务流量分别说明并验证；保留上游规范，通过应用配置表达选择。

发行 BillOfMaterials 至少记录 appVersion、DSH 标签及构建标识、锁文件摘要、Electron／Chromium／Node 实际版本、Windows 最低构建、原生依赖、所用 profile 和插件集合、Host 协议、领域 schema、DSH 会话格式、报告格式及构建证据引用。安装产物中的 compiled JS 和预生成 Typert 资料需完整；不把开发目录启动成功当作安装版通过。

首版提供普通手动更新和故障恢复更新两条入口。普通更新继续要求活动、恢复、业务时间等待、用户等待及未结算批次先处理；暂停不自动取得迁移资格，不强制取消任务。故障恢复更新用于旧程序缺陷导致任务无法推进的情形：用户在所属会话或安装恢复入口明确选择后，按下述流程封存；无需旧执行逻辑先把任务跑完或把 UNKNOWN 改为已结算。两条路线均不自动下载／热换执行器，不改变 C03。

故障恢复更新顺序：关闭派发并撤销旧许可 → 停止相关 Agent／执行进程并确认其不能继续接收动作 → 在稳定控制根锁下取得一致备份与 FrozenRunManifest → 由支持旧格式的独立预检／恢复入口检查兼容证据 → 登记绑定包摘要、备份摘要和封存批次的 RecoveryUpdateIntent → 用户手动安装／候选数据迁移 → 新版进入 recovery-only → 只读核实历史及在途业务 → 获得资格后建立关联续测。封存以恢复协调器为责任人，不调用已卡住的业务调度器来取得完成确认；无法确认旧执行者已撤权、格式无法读取、备份不一致或迁移不支持时不得覆盖旧组合，提供只读诊断及保留材料的处理路径。

FrozenRunManifest 记录最后已提交头／计划／环境／原执行组合、原暂停与取消意图、所有未结算 operationId、附件和引用清单、封存原因及用户选择。旧批次显示 frozen-recovery，不计结束、取消或通过；原报告与尝试不改写。新执行组合使用新的 runId，并经 RecoveryLink 关联原批次、已核实事实和待补测实例，不能把跨版本步骤拼成一次完整通过。UNKNOWN 留在跨批次核实清单；同一业务意图换 runId 不能重新获得可派发资格。只有可靠证明原动作未发生且不会晚到生效后，才允许按既有规则重新派发；用户选择更新不等于确认动作未发生。

recovery-only 禁止自动业务派发和自动清理，先恢复引用与控制状态并执行获准的只读核实；原暂停／取消选择继续生效。独立且未受未知动作影响的工作可在用户选择续测、环境及用例重新满足后创建新批次；未知部分仍等待核实或报告缺口。应用能够安装修复版与旧任务能够继续完成是两个验收结论，不能承诺任何损坏都可自动修复。

关闭应用不代表全部批次结束。安装预检读取持久任务登记和各 RunHead，覆盖排队、暂停、等待及未知动作。普通路线据此拒绝不合格更新；恢复路线只接受已封存且通过恢复资格核验的批次。旧程序退出后，独立协调器取得 DD07 的同一控制根锁；检查至切换期间，新 Host 不得打开权威存储或接收任务。缺检查器、不识别格式或缺恢复资格均不覆盖，不能猜测没有任务。独立预检的版本、归属及真实安装接入由 P08 验证和 M5-T02 完成。

取得安装资格后，在稳定控制根登记绑定目标安装包摘要的更新意图；安装协调器持锁至安装阶段结束。新 Host 取得同一锁后先处理更新意图，只允许指定版本执行迁移及资格核验，成功后才能开放任务；协调器异常退出或更新意图未结算时进入恢复，不走普通启动。覆盖前保留可验证的原程序和原数据恢复材料；这些是拟新增集成点，须通过 V14 和上游安装检查，不能描述成官方现成的任务保护能力。

同一批次固定应用与执行器组合；故障恢复更新封存旧批次，新组合的实际执行归入 RecoveryLink 关联的新批次，不原地替换旧 Attempt；外部 Chrome／Edge 被系统独立升级时记录实际环境变化，对受影响流程分段或重新执行，不能伪称原版本保持不变。官方插件管理能力在本应用配置中也遵守运行版本固定与源码保护，不能运行中替换 提供方 或装入无限制工具绕过策略。

代码升级保留 upstream／origin 历史，在独立升级分支比较根及嵌套 AGENTS、skill、引用规则、生成器和检查项；文本无冲突仍需语义核对。运行数据迁移先备份到可验证位置，在候选数据代际验证后于同一控制根锁下切换，失败使用原程序与原数据恢复；不把新 schema 数据直接交给旧程序。具体上游继承和修改清单以[升级策略](../process/2026-09-28-web-testing-upstream-baseline.zh.md)为准。

## 风险

模型能力、总成本和更新恢复仍待指定的真实提供方及原生安装场景验证。
