# Agent Note: 可安装 Web 测试插件技术方案与实施计划

Status: proposed

[English](2026-10-04-web-testing-installable-plugin-plan.md) | 中文

## 问题

现有 Web 测试工作包含可复用的业务插件，也依赖对 DSH 桌面、私有浏览器 IPC、应用身份和发行流程的修改。新的交付目标是在未修改的 DSH 应用中安装独立扩展；将当前工作区重新打包不能满足这一要求。

## 提案

本文是技术提案和实施计划，不代表迁移已完成，也不是已验证的安装教程。用户已选择首版采用独立 Chrome／Edge。源码核对以本地原始 `dsh-v0.2.0-rc.2` 基座为依据，工作区新增接口另行识别；用户实际安装版本的兼容性由 S0 验证。定制桌面的验收结果不自动转为插件验收。

### 1. 交付与交互

交付一个可安装包，暂名 `dsh-plugin-web-test`，独立管理版本。包声明 `dsh.bundle.patch`、Host 导出、构建后的 `./client` 导出及 `dsh.client` 元数据。bundle 增加自己的配置行和 Web 测试 Agent 预设；不替换 DSH 可执行文件，不修改 Electron Main，不修改内置默认预设，也不替换共享模型和遥测配置。

首期支持预构建包目录、tarball 和已发布 registry 包，分别通过插件页验证；开发工作区根目录不是可安装包目录。Git 安装仅在验证具有可安装发行根目录的仓库来源及其构建脚本策略后加入。设置中增加本地化的“Web 测试”分区，用于项目、浏览器选择、模型引用、证据存储和恢复偏好。实际测试会话承载计划、进度、问题和报告卡片。“开始 Web 测试”通过已验证的公开接口创建或选择专用测试会话；普通会话不被静默切换预设。

DSH 继续承载交互，Chrome／Edge 显示被测网站。报告记录浏览器产品与版本、视口、启动或连接模式及相关环境事实。Chrome／Edge 中通过不证明同一网站在 DSH 内嵌浏览器中通过。内嵌自动化作为独立兼容能力；缺少公开控制接口时明确记录限制，不因此恢复桌面分叉路线。

### 3. 复用与职责

| 能力 | DSH 负责 | 插件负责 |
|---|---|---|
| Agent 执行 | Agent 循环、模型适配器、请求日志、压缩与取消基础能力 | 测试指令、已确认用例、有界任务推进和业务恢复 |
| 交互 | 对话、提问、审批机制、设置外壳与插槽 | Web 测试设置、测试卡片、项目和报告导航 |
| 模型 | 提供方注册、凭证存储与已有模型配置 | 引用适合的已配置模型，以及可选的按任务选路 |
| 存储 | Session 日志、受支持的 Storage Domain／后端及附件接口 | 项目、版本化计划、运行、动作事实、报告及证据归属 |
| 浏览器 | 现有浏览器／MCP 集成和按 Session 执行的能力 | 允许的目标与动作、角色隔离、测试断言与证据关联 |
| 打包 | DSH 应用和插件管理器 | 可安装 bundle、构建产物、兼容声明和插件数据迁移 |

[原版浏览器服务](../../../../packages/browser-use/browser-use/README.zh.md)登记唯一提供方名称，不提供统一的 click／observe 接口。[Jobs](../../../../packages/jobs/jobs/README.zh.md)是进程内任务，Goals 和 Schedule 也不等同于持久业务测试调度器。已有机制的保证满足需要时直接复用；其未提供的业务义务由小型插件运行协调器承担。

### 4. 包与模块布局

使用独立开发工作区，首期只发布一个运行包。小型 workspace 布局用于核实已有 Typert 构建工具的适用性，不将 DSH 单仓库变成运行依赖。以下为拟定路径，尚未创建：

```text
dsh-plugin-web-test/
  package.json
  tsconfig.host.json
  tsconfig.client.json
  packages/web-test/
    package.json
    cordis.patch.yml
    src/index.ts
    src/agent.ts
    src/config.ts
    src/domain/
    src/projects/
    src/planning/
    src/execution/
    src/browser/
    src/policy/
    src/reports/
    src/remote/
    src/client/
    tests/
    lib/
```

根 Host 入口负责配置、持久化、Remote 服务和生命周期；该行使用裸包名挂载，使原版 Typert loader 能发现产物。发布 `./package.json`、生成的 `./typert` 和 `./remote` 导出；Client 挂载自己的生成 Remote contribution，不修改 DSH 的 api/remotes 包。`/agent` 入口只在 Web 测试预设内贡献工具、提示和执行限制；`./client` 负责设置及卡片。运行导入使用已发布包导出和包内路径；分发产物不能留下未解析的 `../web-test-*`、源码别名、DSH 检出路径或 workspace 协议范围。

直接使用的 DSH／Cordis 运行服务声明兼容 peer；插件自有依赖明确选择打包或声明安装。保持共享 React／Cordis 的实例身份，遵循 Client 模块工厂格式。在本地构建类型化 Remote 产物，不手写第二套 RPC 协议。S0 必须验证生成器对 Host／Client 配置及 workspace 目录的假设。初始兼容声明仅包含实际测试过的 DSH 发布版本；版本号相同不能证明本地补丁兼容。

### 5. 设置、会话与普通 DSH 行为

通过 `settings.section` 和本地化字典注册 Web 测试页。已有项目表单、状态展示及工具结果卡在依赖公开接口时复用。设置保存浏览器选择、已配置模型引用、证据策略和测试默认值；凭证留在 DSH 凭证服务。安装或禁用插件不重写提供方凭证，也不删除共享模型配置。

测试会话显式绑定一个项目及选定环境修订。用户可以独立继续普通 DSH 对话。插件工具、浏览器资源、提示和限制仅作用于已识别的测试 Agent 及其获准子 Agent。源码读取工具只读；继承的编辑、任意终端、动态代码／插件执行及未适配工具不能绕过测试策略。不再为所有会话包装共享 Host 文件或子进程对象。

这延续原要求，是当前用户账户下的应用层控制；预设不是操作系统沙箱。限制必须通过已核对的执行接口落实，不能只依赖提示词。原版工具注册表对继承工具的可见性限制不一定隐藏直接注册在 Agent 上的工具；即使模型看得到某个 schema，测试守卫仍须拒绝禁止的执行。

### 6. 浏览器接入与兼容

S0 首先评估在专用测试预设中挂载官方 [Playwright MCP 提供方](../../../../packages/experimental/browser-use-playwright-mcp/README.zh.md)，按预设服务规则隔离浏览器登记。使用插件自有浏览器档案，登录或接管时显示浏览器；相同场景通过后再支持可选无头执行。连接现有浏览器属于显式选择，不意味着可操作全部个人标签页。

适配层必须限制允许的来源、角色／上下文归属、已批准的文件传输位置和动作类别。上游服务提供某工具，不代表自动授予任意页面执行、文件写入、不受控下载／上传、浏览器配置或外部目标访问。已知操作在派发前验证目标及当前观察。确需页面脚本时，使用输入经过校验的固定插件实现，不执行任意模型程序。

S0 证明官方提供方加 Session 范围执行守卫能够落实动作限制并记录派发结果时，优先采用这一路线。如果拿不到必要的派发前或结果事实，再基于维护中的上游协议和浏览器包实现小型插件 MCP 适配器。该备选只负责连接／工具转换与策略，不自建 Chromium、Agent 循环、Electron IPC 或第二个 DSH 应用。大规模迁移业务代码前确定其中一条路线。

用户安装的全局浏览器提供方也可能接入测试 Agent。隔离浏览器登记服务不等于屏蔽全局提供方的生命周期监听，相同 MCP 服务身份可能冲突。检测不支持的组合并明确提示，不自动禁用用户插件。S0 同时测试干净默认 DSH 和已发现的冲突配置；能否共存属于兼容性结果，不能预先假定。

登录凭证和 Cookie 不从 Session 对话记录重建。原版官方启动封装强制使用隔离浏览器，不提供持久 userDataDir／storageState 配置。插件自有持久档案因此需要单独验证的启动／连接适配层；S0 使用官方提供方时，重启后可能需要重新登录。按提供方支持的方式重连或新建浏览器，再核对账号、租户、页面和环境后恢复。多角色测试要求独立拥有的浏览器上下文；验证提供方实际能力后才能声称角色隔离。内嵌浏览器覆盖与外部浏览器成功分别记录。

### 7. 业务数据与证据

在唯一插件领域名下复用公开的 [Storage Domain](../../../../packages/storage/storage-domain/README.zh.md)。优先在插件自有数据库和隔离的领域服务中使用公开 SQLite 后端，由 S0 在实际 Electron／Node 运行时验证；不修改 Host 的默认存储路由。保存小型运行目录，按需打开历史运行数据。一个 Host 服务拥有写入权；界面、工具和任务均调用该服务。以下是拟定业务记录，不修改 DSH 的 Session 格式：

| 记录 | 主要内容 |
|---|---|
| Project／EnvironmentRevision | 代码根、网址、角色、环境声明、视口及修订号 |
| SourceSnapshot／Requirement | 实际源码版本、可读覆盖、不可变片段／引用、已确认或推断的预期 |
| PlanRevision／CaseRevision | 范围、前置条件、步骤、断言、待答问题、角色及环境要求 |
| Run／CaseAttempt | 引用的修订、阶段、控制状态、进度、等待原因、模型路线和用量观察 |
| Operation | 稳定身份、请求摘要、运行／尝试／步骤、派发状态、观察结果及证据引用 |
| Evidence／ReportRevision | 原始材料、模型规范化引用、环境事实、覆盖／结果及导出清单 |
| Baseline／Correction | 选定比较版本、用户判断、受影响用例及保留的原结论 |
| CleanupPlan | 插件自有资产或新建测试数据、受影响引用、用户决定及实际结果 |

Storage Domain 串行化写入，但不承诺多表事务或跨进程业务排他。先写不可变引用记录，再发布其头记录；动作状态保存在权威记录中，中断后重建派生进度。不能将通知等同于持久提交。S1 保证每个插件数据根只有一个写入者；SQLite 文件锁本身不能同步两个 Host 缓存的业务状态。现有 Windows 归属锁是复用候选。权威记录遇到未知 schema 版本必须拒绝打开，不能表现为数据缺失；需验证这一行为，不能直接采用原版 JSON 逐记录缓存语义。

模型可见输入和工具结果进入正常 DSH 日志。插件业务表保存业务权威；传给模型的事实通过已记录的输入、工具结果及其元数据投影。不新增自定义 Session 事件类型：原版外部插件指南禁止这样做，因为 Session.append 无法将未知事件标为可忽略，后续读者可能无法读取。使用受支持的 followup／inject 和标准工具结算，保证界面插件缺席时历史仍可只读查看。

原始截图和导出文件存入插件自有证据区域，使用经过校验的路径、摘要及引用清单。模型图片和普通 Session 引用使用受支持的附件接口；原件与缩放图明确区分。不依赖工作区新增的文件保留／file-publisher 接口，也不解析不透明 AttachmentId。

删除仅处理用户选中的、无保留引用的插件自有资产。DSH 共享 Session 附件仍由 DSH 管理；清理界面说明两者差别，并报告实际回收字节。保留活动运行证据和回归基线。卸载插件默认保留业务数据；旧应用数据通过版本化的只读导入器写入独立目标，未知动作和历史保持完整。

### 8. 测试执行与恢复

用户流程为选择项目／环境、分析源码与页面、形成候选用例、澄清并确认范围、执行、评估断言、发布报告，最后进行获准的测试数据清理。代码实现提供候选预期，不能自行证明业务正确。未知业务规则保留为问题或覆盖分母中的未验证项。只生成用例不授权业务变更。

阶段与状态分开。阶段包括分析、规划、执行、报告和清理。状态区分排队、执行中、等待用户、等待业务时间、暂停、恢复中、完成、取消和阻塞。运行完成可以包含失败或未验证用例，不等于所有断言通过。

业务变更动作依次执行：持久记录意图；重验环境、范围和目标；保存派发中；派发一次；独立观察并持久结算结果。可能派发后的崩溃或通信中断保留 UNKNOWN。重新规划或换工具调用 ID 不授权重复未解决的同一意图。观察可以确认成功或未执行，否则保留缺口，仅继续独立工作。

暂停／取消先同步关闭本地新动作派发，再保存控制决定并请求取消自有工作。控制决定保存失败单独报告。停止模型调用不会回滚在途副作用。模型／网络重试与业务动作重试采用不同策略。共享测试环境的运行串行调度；角色并发需要明确用例意图及隔离上下文。

插件或 DSH 重启时，在允许派发前读取未完成运行。用户暂停和取消状态保持；其他符合条件的运行仅在核对兼容性、源码／部署变化、账号状态和未知动作后自动恢复。业务等待持久化时间点，在宿主下一次运行时恢复观察。DSH 进程退出后无法继续执行测试；不假定存在自定义更新器或退出否决接口。

### 9. 启用、禁用、卸载与升级

根插件拥有由其测试 Agent 和浏览器适配层共同校验的派发代次。禁用时先撤销代次，再异步清理；拒绝新运行，结算或记录在途未知工作，等待自有进程退出后关闭存储。活动 Agent 可能仍持有已退役预设修订，单纯移除预设定义不够。S0 验证公开 Agent 控制和管理器卸载行为；无法可靠停止自有工作时阻止发布。

不能从通用 disposer 推断用户意图：手动禁用、HMR 与宿主关闭可能共用此回调。S0 必须核实公开管理事件或已选 bundle 状态能否确定持久停止原因。显式暂停／取消始终保存原因。无法分类的通用释放应保留运行，并在重新激活时要求显式继续，不能猜测被用户禁用的运行可以重启；普通崩溃恢复另行处理。S4 验收前须明确重新激活的实际行为。

卸载移除注册和包代码，保留数据与导出。普通 DSH 历史和会话继续使用。原测试会话的预设缺席时，可能需重新安装兼容插件才能继续；只读报告导出仍可使用。受支持的升级步骤为：先暂停并确认插件工作已停止，再安装替代包，管理器返回 restart-required 时重启，然后核对实际加载版本，在已验证数据副本上迁移后再选用。替换包本身不保证管理器已经暂停旧运行实现。旧数据保留，插件不拦截 DSH 自身更新器。

| `web-test-conversation` | 保留工具／Remote 业务方法，仅绑定测试会话 | 普通／测试会话隔离及日志结果 |
| `web-test-presentation` | 保留组件、字典和工具卡，增加设置分区及范围化展示 | 真实 Client 加载及注册释放 |
| `web-test-models` | 优先引用已有配置路线，迁移能力检查，后续迁移多路线逻辑 | 不复制凭证即可使用现有账号；能力缺失明确呈现 |
| `web-test-policy` | 保留决策规则，替换全局装饰及私有接口导入 | 禁止的测试动作被拒绝，普通 DSH 操作不变 |
| `browser-use-web-test` | 保留动作／证据语义，替换私有桌面传输 | 从 DSH 发起的真实外部浏览器流程 |
| Desktop／CLI 补丁和应用启动器 | 保留为历史来源，排除在分发插件之外 | 不需要修改后的 DSH 二进制或检出目录 |
| QuickJS、附件保留和恢复原型 | 仅针对仍存在的具体需求评估 | 每个保留依赖都有具名消费者及受支持的包路径 |
| 旧测试、探针和证据 | 移植适用场景，保留历史结论 | 在实际插件产物上重验受影响路径 |

### 11. 实施阶段

下列顺序负责新路线的交付安排。方案之后的首项实施是 S0，不能先搬完整仓库再验证可安装性。并行工作按模块分配独立写入权；集成人负责安装产物及最终验收。

| 阶段 | 任务与交付物 | 依赖 | 完成条件 |
|---|---|---|---|
| S0：原版 DSH 可行性 | S0.1 记录干净基座／公开导出；S0.2 脱离检出目录构建并安装 bundle＋Client＋Remote＋测试预设产物；S0.3 验证浏览器、SQLite、已有提供方冲突及活动任务禁用 | 用户选定外部浏览器路线 | 原版 DSH 加载非 broken 预设并实际执行一个允许工具；设置／Remote／浏览器可用；禁用后仍被保留的旧 Agent 不能派发；不支持的接口均有明确处置 |
| S1：包与数据基础 | S1.1 固定外部构建／peer 版本；S1.2 配置命名空间、本地化及清理归属；S1.3 存储／写入者设计、兼容检查及 R01–R58 对应 | S0 | 打包产物无检出目录依赖；项目数据重启保留；普通默认配置不变 |

| S3：首个完整测试流程 | S3.1 源码／页面分析及用例确认；S3.2 带动作事实及取消／中断检查的真实浏览器流程；S3.3 证据、报告展示及 HTML／Markdown／JSON 导出 | S2 及选定浏览器适配层 | DSH 发起受控站点测试，发现已知缺陷、记录正常对照，并生成可复现报告；中断的业务变更不被静默重试 |
| S4：持久执行 | S4.1 暂停／取消／卸载；S4.2 崩溃恢复及 UNKNOWN 核实；S4.3 角色／环境调度与持久等待 | S3 | 中断的业务变更不盲目重做；暂停／取消保持；符合条件的工作仅经核对后恢复 |

### 12. 验证与发行证据

单元测试覆盖记录校验、修订冲突、授权过期、范围决策、动作转换和报告统计。会话回放覆盖模型可见计划、问题、工具结果、图片及报告内容。组件测试覆盖本地化设置／卡片和释放。随后通过真实插件管理器及原版 DSH 宿主测试构建产物。

核心端到端场景为原版 DSH 安装、添加插件、选择项目／环境、确认用例、真实浏览器动作、独立核对断言及保存报告。覆盖登录失败、越范围导航、取消业务变更、浏览器断连、重启、图片能力缺失、证据存储不足和插件版本不兼容。独立 Playwright 成功或 mock Host 均不能完成此场景。

使用隔离且兼容的测试 profile 及自有测试浏览器／资源。比较安装前、启用中、禁用后、卸载后的普通 DSH 行为和相关配置；单独测试已有浏览器提供方。验证打包产物时令开发检出目录不可用，防止源码别名和相邻 workspace 依赖掩盖坏包。

真实模型检查使用选定 DSH 路线和受控站点，标准答案不交给被测模型。资源测量包含插件空闲开销、一次真实运行、保留材料及清理；说明观察到的进程和字节，不声称测量了整台机器。完整保留范围的发行还包括原有 24 小时任务验收及 Windows 10 22H2／Windows 11 x64 兼容检查，S3 单独通过不能代替。仅重跑相关输入改变的检查和要求的最终产物检查；完整 DSH 平台矩阵不作为默认插件里程碑。

## 备选方案

**继续定制桌面。** 可保留现有私有浏览器桥，但需要修改后的 DSH 发行和持续应用升级维护，与原版插件管理器安装的目标冲突，因此作为历史实现材料保留。

**只加设置项并打包全部旧代码。** 界面入口不能消除私有导入、全局守卫、应用身份和检出相对路径依赖，必须先抽取和隔离再分发。

**只写 Skill 或通用浏览器 MCP 服务。** 它们可以提供指令和动作，但不能独立满足项目历史、确认计划、业务动作恢复、证据归属和报告流程，可作为插件依赖，不能完全替代插件。

**先要求内嵌浏览器完全等价。** 可保持旧浏览器偏好，但会使独立安装路线受当前缺少的公开控制接口阻塞。首版选用独立 Chrome／Edge；内嵌支持需要独立证据及明确受支持的接入。

## 验收标准

1. 单个包通过原版 DSH 插件管理器安装，不修改 DSH 源码、二进制或默认预设。
2. 设置、类型化 Remote、测试预设和构建后的 Client 从安装产物加载，开发检出目录不可用时也成立。
3. 插件启用期间及移除后，普通会话保留原有工具、模型配置和浏览器行为。
4. 测试会话按已确认用例完成真实浏览器动作，生成持久报告，并独立核对结果和证据。
5. 测试专用限制在执行时强制落实；不安全或未支持路径明确失败，不能从提示或针对其他动作的审批获得权限。
6. 禁用和取消阻止新派发并释放自有资源；可能已发生的在途副作用保留准确结果。重启不盲目重复 UNKNOWN 动作。
7. 保留业务要求具有当前验收对应；外部浏览器成功不表述为内嵌浏览器覆盖。
8. 数据、报告和基线在禁用、卸载及受支持升级后可恢复；删除遵守归属和引用关系。

## 风险

DSH 公共接口和浏览器提供方尚未稳定。外部 Client／Remote 构建、多个提供方组合及活动预设卸载是 S0 的主要风险。验证失败时调整对应接入设计或支持版本，不静默修改用户 DSH。

独立插件仍负责相当一部分测试业务。DSH 提供执行基础设施，不自动提供正确用例、完整覆盖或可安全重复的业务变更。简化交付形式不会消除这些实现及验证义务。

外部浏览器档案、凭证和共享 Session 附件具有不同所有者。登录恢复、空间回收和卸载保证必须符合实际归属。旧数据导入保留历史版本和未知动作，不覆盖之前工作的唯一副本。
