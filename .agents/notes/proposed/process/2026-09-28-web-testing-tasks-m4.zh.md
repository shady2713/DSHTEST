# Agent Note: 开发任务：M4 完整能力

Status: proposed

[English](2026-09-28-web-testing-tasks-m4.md) | 中文

## 问题

新增执行路线与回归能力必须补全同一产品策略及证据模型。

## 提案

阶段准入与当前任务状态以协作指南及其 TaskRegister 为准；历史探针结果不代表这些实施卡已完成。任务接口、改动归属、独立复核、检查和交接格式以[agent（智能体）开发与协作指南](2026-09-28-web-testing-agent-guide.zh.md)为准。改动归属须经 RepositoryMap 解析为真实路径，并在派发时登记。前置完成指交付物已被消费方和独立复核者接收；提交代码或口头宣布完成不等于满足前置，明确标注的分项依赖除外。

本阶段 10 张卡，依赖 M3 的稳定调度。原生、独立浏览器和轻量决策模型分别要求 M0 对应子路线取得真实通过证据；M0 的有限放行不能豁免它们。阶段最终交付不缩减功能，所有路线继续使用统一授权、持久化、控制、证据及报告。

**M4-T01：受控原生提供方与桌面租约**

**目标：** 实现文件框、真实键盘和必要系统交互，保持已确认的当前账户保护等级。

**前置：** `M3-T07`、`M0-T06`。

**阅读：** DD03 全文、P04 原生分项通过证据、AC12／AC23、V08／V09／V13。

**改动归属：** web-test-computer 的唯一 Computer Use 提供方、DesktopLease 和所属测试。

**执行分工：** 原生控制 subagent 独占 Computer Use 提供方和租约适配；同一 Windows 输入桌面只安排一个动作执行器，浏览器后台只读工作可独立进行。

**步骤：**

1. 对照实际 Cua SDK 发现目录和 schema，只映射获准窗口发现、快照、输入及必要剪贴板；不同时装配上游全量原生提供方，不猜工具名。
2. 接入同一控制代次与 DesktopLease，输入前重验窗口／进程／焦点和新鲜快照；原生输入全桌面串行，前台需求不能静默升级。
3. 实现选择／取消／受控保存，不开放文件框删除、启动程序、UAC 或应用自身设置操作；锁屏、睡眠、RDP 断开和用户接管进入环境等待。卸载、SDK 崩溃按持久状态恢复。

**交付：** 原生能力表、租约和实际输入事件、焦点与路径拒绝证据；T03 在复杂 fixture（测试前置数据）验证。

**接续：** T03 消费真实原生输入与焦点拒绝；T10／M5 取得 SDK／系统组合、环境等待及用户接管证据。

**正常验收：** 真实 IME／文件框可作用于归属目标，用户占用可见且只有一个控制者；可后台的独立浏览器工作继续。

**失败对照：** 编辑器抢焦点、链接指向源码、陈旧窗口和危险对话附加操作被拒绝；崩溃不重复已交付动作。

**停止条件：** M0 原生路线未放行或保护无法落到执行处时暂缓；全局输入竞争残余风险按 C01 如实说明，不假称系统级保证。

**M4-T02：受管独立 Chrome／Edge 路线**

**目标：** 在同一 Browser Use 协议中实现内置浏览器受限时的受管替代路线。

**前置：** `M3-T07`、`M0-T06`。

**阅读：** DD02 能力矩阵、DD12、P04 外部路线证据、AC35、V01／V03。

**改动归属：** web-test-browser 外部目标实现、进程／profile 所有权和 Client 目标展示。

**执行分工：** 浏览器 subagent 独占外部提供方实现；可与 T01 并行，但公共观察 schema／控制门由集成人串行合入。个人浏览器与验收档案分离。

**步骤：**

1. 采用核实后的 Playwright 与实际 Chrome／Edge 组合，建立隔离 context／专用 profile，记录启动方式、版本及更新检测，不默认接管日常浏览器档案。
2. 观察和动作输出同一领域协议，接入授权、控制门、恢复、证据与生命周期；如提供 CDP 附着，单独枚举能力，不能视为完整受管启动。
3. 切换路线先核验登录、目标与流程，从可恢复边界继续；不搬运活动页面或无依据共享 Cookie，记录实际执行环境。

**交付：** 外部 BrowserTarget 实现、版本组合及关闭／重建证据；DD02 对应行事实，T03 做双路线对照。

**接续：** T03 消费双路线一致约定；T10／M5 取得实际浏览器版本、能力差异及资源清单。

**正常验收：** 在专用档案完成同一业务流程，身份互不污染，退出后清楚区分可释放资源和保留历史。

**失败对照：** 不支持附着能力、旧目标、版本改变、Host 失联和页面请求宿主控制面明确拒绝／重验；不以关闭隔离解决问题。

**停止条件：** M0 外部路线未放行、个人 profile 混用或必要能力仍不清楚时，阻塞对应场景而不自动标成功。

**M4-T03：复杂交互、身份、完整流程与并发**

**目标：** 把 DD02 能力矩阵变成真实可执行 fixture，补齐完整测试中的交互复杂度。

**前置：** `M4-T01`、`M4-T02`。

**阅读：** DD02 全矩阵、AC09／AC22／AC38／AC40／AC42／AC43／AC50／AC52、V02／V03。

**改动归属：** browser／computer 已有执行器、执行组调度、F1／F2 和证据采集。

**执行分工：** 交互集成 subagent 组织能力矩阵；可分派独立页面材料和只读证据审查，原生测试串行，执行组和公共提供方的修复交原 owner。

**步骤：**

1. 逐项覆盖跨域 iframe／OOPIF／popup、Shadow DOM／Canvas、滚动拖拽、Enter／换行／粘贴／中文 IME、上传下载及内容；实际事件要求不能用直接赋值冒充。
2. 完成密码、验证码／短信码／扫码适用登录和人工接管；以同业务 ID 跨端创建—处理—回查，并验证共同编辑／审批的真实重叠和冲突规则。
3. 固定实际视口／DPR／DPI；补网络／控制台采集、默认关键截图和按需录像，明确原生对话是否入镜及脱敏限制。旧状态导入与新建干净上下文分开。

**交付：** 复杂能力实现、矩阵逐行 fixture 与证据、角色并发时序及内容核验记录；未支持行保留缺口。

**接续：** T08 获得已验证复杂动作；T09 封版矩阵 fixture，T10 复核两路线能力；缺口必须带具体场景及替代是否已验。

**正常验收：** 业务流程同记录完整闭环，适用并发确有时间重叠；录像开启有真实材料，错误下载内容被发现。

**失败对照：** 封闭结构冒充 DOM、失效登录、验证码入导出、两个无关记录拼流程、预览缩放冒充测试尺寸均不通过；DevTools 抢连接可恢复。

**停止条件：** 单路线不支持且无已验证替代时，该必需能力保持未完成，不能只在报告写未验证就关闭产品验收。

**M4-T04：跨时间业务与默认故障恢复**

**目标：** 支持真实等待后的业务核验，并把适用网络异常纳入完整测试。

**前置：** `M3-T07`、`M2-T06`、`M2-T07`。

**阅读：** DD08、AC49／AC51、F3／F5、DD02 故障行。

**改动归属：** Runtime 时间窗口、受控故障租约、后端观察与 F3 材料。

**执行分工：** 时间／故障 subagent 负责窗口与租约；与 T01／T02 同时工作时只改其登记 Runtime 扩展文件，目标控制接口变更交集成人。

**步骤：**

1. 持久保存计划观察窗口、时区、实际时钟和关联业务 ID；等待释放资源并推进独立实例，到时实际观察成功／失败终态。
2. 实现按目标／context 限定的断网、延迟和请求失败，验证缓存／Service Worker 对注入的影响及解除结果，不影响 Host 控制连接。
3. 准备窗口内／外、睡眠重开、错过观察及注入不生效对照；故障和准备同样校验环境，不能擅自停止用户服务或改系统网络。

**交付：** TimedObservation／FaultLease、真实时间与生效／解除证据、F3 扩展；T10／M5 纳入完整组合。

**接续：** T08 复用受控注入，T09 保存实际时间 Oracle，T10／M5 取得睡眠重开及错过窗口证据；模拟时间不替换真实观察。

**正常验收：** 适用异常自动进入完整计划，实际失败与恢复可对应；等待中独立任务运行，到窗口有真实观察。

**失败对照：** 提前触发逻辑、错过时窗、只设置未生效的模拟、解除失败和 HTTP 受理不能冒充最终业务通过。

**停止条件：** 真实时间材料未到窗口只标等待／未执行；需要越权修改服务才可模拟时保留缺口，不伪造后端故障。

**M4-T05：版本、回归基线和用户处置**

**目标：** 让新增版本和历史回归可追踪，用户纠正不改写已发生事实。

**前置：** `M3-T07`、`M2-T02`、`M2-T03`、`M2-T08`。

**阅读：** DD04／DD09、报告规格、AC15／AC30／AC44／AC45／AC47／AC52。

**改动归属：** analysis 变更影响、Runtime 基线与处置、Client 历史／复测卡片。

**执行分工：** 回归 subagent 负责快照比较、基线和 recipe；Client owner 提供历史卡片。可与 skill（技能）逻辑分目录并行，公共 Revision 类型串行合入。

**步骤：**

1. 比较完整源快照及业务预期，展示旧／新用例差异；业务行为改变开测前确认，仅定位变化不反复问同一规则。运行版本信号与源码版本分别记录。
2. 允许选定已确认历史作基线，绑定用例、视觉和规则版本；用真实旧数据／附件／会话缓存验证兼容，缺历史材料就列缺口。
3. 实现误报、符合预期、暂缓修复的版本化处置；新规则形成新用例并实际复测，保留原失败、尝试和报告，未完成批次不替换正确基线。
4. 为已确认稳定步骤形成受约束 ExecutionRecipeRevision：每轮重新观察和校验前置后真实执行，目标歧义／版本变化退出 recipe；未知动作、旧坐标和历史通过结果不得回放。交 M4-T07 作确定性对照。

**交付：** ChangeImpact、BaselineRevision、Disposition／RetestLink 和前后版本真实证据；历史导出与报告可追溯。

**接续：** T07 必须收到真实 recipe、固定用例与复位办法后才能做三组比较；T09／M5 取得原始失败和用户处置的版本链。

**正常验收：** 新版本提示需要确认的真实业务变化，未变规则复用；用户处置有理由和时间，新旧结果都可读。

**失败对照：** 源码 hash 冒充部署证明、刚生成数据冒充旧数据、暂缓当已修复及删旧证据均被拒绝；运行中换版隔离受影响证据。

**停止条件：** 没有可靠版本信号则明确用户声明／未知，不承诺检测到所有热更新；影响未澄清的用例待确认。

**M4-T06：用户 skill 与草案确认闭环**

**目标：** 让用户用对话补充测试知识，并保持当前运行规则稳定。

**前置：** `M3-T07`、`M1-T06`、`M2-T02`、`M2-T03`。

**阅读：** DD04／DD05／DD09、AC19／AC20／AC21、V08／V12。

**改动归属：** 用户 skill 配置／快照／草案服务和 Client 差异卡片；不替换 DSH 开发规则。

**执行分工：** skill subagent 负责发现、快照及草案确认；不改官方研发 skill 正文。Client 和配置入口由对应 owner 合入，独立验收者尝试脚本／依赖越界。

**步骤：**

1. 接入全局／项目 skill，记录适用范围、冲突、来源和版本；冻结实际引用的本地规则依赖及内容，不仅记录路径。
2. 通过普通对话或测试经验生成具体差异草案，用户接受才产生可用新版本，拒绝／未答复不生效；保存草案与确认关联。
3. 运行批次继续原规则快照，新任务可用新版；skill 脚本、PTC、MCP 不扩大工具权限，知识模板不冒充真实执行能力。

**交付：** SkillRevision／DependencyManifest、Draft／Acceptance 和加载证据；用例能引用确切生效规则。

**接续：** T09／M5 获得确认前后版本和依赖快照；活动 Run 继续旧引用，新用例消费新版本，不能静默重规划活动任务。

**正常验收：** 接受草案后新用例体现规则，旧运行仍读取冻结材料；项目无关会话不自动带入其他项目 skill 内容。

**失败对照：** 运行中改原文件及依赖、无效内容、越权脚本、未答复草案和旧确认重放不会悄然改变活动规则。

**停止条件：** 无法冻结依赖或冲突影响预期时提具体问题，不能自动覆盖用户规则或上游工程要求。

**M4-T07：轻量决策模型正式适配、校准与性能比较**

**目标：** 交付可审计的有限候选决策路线，并用同等测试质量衡量收益。

**前置：** `M3-T07`、`M0-T07`、`M4-T05`；M0 轻量路线分项已通过，且收到 T05 的稳定回归 recipe 与同一用例材料。

**阅读：** DD10／DD11 全文、P05 轻量决策模型分项通过证据、AC18、V10／V11、G05。

**改动归属：** 可复用的 DSH 适配器或按需新增提供方适配器、路由候选构造／校准和 Session 对应测试。

**执行分工：** 模型 subagent 实现适配与校准；独立评测 subagent 管理保留集并执行 A／B／C，对照 recipe 由 T05 owner 提供。三组复用固定负载但独立复位，避免污染缓存与数据。

**步骤：**

1. 经 ctx.llm 接入统一 DecisionRequest／DecisionResult，至少实现一种真实轻量模型的候选选择／分类；优先复用既有适配器。只验证实际选用适配器的能力和专有协议，按提供方官方证据适配；不强迫实现其他提供方原语，不伪造模态、置信或评分。
2. 候选包含完整动作、目标、参数及观察代次，执行前再校验；接 M3 唯一辅助重试、取消、用量与真实 Session 记录，保留 requested／actual model。
3. 建立独立校准集和保留验证集，无阈值证据先由强模型或确定性路径核验；模型／语言／候选生成变化重新校准，漂移别名禁跨请求缓存。
4. 按 DD11 预登记 A 通用模型、B 确定性执行＋歧义处理、C 轻量参与三组，固定用例／断言／数据并分别复位；测总耗时、已知输入输出 token 与未知用量、错误动作、检出／误报、未验证和人工时间，计入生成候选、提供方实际缓存用量、强模型复核及恢复成本；toolUpdate 能力不支持时不假设其缓存收益。冻结主要收益指标与容差后判断，不在看结果后换指标。

**交付：** 正式适配组合（优先复用，缺口才新增适配器）、CalibrationRevision、路由与缓存规则、真实提供方和成对性能报告；不预定提速倍数。RouteBenefitDecision 明确：能力接通／质量合格／收益成立分别记录；只对质量及收益均合格的任务类别默认启用轻量路线，未证明收益时保留能力并使用较优合格对照。

**接续：** T09／T10 接收真实轻量能力和 RouteBenefitDecision；默认路由只启用合格类别，无收益不移除已实现能力，也不把失败路线伪称提速。

**正常验收：** 至少一种真实轻量路线经校准可用，中文和边界可验证；通用路线也工作。更换适配器／配置的约定对照不修改调度、执行器或报告结构，未真实调用的第二提供方不得称已实测。

**失败对照：** 非法候选／标签／评分、不支持能力、陈旧观察、认证／限流／临时故障、取消与缺用量有正确结局；提供方专有错误按实际协议增加对应对照，置信不能放宽授权。增加轻量调用变多却整轮更慢、错误增加及无显著收益的样本，验证不会因此成为默认路线。

**停止条件：** 无任何真实轻量路线证据则此卡待外部条件，可改选合格候选；不能用浏览器直连 SDK、任意阈值或删断言宣称达标，不绑定 Jev 账号。

**M4-T08：按需性能、负载与安全专项**

**目标：** 把可选专项做成真实能力，保持用户未选时不执行。

**前置：** `M4-T03`、`M4-T04`、`M2-T06`。

**阅读：** AC11、R11、F6、DD04／DD07、环境和第三方授权规则。

**改动归属：** 专项用例／执行适配、受控观测与 F6 fixture；沿用统一动作和报告协议。

**执行分工：** 专项 subagent 负责受控性能／安全适配，独立者核对实际负载和已知问题；与其他动作验收分离目标环境，所有副作用仍走同一许可入口。

**步骤：**

1. 提供自然语言／选项配置目标、范围、负载参数及预期阈值，明确具体请求和数据副作用；只针对用户合法控制且范围已确认的环境。
2. 构建有限受控的性能／并发负载与访问控制等安全对照；采用核验后的实际工具入口，不把建议文字当执行结果。
3. 记录实测速率、延迟、错误与资源，校验注入达到设定；未设业务阈值只报告测量，不擅自判质量达标。

**交付：** SpecializedPlan、F6 正常／已知问题材料、实际测量与报告示例；T09 纳入最终材料。

**接续：** T09 获得 F6、范围和指标定义；T10／M5 复核未选择不执行、取消停止新请求及未知阈值仅报告事实。

**正常验收：** 用户选择后能执行并发现已知问题，范围与速率可核对，取消能停止新请求。

**失败对照：** 未勾选却执行、参数无效、生产范围不足、实际压力量未达到而宣布通过均被拒绝；专项不解除源码保护。

**停止条件：** 未获具体专项／环境授权时不施加负载或攻击性请求；缺工具证据标未执行，不减少首版可选能力承诺。

**M4-T09：F1–F6 完整材料与独立标准答案**

**目标：** 在正式验收前把所有材料封版，保证检验能推翻错误实现。

**前置：** `M4-T03`、`M4-T04`、`M4-T05`、`M4-T06`、`M4-T07`、`M4-T08`。

**阅读：** 验收标准全文、实施计划材料表、DD13、各功能交接包。

**改动归属：** 官方测试材料、版本清单和独立验收依据。

**执行分工：** 独立验收材料 subagent 封版，材料 owner 修缺项；不得由产品执行 agent 读取隐藏答案后再充当陌生项目验收。

**步骤：**

1. 将六类材料逐项关联 58 条 AC、18 条 V 及能力矩阵，复核源码、数据、历史、角色、原生环境和故障注入均可取得。
2. 封版种子、初始化／复位、正常与错误对照、独立 Oracle；保留校准之外的验证样本，不能用调参数据充当全部验收依据。
3. 把 F4 真实旧记录／附件和变更链、F5 实际故障证明、F6 授权范围写清，检查秘密和可识别数据是否进入可交付材料。
4. 增加未参与调优的陌生项目保留材料，延续 P06 的独立答案、功能分母及人工参照；复核错误实现自洽时不会获业务通过，答案泄漏样本不得计验收。

**交付：** 最终 FixtureManifest、AC／V→fixture／Oracle 索引、复位与使用说明；M5 直接消费。

**接续：** T10／M5 接收 Manifest 与 AC／V 索引；失效、泄漏、不可复位材料退回来源卡，不通过改 Oracle 凑通过。

**正常验收：** 无聊天历史的验收 AI（人工智能）可建立环境，按编号取到正常和能拒绝错误实现的对照。

**失败对照：** fixture 缺失、假历史、答案泄漏、只测自报或修改 Oracle 迎合当前错误的情况必须退回。

**停止条件：** 任何必需验收无材料时保持未完成并指出建设主责；不能把难准备的场景改为不适用。

**M4-T10：能力一致性、完整预算与阶段门槛**

**目标：** 在进入发行验收前收齐所有路线和资源标准，消除运行期才发现的差异。

**前置：** `M4-T09`。

**阅读：** DD02 能力矩阵、实施计划 ResourceBudgetRevision、全部 M4 卡与 V01–V18。

**改动归属：** 双路线集成测试、能力记录和最终资源预算；不复制另一套支持状态表。

**执行分工：** 集成主 agent 核对一致性，独立资源验收者测全组合；能力事实只维护 DD02，一处变更通知全部消费方。

**步骤：**

1. 按实际 profile 逐行核对矩阵，记录版本、条件、支持／受限／不支持、证据及替代；内置和外部路线输出相同领域语义，差异明确。
2. 覆盖原生、独立浏览器、录像及组合并发的资源测量，冻结全组合数值和参考环境，包含内存峰值／斜率、句柄释放、磁盘和控制延迟。
3. 核对所有承诺能力有合法路径，残余限制与报告一致；更新设计中的已证实细节，不把未实现写成不可测用户项目的问题。

**交付：** M4 GateEvidence、DD02 实际矩阵、完整 ResourceBudgetRevision 和发行输入清单。

**接续：** M5-T01 取得冻结候选输入、全部路线和数值预算；任何实现／模型策略／依赖改变都需标记受影响证据。

**正常验收：** 必需能力有已验证路径且限制透明，预算在 M5 启动前已有数值；不同路线失败语义一致。

**失败对照：** 仅一种路线成功冒充全部、原生对话未入录像却宣称全录、缺预算和改阈值包装通过均不放行。

**停止条件：** 任何首版必需能力未验、轻量决策模型只有桩或新增路线未测量时，不进入完整交付判定；明确回到对应任务修正。

**阶段交接门槛**

F1–F6 封版，DD02 全矩阵有真实状态及必需能力的合法路径，轻量路线与通用路线分别可验，复杂业务与历史回归完整。所有新增组合的数值预算在 M5 前冻结；依赖外部条件的必需能力不能以“以后再做”换取阶段通过。
