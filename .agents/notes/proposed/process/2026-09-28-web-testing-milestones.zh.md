# Agent Note: 开发里程碑与验证计划

Status: proposed

[English](2026-09-28-web-testing-milestones.md) | 中文

## 问题

完整范围需要明确建设顺序，在依赖实现之前检验不确定集成及产品有效性。

## 提案

[可安装插件计划](../architecture/2026-10-04-web-testing-installable-plugin-plan.zh.md)以 S0–S6 定义新选定交付路线。下文 M0–M5 任务卡继续提供业务场景和历史证据，原来的整阶段准入顺序不自动成为新插件可行性工作的前置条件。已有结果保持原范围。

交付状态：M0 未通过。用户已撤销等待上游内嵌浏览器的决定；恢复有界的受控浏览器接入及[明确准入的 M1 子项](2026-09-28-web-testing-tasks-m1.zh.md#development-admission)，其实现不代表整卡或阶段通过。当前状态由[协作指南](2026-09-28-web-testing-agent-guide.zh.md)维护，[基座规则](2026-09-28-web-testing-upstream-baseline.zh.md)固定 dsh-v0.2.0-rc.2；新组合验收前须复验受影响证据。

本文件回答先做什么、依赖什么、取得什么证据才能继续。[需求 R01–R58](../feature/2026-09-28-web-testing-requirements.zh.md)规定交付范围，[AC01–AC58／G01–G16](../testing/2026-09-28-web-testing-acceptance.zh.md)规定验收；分阶段建设不删减首版承诺。接口与数据仍归属三份详细设计，本文件不重新定义它们。

向开发 AI 派发工作的入口为[Agent 开发与协作指南](2026-09-28-web-testing-agent-guide.zh.md)。该指南及六份阶段任务卡把本计划细化为 50 项工作，明确前置、归属、交付、正常／失败对照和停止条件；[覆盖与交接表](../testing/2026-09-28-web-testing-development-coverage.zh.md)将全部 AC／G／V 分配到主责任务。subagent 的分派、共享文件锁、独立审查与交接协议统一使用该指南；取得开发授权后由主 agent 按依赖持续安排，不要求用户逐卡派发。

**实施顺序与阶段退出条件**

每一阶段产出都包含实际基线、变更、适用官方检查、正常和失败对照及未完成项。阶段演示可以只覆盖部分功能，必须标注范围；阶段通过不等于产品交付。只要涉及源码保护、环境授权、动作去重和状态保存，约束从第一条实际动作起生效，不能等到后期补安全和恢复。

| 阶段 | 建设顺序与依赖 | 必须形成的结果与退出条件 |
|---|---|---|
| M0 | 核对固定基线，准备最小材料，执行 P01–P08 并审查集成成本；执行顺序按任务依赖而非编号。T08 现在可审阅未齐备证据并记录有限子项准入。 | 完整准入仍须 P01／P02／P03、P05 主路线及失败工具结果恢复、P06／P07／P08 具备继续证据；原生、外部和轻量子路线可限定暂缓，最终承诺不删除。 |
| M1 | M0 未通过期间，按[开发准入表](2026-09-28-web-testing-tasks-m1.zh.md#development-admission)限定推进。先完成插件装配与实际身份隔离，再实现现有路径消费的定义及最小存储；配置、策略和普通对话按各自前置接续，真实浏览器观察依赖 P01／P03。 | 从真实桌面入口完成配置、项目接入、观察及重开读取；源码与宿主隔离、凭证不入聊天的失败对照有效。形成后续资源预算的测量基线；限定子项完成不代表这些完整退出条件通过。 |
| M2 | 基于 M1 完成材料、全项目分析和确认用例，再接真实动作与最小持久调度、断言、后端观察、数据台账和报告，最后从对话端到端联调。 | 一条已确认业务流程完整执行并出报告；正常与植入缺陷可区分；动作意图／结果提交与基本崩溃恢复从此阶段即有效。 |
| M3 | 扩展 M2 的恢复路径、等待、重试、停滞检测、空间管理及用户接管。 | 相关恢复矩阵和 R55、R57、R58 通过；不重复业务操作，空间不足和模型故障不丢任务，大附件不阻塞停止派发；冻结已实现组合的资源预算。 |
| M4 | 基于既有统一执行协议扩展受控原生 provider、独立浏览器、多角色、复杂页面及业务并发；相关路线须先通过 M0 探查。 | DD02 能力矩阵逐项取得证据；复杂业务场景可执行；通用路线及采用合格轻量决策模型的路线分别正确；测量新增路线并在 M5 前冻结完整组合预算。 |
| M5 | 所有承诺能力及材料齐备后，进行完整回归、24 小时运行、原生安装和升级验收。 | AC01–AC58、适用 G01–G16 和 V01–V18 均有真实证据；预算、能力矩阵、报告及已知限制一致，未验证必需能力不计交付。 |

工程落点沿用 DD01：先建立当前使用方需要的 web-test 定义、web-test-runtime、最小应用装配及 browser，随后加入 analysis、client 展示、受控 computer 和按需提供方 adapter。policy 的约束从 M1 生效，不能等独立包完成才执行；首个包不预造全部终态抽象。普通 DSH 对话在 M1 贯通，Skill 草案／确认与项目分析在 M2–M4 逐步加入；完整 Skills 能力仍按原验收交付。

**各阶段的集成与审查责任**

主 agent 负责基座、依赖图、接口版本和阶段放行，最多同时安排三个边界明确的 subagent。优先并行互不重叠的调查、材料建设和模块实现；修改 schema、profile、依赖锁、生成物、主调度文件及 Host 协议由指定集成人单写。每张任务卡的“执行分工”和“接续”明确委派边界及消费方，具体目录在 M0 的 RepositoryMap 固定。

| 阶段 | 推荐职责组合 | 集成前必须核对 |
|---|---|---|
| M0 | 桌面探查、存储探查、模型探查可并行；独立材料／Oracle 维护者与产品执行 Agent 隔离上下文。 | P01 与 T07 主路线／恢复实现通过后才验完整 T05，独立生命周期子项可先行。T08 现在可记录阶段未准入及允许子项，完整收口须齐备全部必需证据；不让任一路线自评替代独立证据。 |
| M1 | 主 agent 装配和约定；模型与策略分目录并行；Client 和浏览器按前置接续。 | 官方壳／配置复用与测试专属逻辑分清；热启用工具和人工审批仍受硬限制。 |
| M2 | 分析、执行、报告按真实产物依赖顺序交接；材料可独立扩充，正常／缺陷验收由独立者做。 | T07 依赖报告约定，不依赖尚未完成的报告实现；T08 集成真实报告后清理，避免双向等待。 |
| M3 | 恢复协议先冻结；模型重试与控制适配可在文件隔离后并行；空间及停滞使用同一状态源。 | 官方 Jobs／Schedule 不替代 Runtime；全部持久批次参与退出和更新，失败工具结果与业务 UNKNOWN 分别验收。 |
| M4 | 原生、外部浏览器、时间、回归、Skills 按槽位和目录调度；轻量评测必须等 T05 recipe。 | 共用桌面输入不能并行；模型对照采用相同负载并各自复位；新增资源组合重新测量。 |
| M5 | 产品验收与 24 小时资源验收可在同一冻结候选、独立设备和数据下并行。 | 任一实现修复都标明受影响证据并重验；原生平台、源码状态、补丁组合与安装产物一致。 |

官方工程检查伴随每次改动执行，阶段末只补组合与独立复核。subagent 报告完成后，主 agent 检查实际 diff、命令结果和交付文件，再安排独立审查；有争议时回到事实和验收，不以多个 Agent 同意当作通过。缺少外部凭证或设备时先执行无依赖工作，受影响任务保持待条件并保留再入路径。

**M0：有界的前置技术验证**

M0 是证伪关键假设与产品有效性的阶段，不是缩减版产品。P01–P05 各最多 8 个有效工程工时，P06 最多 16、P07／P08 各最多 8，八项初始探查合计最多 72 工时；准备、独立答案及总结另记，外部等待单列。这是初始验证时间盒，不是完成承诺、模型费用额度或用户测试任务上限。启动时登记负责人、版本、设备、起止及预算；#4595／#5214 等上游修复的升级归并与回归计入对应 P05，超出时如实登记剩余问题、已用时间和追加或重分配决定，不以初始 72 工时保证完成。主 agent 可在既有开发范围内调整工程安排；改变范围、基座或保护程度另行决策。不能反复重置计时或把超时包装为通过。

| 探查 | 最小操作与失败对照 | 继续条件／失败后的处理 |
|---|---|---|
| P01 桌面与受控执行 | 先恢复可运行的 Electron 环境，再按 [M0-T03](2026-09-28-web-testing-tasks-m0.zh.md)为现有 webview 接入有限 Host／Main broker。真实 Loader／profile 下，用独立 WebContentsView 做相同观察点击、角色分区、popup／下载、焦点、视口、关窗保留及失联撤权对照，记录隔离证据。 | BrowserCarrierDecision 同列能力、生命周期和 IntegrationSurfaceRegister 成本；不预选载体，也不把 Electron 启动失败推断成 API 不支持。主页面探针不足以通过完整 P01；真实浏览器依赖项等待对应证据，独立 M1 子项按准入表推进。 |
| P02 持久数据与恢复 | 经 storage domain 创建批次、保存意图和证据引用；在入口发布、业务已执行但结果未提交、通知投递处中断；重送命令与旧动作槽位。比较 1 千／1 万／10 万条代表性记录的打开、查询、提交及恢复成本。 | 不多建资源、不重复业务、不丢已提交事实；实际内存与耗时可解释。记录证明哪些分段／检查点必要；单次写入演示不足以通过。失败优先简化合法领域方案，不绕过官方存储机制。 |
| P03 控制与资源生命周期 | 消费 P05 已通过主路线及恢复实现后，两个角色上下文执行有重叠要求的动作；制造部分工具结果已存而后续调度失败、长等待、大附件保存、旧结果晚到及 Host 重建；请求暂停。 | 角色隔离，同 Agent 无嵌套队列死锁，暂停阻止新派发，状态保存如实，旧代次不能继续操作；会话配对修复后未知业务仍先核实，不盲重发。不能满足则调整执行组和提交安排后重验。 |
| P04 原生与双浏览器路线 | 在 Windows 上验证一条原生文件框／输入流程和一条受控独立浏览器流程，记录目标、焦点、权限、档案与视口；加入不允许目标对照。 | 两条路线可关联同一用例与证据，限制有效；只通过普通 CDP 点击不能证明原生输入。不可用的承诺能力阻塞 M4 相关路线，不将矩阵改成“不需要”来通过。 |
| P05 模型与辅助请求 | 经正式 LlmAdapter／ctx.llm 做一次真实主路线调用和至少一种候选轻量模型的选择／分类；验证 Session V4 记录、超时／限流／取消及等待重开；验证所选基座已包含的 #4595／#5214，登记保留本地改动及相关检查，对照不加载／加载原型的普通请求，并实际续发失败步骤之后的模型请求。 | 请求、用量、唯一重试责任及消息配对恢复可追溯；TOOL_OUTCOME_UNKNOWN／TOOL_NOT_STARTED 不等于可重放业务动作。主路线缺少恢复实现验证不得放行 M0；轻量候选不可用可改选其他合格模型，不绑定 Jev。没有任何真实轻量路线证据时保留该能力阻塞，可推进无依赖工作；不静默降级能力。 |
| P06 产品有效性 | 用未参与执行逻辑开发的项目材料及预登记业务子集，经 DSH 最小链路分析、确认、操作与报告；加入实现明确但业务规则错误、正确对照及重复回归。 | ProductEffectivenessProtocol／Result 按下述独立答案与人工参照判断；不能用运行成功或工具自己的清单当效果证据。失败先限定修正，不全面展开 M1–M4。 |
| P07 附件生命周期 | 查明所选 AttachmentStore 缺口，在所属抽象／provider 验证最小引用保留与删除协议；普通 Session／fork、报告及读写票据共享同一对象，加入发布与删除竞态。 | 取得 AssetLifecycleDecision，明确实际公共约定、所有者覆盖及检查成本；引用不明保持保留。缺可行合法路线时阻塞长期资产架构与 AC55，不延到 M3 才决策。 |
| P08 故障恢复更新 | 以最小持久批次制造旧调度逻辑无法推进，含 UNKNOWN 和主动暂停；独立协调入口封存、验证迁移候选并进入 recovery-only。 | RecoveryUpdateDecision 证明无需旧任务完成也能获得恢复更新资格，未知动作不重放；记录真实安装接入位置及未验部分，M5-T02 再验真实安装包，探查不冒充发行通过。 |

每项到时必须形成 ProbeResult：假设、版本与环境、操作、失败对照、实际命令和证据、耗时、修改范围、结论及后续依赖。超时没有足够证据即为“暂缓”，不是失败已被证明，也不是通过；需要进一步探查时先明确剩余问题及追加时间盒。发现会扩大底座修改或改变产品承诺的方案时提交具体设计取舍，不默认删功能、解除只读或替换 DSH。

M0-T08 可以在记录 M0 未通过的同时，仅放行前置证据已核实的[表内 M1 子项](2026-09-28-web-testing-tasks-m1.zh.md#development-admission)。集成人逐项登记消费的证据和停止条件；这不等于整个 M1 准入，也不允许绕过浏览器前置。M0 的运行材料不能冒充完整 AC 验收；探查代码若保留进正式工程，仍须按官方归属、类型、测试、文档及检查要求整理，不保留临时绕过或平行 agent-loop。

**P06：有限规模的产品有效性门槛**

P06 在 M0-T09 执行，不依赖完整 M2／M4 实现。复用已通过的最小 DSH 装配、模型、受控执行和持久边界，完成有限业务子集的分析到报告链路；不预建终态框架，不为演示关闭保护。Probe 代码保留入产品仍须符合官方检查。P06 与 P07／P08 的发现共同约束 M0-T08。

验收方预先固定 ProductEffectivenessProtocol：至少一个未为本工具定制的可合法使用项目快照、明确有限的业务子集、初始数据与复位方式、正确与缺陷对照、用户可提供规则、仅验收方掌握的功能／缺陷清单、逐项严重性、验证次数和顺序。包含实现与意图不一致、规则尚未提供、视觉／交互错误及正常行为。答案不作为项目普通文件或模型上下文输入；不得让执行 Agent 读取验收日志或缺陷清单。校准／修正材料与保留验证材料区分，看到答案后修正需使用新保留对照再作继续判定。

记录功能识别数／预登记必检数、已检出缺陷／已知缺陷数、误报、错误业务通过、未验证数，以及用户澄清条数、准备／接管／复核活动分钟、总耗时与模型用量。需求未知时提出正确问题不等于检出缺陷；用户确认后必须真实补测才能计检出。人工参照采用相同范围、数据、操作和报告要求，记录测量顺序与熟悉度；首轮准备成本和同版本回归成本分别报告，缺人工实测参照不编造收益。陌生项目的原版不得为本工具量身构造；缺陷对照可在独立研发材料副本中预先制作，产品执行时仍不能修改被测源码。

初始继续条件仅针对这个预登记小样本：必检功能都被识别并纳入用例；提供必要规则后，必检已知缺陷都被证据识别；正确对照无误报，未确认意图无错误业务通过，必须验证项无被隐藏缺口。用户已将人工参照对比延期至 M5；保留为未验证效果条件，不能记为 M0 通过。最终验收前，至少一次同范围回归的用户活动时间须低于人工参照，机器耗时另列。未满足任何项则调整／暂缓；可继续已授权的局部修正和独立探查，但不放行依赖性全面建设。不声称这个小样本证明所有项目零漏报；M2／M4 扩充保留材料，M5 仍按全部 AC 验收。样本和门槛在执行前冻结，不在看结果后删缺陷、改正确答案或缩小范围。

**验收材料的建设计划**

F1–F6 是六类材料，采用可组合的小型样例与一个代表性业务系统，不要求六套完整应用。每份材料有版本、确定的初始数据、预期结果、已知缺陷、正确对照、恢复到初始状态的方法及适用编号。预期清单由验收方独立维护，不能由工具自己生成后充当标准答案；植入缺陷的对照答案不作为普通项目需求输入。

| 材料 | 最早投入及逐步扩展 | 必须保存的独立依据 |
|---|---|---|
| F1 页面与输入 | M0 提供点击、输入、文件框和两角色最小样例；M4 前补齐复杂页面、IME、视觉正常／异常及各视口。 | 交互事件、目标状态和正确布局；同样输入的正确／错误结果。 |
| F2 完整业务系统 | M0／M1 准备最小双角色创建—审批—查看流程；M2–M4 扩展多目录、多入口、驳回和共同编辑。 | 同一记录的合法状态变化、角色可见性、正确与植入缺陷版本；代表性不同语言源码材料。 |
| F3 后端与时间 | M2 建立异步入口、日志／只读核验；M4 补齐真实时间窗口与失败终态。 | 受理不等于完成、到期规则及观察事实，模拟时间和真实经过时间分开。 |
| F4 历史与版本 | 从 M1 起保留真实产生的资产；M2–M4 建立两个业务版本及旧附件、规则、Cookie／缓存样本。 | 原版本来源、变更／未变更对照和兼容预期，不用刚生成数据冒充历史。 |
| F5 运行故障 | M0 起建立中断点；M3 补齐存储、模型、通知、空间、停滞及晚到返回。 | 故障是否真的施加、目标是否执行、持久化边界和恢复后外部状态。 |
| F6 可选专项 | M4 准备受控性能／负载与访问控制场景，M5 验证工具的专项能力。 | 明确目标及已知问题／正确对照；真实生产服务不作为故障材料。 |

材料准备尽早与分目录实现并行，公开输入与隐藏 Oracle 分开；真实历史只能由前阶段产物形成，不能因并行准备而伪造。涉及同一目标环境、原生桌面、控制根或资源验收机器时串行使用，避免互相污染。研发用样例和故障注入归属官方测试体系；运行本产品测试用户项目时，仍不能修改被测源码、安装依赖或自行部署旧版。第三方提供方允许在分类故障验证中使用受控替身，但真实请求、DSH Loader、存储和实际执行者的必要验收不能全部由替身代替。

**资源预算的测量与冻结**

V07 的“内存可控”必须转为下面的可判定标准。先在 M0／M1 测量并提出候选，M3 结束前冻结已实现组合的 ResourceBudgetRevision；M4 新增路线须单独测量并在进入 M5 前冻结完整组合。M5 的 24 小时验收不得在缺少数值或运行后改阈值的情况下启动／宣布通过。历史测量尚不能构成所选应用组合的冻结预算，复用前须审计采样及输入；下表列出必需字段，不虚填 GB 或句柄上限。

| 范围 | 运行前必须固定的参数 | 判定方式 |
|---|---|---|
| 参考环境 | Windows 构建、CPU、RAM、磁盘类型及空闲量、DSH／依赖版本、视口／DPI、页面和角色并发数、录像模式、材料规模及随机种子 | 结果只适用于所列配置；最低支持系统与代表性 Win11 均保留原生证据，不将参考机等同产品唯一支持设备。 |
| 内存 | 全部受管进程的 private bytes 峰值上限、Host 单独上限、预热时长、采样间隔、等负载稳定窗口与允许增长斜率 | 统计 Main、Host、Renderer、受管独立浏览器和必要原生进程；用户服务独立统计。完整时间序列不能只报最后一次值；缺采样显式记录。 |
| 句柄和资源 | 各进程句柄／线程峰值、活动目标与子进程上限、释放等待时长、重复创建／销毁循环后允许残留量 | 通过完整生命周期对照判断；运行中合法缓存不直接判泄漏，但必须有边界和解释。 |
| 磁盘 | 各采集模式的记录／证据增速上界、每动作或每分钟材料预算、未引用临时材料允许量、预警余量、控制记录预留空间及写入检测周期 | 区分必要证据的合理累计增长与无法解释增长；保护性等待必须早于不能保存关键状态。录像关闭／开启分别计量，不以删证据凑指标。 |
| 持久化与控制 | 固定记录规模下的打开、查询、提交、恢复耗时上限，以及本地控制到禁止派发的延迟上限 | 记录样本数、分位数和最坏值；模型／业务等待与本地控制耗时分开，磁盘失败有明确反例。 |

这些工程预算限制工具资源失控，不构成用户任务的累计费用或时长额度。用户存储上限可不设置，但空间预警与保存能力保护必须配置并通过验证。预算超标应调整实现或清楚提出设备／承诺的变更，不能在验收后上调阈值包装通过。预算由实现负责人根据测量提出，独立验收者核对原始序列、负载及判据，主 agent 在后续正式运行前冻结。不能由实现者独自修改阈值再宣布自己通过。

**交付物与变更管理**

最终需有阶段证据、M0 探查结论、材料版本清单、ResourceBudgetRevision、DD02 浏览器能力矩阵实际结果、需求追踪和发行组合。能力矩阵只在[接口与执行 DD02](../architecture/2026-09-28-web-testing-design-execution.zh.md)维护，不能在本文件另写一份支持状态。

存储分段、检查点频率和内部抽象属于可调整实现候选；M0 可在保持领域权威、恢复语义、证据保留和 DSH 规则的前提下简化它们。变更先更新详细设计及受影响验收，不为维持旧图表而保留已证实多余的结构。沿用[基座与上游升级](2026-09-28-web-testing-upstream-baseline.zh.md)，不因探索阶段而降低适用工程检查。

恢复时先核对当前证据并记录 T08 的有限子项决定；修复 Electron 运行环境，再完成 P01 有限 broker／载体对照与 P03 生命周期。受影响 P02／P05／P07／P08 复验、P06 缺口及准入 M1 子项可独立推进；实际复现的 Loader／模型请求故障须修复，历史失败不能成为永久前置。必需证据齐备后再审 T08 完整准入。保留历史耗时，集成人在既有开发授权内登记追加或重分配的时间盒、待解问题和停止点；不把原 15–25 工程日估算当作实测成本或完成承诺。
