# Agent Note: 开发任务：M0 基线与验证

Status: proposed

[English](2026-09-28-web-testing-tasks-m0.md) | 中文

## 问题

必须先检查基座假设及独立材料，再让实现依赖这些假设。

## 提案

交付状态：M0 已有历史探针结果，但未通过；现已授权恢复本地浏览器接入开发，等待上游提供自动化实现不再是前置条件。按所选基座复验受影响证据，明确保留未执行与阻塞分项，当前状态由协作指南维护。任务接口、改动归属、独立复核、检查和交接格式以[agent（智能体）开发与协作指南](2026-09-28-web-testing-agent-guide.zh.md)为准。改动归属须经 RepositoryMap 解析为真实路径，并在派发时登记。前置完成指交付物已被消费方和独立复核者接收；提交代码或口头宣布完成不等于满足前置，明确标注的分项依赖除外。[有限开发准入](2026-09-28-web-testing-tasks-m1.zh.md#development-admission)统一维护整体验收前可实施的有限分项许可。

本阶段共 11 张卡，P01–P08 的时间盒以实施计划为准，初始合计 72 个有效工程工时，准备与总结另记。M0-T08 现在即可评审已有证据，最终收口仍须消费 M0-T09／T10／T11；编号不是执行顺序。时间盒不是交付或费用额度，到时形成继续／调整／暂缓结论，不重置计数。

**M0-T01：锁定实际底座、规则和工程地图**

**目标：** 给后续 AI（人工智能）一个可复现的实际工程入口，核对已选定基线与本地检出，区分版本决定和运行验证。

**前置：** 无任务前置；读取开发任务授权范围及固定基座记录。

**阅读：** 总控、基座与上游升级、TD01／TD11、DD01／DD12、G01／G02／G14。

**改动归属：** 现有 CODE_ROOT 及官方允许的研发记录位置；保留上游文档与本应用 proposed 提案。

**执行分工：** 由集成主 agent 负责固定版本、规则和 CheckPlan；可委派只读工程地图核对，仓库取得、基座补丁和共享清单由主 agent 执行。

**步骤：**

1. 保留全部已跟踪与未跟踪工作，复用 CODE_ROOT。将 dsh-v0.2.0-rc.2 解析为完整提交，核对检出、锁文件和全部保留差异，并更新 .artifacts/web-testing 下的 BaselineManifest；原基座证据单独保留。#4595 与 #5214 已包含于上游，撤去重复回移差异，不再次应用。按基座规则登记剩余应用改动及所有者，不擅自切换 master 或其他标签。
2. 读根与目标目录规则、引用 skill（技能）、README；检查 .harness/ 是否存在，不自行初始化。辨别官方要求、项目补充和社区参考；规则冲突先定位依据。
3. 核对原生 Windows、工具链、包管理器、依赖锁、官方安装及检查流程；按 [rc.2 影响审查](2026-09-28-web-testing-upstream-baseline.zh.md#rc2-incremental-upgrade)更新 CheckPlan，区分 Desktop 已安装插件管理 CLI、GUI 启动和配置检查。建立真实目录、服务入口、生成顺序和证据归属映射，不预造全部终态包。
4. 按基座文件的“文档语言与入口”检查实际双语规范和例外。在 RepositoryMap 登记各文档的用途、事实归属、仓库内位置及配对要求，区分维护规范与被忽略的本地证据。核对 docs/developer/web-testing 中的交接入口及详细 proposed 提案。英文、中文和一致性记录同步更新并执行官方检查。保留上游根 README 正文及其应用导航链接，不以交接入口替换。核验交付目录包含源码、全部规范及任务指令，不依赖被忽略的本地产物；迁移到新位置时同步携带并核验未提交文档。本地文件交接不以提交为前置；若仅通过 Git 分发，须另获提交授权后验证干净检出。任务验收仍须取得实际证据。

**交付：** BaselineManifest、RepositoryMap 初版、RulesMap、CheckPlan（实际命令、运行环境、触发条件、必需凭证、证据位置）。同时记录未提交改动和本次授权边界，供全部后续任务使用。增加 IntegrationSurfaceRegister 初版，逐项列公共扩展与内部修改、所有者、替代方案、生成／检查／升级负担。

**接续：** T02–T07 读取同一 BaselineManifest／RepositoryMap；核对人独立确认完整 SHA、规则作用域与命令可执行性后接收。

**正常验收：** 另一位 AI 能按记录找到真实源码、所属规则和启动／检查入口；官方标签与本地提交可核对。文档映射明确，根 README 保留上游正文并链接应用交接入口；维护文档满足适用配对和检查，读取规范不依赖仓库外目录或被忽略的本地产物。

**失败对照：** 目录含用户改动、候选标签不存在、工具链不匹配或缺规则时如实标注，不能覆盖、猜版本或宣布就绪；交接 README 覆盖上游入口、适用文档缺少配对或译文改变需求时不得验收通过。

**停止条件：** 取不到真实仓库、规则相互冲突且影响改动，或需要新增治理文件而无授权时，暂停受影响步骤并给出具体缺口。

**M0-T02：建立最小 fixture（测试前置数据）和独立判定依据**

**目标：** 准备 P01–P08 所需的 F1／F2／F5 最小材料，避免拿真实业务环境做破坏性探查。

**前置：** `M0-T01`。

**阅读：** 实施计划的材料表、验收 F1–F6、DD02／DD04／DD07。

**改动归属：** RepositoryMap 确定的官方测试及 fixture 目录。

**执行分工：** 材料 subagent 构建与复位 fixture；独立验收 subagent 保管 Oracle、缺陷答案和保留集，不把答案交给之后的产品执行 agent。

**步骤：**

1. 建立一个可复位的本地业务 fixture：角色 A 创建记录，角色 B 审批，A 看到同一记录结果；含点击、换行输入、文件框和两种页面状态。
2. 提供正确版与一个植入缺陷版，固定种子、初始化／复位入口、业务记录 ID 和独立事件日志；为中断注入留下明确边界。
3. 将验收标准答案与提供给产品分析的项目代码／规则分开保存；记录 fixture 版本和安全数据范围。允许研发 fixture 不代表产品可修改被测 fixture 源码。
4. 为 P06 登记陌生项目候选、有限业务子集、独立答案与人工参照获取方式；为 P07 增加 Session／fork 与报告共享附件材料，为 P08 增加旧逻辑卡住但记录可读的暂停／UNKNOWN 样本。没有材料时保留具体缺口，不能以原自建 fixture 替代陌生项目有效性证据。

**交付：** FixtureManifest 初版、启动与复位说明、独立 Oracle、预期事件及最小故障注入点；交给 M0-T03 至 T07 及 T09–T11，后续扩展而非重建六套应用。

**接续：** T03–T07、T09–T11 取得公开 FixtureManifest 和复位入口；标准答案仅给对应验收者。材料版本改变需通知正在消费的探查。

**正常验收：** 不用被测工具的成功声明，也能从外部状态判断一次创建／审批是否发生；复位后可重复得到相同初始状态。

**失败对照：** 错误版被独立判定拒绝，重复提交能被业务计数发现；产品分析输入不含隐藏缺陷答案。

**停止条件：** 无法可靠复位、fixture 连到真实第三方或预期仅来自工具自报时，先修材料，不开始探查。

**M0-T03：P01 桌面、Broker 与受控点击**

**目标：** 为已有官方内置浏览器接入受控自动化，经桌面入口展示最小动作并比较载体，同时保持页面和宿主能力分离。

**前置：** `M0-T01`、`M0-T02`。

**阅读：** P01、I01、DD01／DD02、V01、G01／G03／G06。

**改动归属：** 官方 profile／Loader、desktop Host 协议及 browser 候选归属的最小探查改动。此既有写入范围已允许开展受控 provider／Broker 工作，不以等待上游实现为前提。

**执行分工：** 桌面 subagent 负责载体和 Broker 比较；可委派隔离攻击对照设计。Host 协议和 profile 修改申请集成人锁，不与其他探查同时写。

**步骤：**

1. **R0——运行时身份与失败诊断。** rc.1 审计记录了缓存 Electron 44 运行时执行 `--version` 时以 `0x80000003` 退出；当前运行时仍待复核，不能凭该历史结果判定 webview、WebContentsView 或 debugger API 失败。登记可执行文件与包／lockfile 版本、下载／缓存来源、发行包和可执行文件哈希、架构、运行依赖、退出状态及可获得的崩溃／启动日志。对照所选发行元数据核验完整性并保留失败样本，将运行时启动与应用、renderer、guest 挂载及自动化层失败分别诊断。
2. **R0——受支持的桌面入口。** 使用官方准备和桌面启动流程，固定运行时、应用自有数据目录及 fixture。记录实际版本和启动日志，确认应用文档及其可见浏览器 guest 能加载。禁止使用 `--no-sandbox`、关闭 web security、替换为包／demo 启动器，或把特殊 headless `--version` 成功当成桌面验收。运行时失败阻塞依赖它的 GUI 证据；协议实现／测试等独立工作仍可按[有限开发准入](2026-09-28-web-testing-tasks-m1.zh.md#development-admission)继续。
3. **R1——已有载体与装配。** 盘点真实 Loader／profile，追踪现有 webview 租约、呈现和释放的所有者。桌面已有浏览载体，待补的是 Browser Use provider 和 Host 自动化通路。复用这些所有者，注册唯一的最小受控 provider，不重新搭建完整浏览器产品，也不因缺装配而否决载体。
4. **R1——最小控制通路。** 按 DD02 只实现 fixture 所需的有限 Host↔Main 消息和 provider 操作，同步更新协议两端、验证／版本处理、effect 及相关测试。在执行器中绑定已认证 Host 归属、目标身份、代次和操作白名单；页面内容不得取得控制凭证或任意 IPC／CDP／evaluate 权限。将实际源改动登记到 IntegrationSurfaceRegister。
5. **R2——同一可见页面与独立结果。** 在同一租约页面上取得新鲜观察，通过输入事件录入 fixture 的精确文本，点击业务控件，再读取独立 Oracle。关联目标／文档身份、观察、动作、可见状态和业务记录，一次预期提交只能产生一个事件。`Target.setAutoAttach` 不是这个已拥有主页面探针的先决条件；debugger／子目标失败先定位实际层次，再推断载体限制。
6. **R2——拒绝与生命周期对照。** 覆盖错误目标／所有者、陈旧观察／文档、已关闭目标、旧 Host 代次、断连撤权及取消，并尝试页面／iframe／popup 访问控制面及写入受保护 fixture 路径。实际执行层拒绝无效派发，迟到回调不能恢复权限。区分派发前取消与已经交付、仍待业务结果核验的动作。
7. **R3——有限载体比较。** 在独立拥有、无特权的 WebContentsView 上，以相同 provider／Broker 规则运行同组必要场景。比较角色隔离、导航／iframe／OOPIF 与 popup 归属、下载、焦点／输入、视口／截图、保留及释放／重建，禁止复用特权账户视图。按原因登记支持、失败与未验证项；auto-attach 或其他单项 API 失败，既不能保证换载体即可修复，也不允许删去必需矩阵项。依据证据和维护工作选择，不开发两套完整产品，也不在比较前预承诺固定的 15–25 个工程日工期。

**交付：** P01 ProbeResult 包含 R0 运行时身份／诊断、R1 实际装配及消息、R2 关联的观察／输入／Oracle 与拒绝证据、R3 对比结果。向 M1-T07 提供 TargetHandle 生命周期证据，并交 BrowserCarrierDecision 与两载体的 IntegrationSurfaceRegister 对照，说明能力、剩余缺口及维护成本的实测依据。分项结果不关闭完整能力矩阵。

**接续：** T05／T06／T09 消费选定最小接入；M1-T07 消费 BrowserCarrierDecision 与 TargetHandle 生命周期，不能只交截图或源码片段。

**正常验收：** 同一可见桌面页面能完成新鲜观察、真实文本输入和点击，并产生一个可独立核验的业务事件；关闭目标释放连接，两载体具有必要比较证据。明确发布路径与源码路径差异，以及完整矩阵的剩余检查。

**失败对照：** 页面、iframe、popup 不得取得宿主权限；旧目标和错误代次无动作，拒绝有实际执行层证据。

**停止条件：** 时间盒到期时登记剩余工作及继续／调整／暂缓决定，不重新计时或宣布通过。需要关闭 sandbox／安全配置、开放全局调试端口／任意 IPC、取消只读保护或未经验证 Loader 入口的路线不得放行。运行时失败阻塞依赖 GUI 的验收；[有限开发准入](2026-09-28-web-testing-tasks-m1.zh.md#development-admission)范围内独立工作可继续。

**M0-T04：P02 存储访问模式与恢复探查**

**目标：** 优先验证自研密度最高的领域提交方案，判断分段与检查点是否必要。

**前置：** `M0-T01`、`M0-T02`。

**阅读：** P02、I02、DD06／DD07／DD09、V04／V05、G07／G08／G12。

**改动归属：** 实际 storage domain 消费方和所属测试；不改写底层存储架构。

**执行分工：** 持久化 subagent 负责最小提交及故障点；独立核对者读取外部业务计数。可与 T03 分目录实施，公共 FixtureManifest 由材料 owner 更新。

**步骤：**

1. 经真实 storage domain 和 V4 Session 组合完成创建意图、子记录、入口发布、动作意图／事实、附件引用及通知投递；实测唯一句柄和提交边界，不假设跨记录事务。
2. 在创建中断、动作已发生而结果未写入、通知已送未确认处注入故障；重送命令和旧槽位，使用 F2 外部计数核验。
3. 比较 1 千／1 万／10 万条代表记录的加载、提交、读取与恢复时间和内存；比较合法的简单布局与候选 segment／检查点方案。

**交付：** P02 ProbeResult、访问模式测量、恢复边界表、简化或保留结构的证据；供 M1-T03 和 M3-T01 使用。另交 StorageDesignDecision；优先选择满足同等恢复语义的最小合格结构，未测得收益不预建 segment／检查点框架。

**接续：** T05／T09–T11 消费仓储与意图接口；M1-T03／M3-T01 消费 StorageDesignDecision、记录样本及测量脚本。

**正常验收：** 已提交事实可读、重送不多建资源、动作未知进入核实；规模测量可复现。

**失败对照：** 头提交失败、附件未完成、记录损坏及目标延迟入账不会产生伪完成；仅暂时查不到业务记录不能自动重发。

**停止条件：** 时间盒到期仍无法证明恢复语义或性能可用，标记暂缓；不得换直接 SQL／另建事务层掩盖上游不支持。

**M0-T05：P03 生命周期、并发和控制探查**

**目标：** 验证单 agent 资源队列与真实业务并发、即时停止派发之间能同时成立。

**前置：** 整卡验收要求 `M0-T03`、`M0-T04` 及 T07 主路线／上游恢复分项已接收；轻量子路线可仍待条件。队列所有权、派发门关闭、持久化与取消分项在各自 fixture 和接口具备时可独立执行；它们不能证明真实内嵌目标并发，也不能在 P01 前完成 P03。

**阅读：** P03、DD02／DD07／DD08、V03／V06、G04／G07。

**改动归属：** SessionResources 使用方、Runtime 提交与控制入口、目标生命周期测试。

**执行分工：** 运行时 subagent 负责独立队列／控制探针，再与 T07 已接收主路线／恢复实现及 T03 的 Broker 组合；桌面 owner 经此 Broker 支持实际目标。独立复核者核对并发时序和动作次数，不以 agent 日志自证；记录明确哪些分项仍等待真实目标。

**步骤：**

1. 在一次合法 SessionResources.run 回调中组织两个角色目标，完成有真实时间重叠的操作；不嵌套同一 agent 的 run。
2. 加入长业务等待、大附件保存、模型不返回和 Host 重建；请求暂停并测量本地派发门关闭和持久确认各自时间。
3. 释放长等待占用，撤销旧许可，验证迟到模型结果与旧 Host 回调不能继续操作；记录所有者和取消传播路径。
4. 制造同一步骤部分工具已完成、后续准备或调度失败的情况，核对 assistant 调用与结果配对；区分 TOOL_OUTCOME_UNKNOWN 与 TOOL_NOT_STARTED，已完成结果不丢失。此卡消费 T07 的真实请求和恢复证据，再验证调度、日志及业务次数；不得自行复制 agent loop 修补。

**交付：** P03 ProbeResult、工具结果配对与业务状态对照、执行组与释放协议、控制时序及资源测量；供 M1／M2 调度与 M3 控制扩展使用。

**接续：** T08 合并本卡与 T07 的消息配对证据；T09／T11 消费控制协议。交付明确已派发、未派发、未知的可判别样本。

**正常验收：** 两个角色状态隔离且确有并发，暂停不等待大附件完成才阻止新派发；重建后重新取得合法目标。

**失败对照：** 嵌套队列、旧代次回调、取消后回答和保存失败均不伪装正常继续；在途动作单独核实。工具结果缺失不得自动判失败重派；尚未调用的工具不能伪造成功。

**停止条件：** 时间盒到期、存在死锁或只能删除并发承诺才能继续时，暂缓依赖并提交具体调整方案。

**M0-T06：P04 原生控制及独立浏览器探查**

**目标：** 分别确认 Windows 受控原生路线和受管独立浏览器路线的可行边界。

**前置：** `M0-T02`、`M0-T03`。

**阅读：** P04、I03、DD02／DD03／DD12、V08／V09／V13。

**改动归属：** 受控 Computer Use 提供方、单一 Browser Use 提供方的外部路线及测试。

**执行分工：** 原生与外部浏览器可拆成两个限目录子任务，共用冻结观察协议；相同 Windows 桌面的原生输入串行，公共提供方注册由集成人合入。

**步骤：**

1. 在原生 Windows 读取实际 Cua SDK 工具描述，建立最小允许列表；操作归属明确的文件框／输入目标，记录焦点和租约。
2. 建立受管 Chrome／Edge 档案，完成一条独立浏览器观察与动作流程；明确完整启动与 CDP 附着能力差异。
3. 加入编辑器抢焦点、文件框危险动作、越界链接与关闭重建；分别报告两条路线的支持、限制、系统组合和剩余风险。

**交付：** P04 原生子结果、外部浏览器子结果及能力矩阵证据链接。两者独立放行，供 M4-T01／T02 使用。

**接续：** T08 分别记录两个子路线结果；M4-T01／T02 仅接收各自通过分项，任一暂缓不影响另一项的证据身份。

**正常验收：** 实际输入与页面状态匹配，档案隔离，关闭后资源可释放；不是仅 CDP 填值冒充原生测试。

**失败对照：** 错误目标、陈旧焦点和不明操作被阻止；拒绝不能仅由模型口头承诺。

**停止条件：** SDK 不支持必要保护、缺原生设备或时间盒到期则相应路线暂缓；不得宣称同账户控制等同操作系统隔离。

**M0-T07：P05 主模型与轻量决策模型辅助调用探查**

**目标：** 确认两类请求经 DSH 的真实链路、记录和恢复责任，尽早发现轻量决策模型能力不匹配。

**前置：** `M0-T01`、`M0-T02`。

**阅读：** P05、I04、DD10／DD11／DD08、V10／V11／V17、G05。

**改动归属：** 正式 LlmAdapter／ctx.llm 使用方、Session 事件及最小 typed-decision 适配探查。

**执行分工：** 模型 subagent 负责真实请求、能力及上游已包含的 #4595／#5214 回归；集成人单写所选基座装配与 PatchManifest。故障注入前先对照不加载／加载原型的普通请求，T05 消费已接收恢复证据；不能为复现已撤回移而修改 agent loop。

**步骤：**

1. 使用安全配置入口提供凭证，执行一次真实主模型调用和至少一种候选轻量模型的选择／分类；登记含适配器／依赖解析版本与配置路线的 ModelCapabilityDescriptor，按 rc.2 提供方／catalog 变化复验受影响能力，不能用 catalog 条目或 rc.1 结果冒充当前运行证据。优先复用既有适配器，专有协议才新建。Jev 仅为可选实例；不可用可改选合格路线，只验证实际提供方的候选选择／分类能力，不强迫实现其他提供方专有原语。
2. 核对 V4 Session 的实际消息构造、记录、请求 ID、结果、用量及结束原因；不假设直接 ctx.llm 调用已有主 agent 的自动日志／重试。
3. 用受控本地 HTTP 端点，经实际 Loader、LlmAdapter 和 Agent 重试路径返回有界的 429 响应，不主动耗尽付费提供方配额。注入超时、重试等待中取消、重开及迟到返回，记录请求次数、等待终止、Session 事件和恢复。已有本地两项适配器测试结果只覆盖 adapter，不能通过本集成步骤。分清适配器、Agent 插件和 Runtime 的唯一重试所有者；分别验证桌面公开的 [Remote cancel 方法](../../../../packages/api/session-controller/src/index.ts)与 [SDK 传输层缺少协议取消](../../../../packages/sdk/client/src/client.ts)，不能因 SDK 缺操作就声称桌面无法取消。fixture HTTP 证据、真实提供方证据与无 key 回放分开记录。
4. 独立生成部分结果已保存、后续派发失败场景，在所选基座已包含的 #4595 实现上实际续发模型请求，核对配对和已完成结果。登记当前构建／差异身份及相关检查，原基座对照保留为历史证据；复验已包含的 #5214 多图映射同时过期与恢复。重发仅限模型请求，不能用于未知业务动作，不另建修补循环。
5. 确认 P06 所需主路线输入／输出与确定性工具能贯通；轻量接入能力与默认启用收益分开。P05 只证明协议可用，不能宣称比确定性执行更快或默认给所有动作增加一次轻量调用。

**交付：** P05 主路线／轻量路线分项 ProbeResult、区分上游已含修复与保留本地改动的 PatchManifest、字段差异、Session 样本和重试所有权，供 M1-T04／M3-T02／M4-T07 使用；普通请求装配对照与真实提供方证据分开记录。

**接续：** T09 仅消费主路线通过分项；M1-T04／M3-T02／M4-T07 分别取得连接、重试和轻量约定证据。T08 核对本卡与 T05 的联合恢复门槛。

**正常验收：** 真实请求可追溯至提供方，失败步骤后的消息配对及真实续发有效；合法 decision 可解析，取消和等待能解释，没有凭证泄漏。主路线通过必须包含官方恢复修复的完整相关检查。

**失败对照：** 能力不支持、非法结果、错误凭证和缺 key 分别记录；不得静默改为通用聊天请求或让无效 decision 变动作。

**停止条件：** 候选无凭证可换另一合格候选；所有轻量候选均无真实证据或时间盒到期时标未验证。只放行已有证据的主路线，轻量能力保持对应交付阻塞。

**M0-T08：路线决策与工程约定收口**

**目标：** 把探查变成可约束下游的决策，防止带着未验证假设全面开发。

**前置：** 现在即可基于已有证据和明确缺项开始评审。M0 最终验收需要 `M0-T03`、`M0-T04`、`M0-T05`、`M0-T06`、`M0-T07`、`M0-T09`、`M0-T10`、`M0-T11` 的结果，不必为启动评审而把报告标成 ready。

**阅读：** 全部 ProbeResult、实施计划、DD01–DD13、基座与上游升级。

**改动归属：** RepositoryMap／CheckPlan／探查记录及受影响设计文档；必要探查代码归位。

**执行分工：** 集成主 agent 决策和锁定组合；独立审查 subagent 复核 ProbeResult 及失败证据，不改被审实现。缺资料时退回 owner 补证，不能由汇总者代填通过。

**步骤：**

1. 现在即可根据已有证据形成 GateDecision，条件不足时明确给出未通过结果。逐项判定继续、调整、暂缓，并引用[有限开发准入](2026-09-28-web-testing-tasks-m1.zh.md#development-admission)中的已授权实施分项，不在此复制许可表。核心桌面、领域恢复／控制、主模型及 P06／P07／P08 要求仍是完整 M0 验收条件；允许开发不等于依赖已接收，也不免除剩余证据。
2. 联合核对 T05／T07 的会话续跑与未知业务不盲重放证据，在所选基座检查上游已包含的 #4595／#5214、保留本地改动及相关检查。旧基座结果或普通模型请求成功不能代替失败步骤复验；有限子项开发许可与完整准入分开记录。
3. 将实际包、服务签名、生成与生命周期责任写入 RepositoryMap；记录哪些上游改动确实必要、如何随升级审查。
4. 根据 P02 简化或确认存储结构；清理探查临时绕过，保留代码则补齐所属测试和文档。链接 M1 当前开发准入决定，记录 M4 暂缓分支，不另建竞争的启动许可清单。
5. 核对 ProductEffectivenessResult、AssetLifecycleDecision、RecoveryUpdateDecision 和集成成本登记；对每个公共约定或内部修改作保留／简化／暂缓决定，记录工时与验证负担估算及未知。不以规范检查通过替代产品检出能力或升级兼容性。

**交付：** M0 GateDecision、实际基线、RepositoryMap／CheckPlan 修订、设计差异、探查代码处置及资源测量初值；作为全部实现任务的输入。

**接续：** 发布已接收输入、缺失证据和重入条件，启动许可链接到唯一 M1 开发准入所有者。M1 可实施已授权有限分项，同时明确未满足依赖；正式验收只消费已接收输入。变更产品承诺才提出用户决策，不逐卡请求批准。

**正常验收：** 每个验收决定都有真实正常／失败证据；有限实施许可的范围及未解决依赖保留在准入所有者中，阶段性未通过 GateDecision 也是有效评审结果。未验证的轻量决策模型／原生分支不会被主路线通过掩盖。

**失败对照：** 模拟只有文字结论、探查超时和互相矛盾的报告，必须保持限制；不能把未支持功能移出矩阵以宣布通过。

**停止条件：** 调整会改变产品范围、保护程度或绕过官方要求时，提出具体取舍等待用户决定；工程细节可在原约束内修订。

**M0-T09：P06 陌生项目上的产品有效性**

**目标：** 尽早证明有限范围内能识别功能、区分错误与正确行为，并减少回归的人工作业。

**前置：** `M0-T02`、`M0-T03`、`M0-T04`、`M0-T05`、`M0-T07`；只消费 P05 已通过的主路线，不要求轻量子路线通过。

**阅读：** 实施计划 P06、报告的预期依据、TD02／TD08、AC07／AC09／AC29／AC41。

**改动归属：** 已验证 DSH 探查 profile、最小分析／受控执行消费方及独立验收材料；不提前建设全部 M2 包。

**执行分工：** 产品执行 subagent 只读公开项目和用户规则；独立验收 subagent 持有隐藏答案并计算指标。主 agent 预登记协议及人工参照，避免同一上下文既看答案又执行。

**步骤：**

1. 按实施计划冻结 ProductEffectivenessProtocol，登记陌生项目来源、有限范围、正确／缺陷对照、隐藏答案、人工参照、运行顺序及实际用户问题模式；验收日志不向 agent 暴露。
2. 经真实模型和受控动作完成生成用例、关键规则确认、执行、逐项判断及最小报告；timed 问题的超时或 pending 仍属意图未确认，选用 timed 时按 M1-T05／T06 有效性规则覆盖迟到答案，有效确认后才实际补测。UNKNOWN、只读边界、持久意图和模型记录仍生效。
3. 运行同范围回归并测量用户活动时间；按预登记分母核对识别、缺陷、误报、错误业务通过、未验证和人工负担，首轮与回归分别报告。

**交付：** ProductEffectivenessProtocol／Result、独立 Oracle 对照、最小链路代码与证据、适用范围和失败归因，交 M0-T08 及 M2／M5。

**接续：** T08 读取 Result；M2-T02／T09 与 M4-T09 继承有效样本、保留集边界及人工时间定义，不能将已泄漏答案的材料继续当陌生验证。

**正常验收：** 实施计划规定的有限样本未延期条件满足，延期人工对比仍显式保留；错误实现不会因与生成预期一致而业务通过，用户确认后有真实补测。

**失败对照：** 未给业务意图、实现明确但错误、正常页面、遗漏入口及隐藏答案泄漏均有可区分结果；泄漏的样本作废并换保留样本。

**停止条件：** 达到 16 工时时间盒、缺独立答案或未满足未延期效果条件时，调整／暂缓；人工对比按用户决定延期至 M5，不能报为通过，不能放行依赖性全面开发或伪称零漏报。

**M0-T10：P07 附件引用与删除能力扩展**

**目标：** 将所选底座没有现成引用感知清理能力的事实，落实为可验证、归属明确的扩展路线。

**前置：** `M0-T01`、`M0-T02`、`M0-T04`。

**阅读：** DD09 附件生命周期、P07、AC55／G08／V16、实际 AttachmentStore／提供方与 Session／fork 引用路径。

**改动归属：** 官方附件抽象、实际提供方、必要引用消费方及所属测试；由 RepositoryMap 标明扩展，不在业务包直接删对象文件。

**执行分工：** 附件 subagent 负责官方抽象与提供方扩展，Session／fork 消费方修改由对应 owner 或集成人串行接入；独立者验证删除前后可读性和字节释放。

**步骤：**

1. 盘点保存、发布、Session／fork、报告、快照、基线、导出与在途票据的全部引用所有者；未知历史保持保留，记录不可盘点的边界。
2. 验证最小保留票据、引用提交、删除准入互斥及提供方删除协议；持久化失败或中断不得失去仍需要的对象，接口新增遵守官方约定和生成要求。
3. 以普通会话及两个报告共享对象验证删一份不破坏其他使用者；施加新引用／导出／删除竞态与崩溃，独立测量物理空间回收；deleteFileVerbatim 返回的逻辑字节不能代替引用协调、删除串行化或已打开读者对照。

**交付：** AssetLifecycleDecision、实际接口与引用所有者表、失败对照、IntegrationSurfaceRegister 成本及分阶段交接；供 T08、M1-T03、M2-T05、M3-T05。

**接续：** T08 接收扩展归属；M1-T03 建立票据，M2-T05 发布证据，M3-T05 实现清理。交接须列全体引用 owner 与未知历史保留策略。

**正常验收：** 至少一个不再被保留的对象经提供方实际删除，共享／活动对象受保护；原保存／读取约定仍有效。

**失败对照：** 不能只查测试报告引用；普通聊天／fork、新引用、未提交保存、未知历史和导出读者存在时，不误删、不伪报释放。

**停止条件：** 达到 8 工时、无法盘点所需所有者或只能拼底层路径删除时暂缓；没有合法扩展路线不得放行依赖资产架构。

**M0-T11：P08 故障恢复更新与未知动作保留**

**目标：** 证明旧任务无法推进时仍可安全进入修复版，而不把更新变成重复业务操作的入口。

**前置：** `M0-T01`、`M0-T02`、`M0-T04`、`M0-T05`。

**阅读：** DD07／DD09／DD12、P08、AC03／G12／G16／V14、实际安装与迁移入口。

**改动归属：** 独立恢复协调入口、领域封存／迁移消费方及所属测试；保持控制根唯一写入和官方安装机制。

**执行分工：** 恢复 subagent 负责独立协调和旧格式检查，集成人拥有安装接口及锁身份；独立验收者施加中断，不与 Runtime owner 同时修改锁协议。

**步骤：**

1. 制造旧调度器不能继续但持久记录可读的批次，包含用户暂停及 UNKNOWN；确认独立协调器可撤权、停止旧执行器、取锁并备份，不等待业务任务结束。通过 DD12 的只读 PersistentActivitySnapshot 读取控制根、采样时刻、RunHeads、未结算动作及完整性错误，先证明冷会话批次不漏计。
2. 保存 FrozenRunManifest／RecoveryUpdateIntent，经旧格式只读检查和候选迁移进入 recovery-only；检查器失效／备份不一致时不覆盖原组合。
3. 验证原状态和未知动作在新版本仍可查询，新 runId 不绕过核实；记录真实安装流程接入位置、兼容范围及尚未运行的安装验收。

**交付：** RecoveryUpdateDecision、PersistentActivitySnapshot 探查证据、冻结／恢复时序、兼容判定与失败对照、集成成本；供 M0-T08、M3-T01、M5-T02。

**接续：** T08 接收可行性；M3-T01 实现封存／关联，M5-T02 用真实旧新安装包复验。交付备份一致性和原暂停／UNKNOWN 的核对方法。

**正常验收：** 旧任务未完成也能取得有条件的恢复资格；新版首先只读核实，旧报告不变，暂停和 UNKNOWN 不被清零。

**失败对照：** 旧执行器未撤权、无备份、不识别格式、更新中断及以新批次重发未知动作均不能正常放行。
