# Agent Note: 开发任务：M3 持久任务

Status: proposed

[English](2026-09-28-web-testing-tasks-m3.md) | 中文

## 问题

长程任务需要持久恢复、受控重试、接管、进展检测和存储限制。

## 提案

阶段准入与当前任务状态以协作指南及其 TaskRegister 为准；历史探针结果不代表这些实施卡已完成。任务接口、改动归属、独立复核、检查和交接格式以[agent（智能体）开发与协作指南](2026-09-28-web-testing-agent-guide.zh.md)为准。改动归属须经 RepositoryMap 解析为真实路径，并在派发时登记。前置完成指交付物已被消费方和独立复核者接收；提交代码或口头宣布完成不等于满足前置，明确标注的分项依赖除外。

本阶段 7 张卡，在 M2 已有的基本恢复上扩展完整矩阵。持久状态、模型重试和业务重发是不同问题：模型可持续等待恢复，结果未知的业务操作不能盲目重复。所有等待均需可解释、可恢复、可查询。

**M3-T01：完整崩溃恢复与写入所有权**

**目标：** 把最小恢复扩展到全部关键提交边界，保证重开不丢事实、不重复业务。

**前置：** `M2-T09`。

**阅读：** DD06–DD09、AC15／AC37、V04／V05、G07／G12。

**改动归属：** Runtime 锁、恢复协调及 StorageDesignDecision 已选结构与 outbox；只有 M0 已证明必要时才实现 segment／检查点。

**执行分工：** 恢复 subagent 独占锁、恢复和事实提交实现，所选装配与上游已包含的 Session 恢复由集成人统一核对；独立验收者注入崩溃并从外部核对业务。

**步骤：**

1. 依 M0 已验证结构补齐创建、动作、事实、Head、通知各中断点的恢复；读取严格 schema，明确兼容、损坏和未发布孤儿的处理。
2. 跨路径别名、Windows 登录会话、安装标识及数据代际验证同一控制锁；原 owner 真正退出并取得锁后才能接管，Host epoch／目标许可同步更新。
3. 对未知业务结果用独立观察对账，保留迟延入账场景；稳定通知 ID 去重至 UI 和模型消费，Session 重放不代表浏览器资源已恢复。
4. 复验 M0 放行组合的失败步骤恢复：已保存工具结果不改写，未开始／未知结果保持区分；已关闭的不一致旧轮次和日志写入失败分别列恢复边界，不能宣称基座已包含的修复自动修复全部历史。Session 修复与 Runtime 动作核实分别取证。
5. 按 P08 接入 frozen-recovery／RecoveryLink 和跨批次 UNKNOWN 核实；独立恢复协调器与 Runtime 争用同一锁，普通重开不自动激活封存批次。

**交付：** RecoveryMatrix 实施版、各中断点证据、锁与通知去重结果；所有后续控制／重试消费同一恢复服务。

**接续：** T02／T03／T05 获得同一恢复入口、UNKNOWN 与封存状态；M5-T02 消费兼容检查和原组合恢复证据。

**正常验收：** 不同位置中断重开均回到可解释状态，原已提交事实和报告不丢失；重送旧命令不新增资源。

**失败对照：** 暂时无记录、损坏头、双 Host、旧模型回调和通知重复不能引出再次业务派发或伪完成。

**停止条件：** 存在可重现重复业务／双写时阻塞下游稳定性结论，先修协议；不得靠人工删数据库后重跑通过。

**M3-T02：持久模型重试、备用路线和辅助请求**

**目标：** 让模型临时故障跨进程重开继续恢复，同时保持唯一重试责任和准确用量。

**前置：** `M3-T01`、`M1-T04`。

**阅读：** DD08／DD10／DD11、AC16／AC17／AC18、V10、G05。

**改动归属：** agent 重试插件使用方、Runtime 辅助请求调度、路由和 Session 事件。

**执行分工：** 模型 subagent 负责 RetryState 和唯一重试归属，可与 T03 在冻结 Runtime 接口后分文件并行；改主调度文件须排他预约。

**步骤：**

1. 区分主 agent 请求与直接 ctx.llm 辅助请求，后者明确记录 request／attempt 身份和 Session 事件；两条链各只保留一个重试 owner，不叠加 SDK 无限循环。
2. 分类认证／配置、限流／临时服务、超时／流中断和能力错误；持久记录退避、Retry-After、下一尝试和路线，临时故障无累计费用或短次数终止。
3. 不以官方 Jobs／Schedule 作为 RetryState 权威；持久 retryAt 和启动扫描由 Runtime 负责。需要定时唤醒时先显式选择可选 schedule 组合包再配置其行；投递只作为可能重复或缺失的信号，进入同一状态与去重检查。
4. 跨重开恢复等待，取消代次压住迟到结果；备用路线须能力相容并记录实际选择。轻量决策模型全量协议在 M4-T07 补齐，本卡先验证真实主链及已可用辅助链。
5. 在同轮工具调度失败之后实际发出下一次主模型请求，核对基座已包含的结果补齐与业务 UNKNOWN 对账；所选适配器的多图失效恢复只重试模型输入，不回放已经执行的页面操作。

**交付：** RetryState／AttemptRecord、错误分类及备用路线协议、实际提供方与受控故障证据，供 M4 适配器和状态投影复用。

**接续：** T04／T06 读取持久尝试和等待原因；M4-T07 使用同一辅助调用链，不能在适配器再套无限重试。

**正常验收：** 连续临时失败超过短重试次数后恢复可继续原任务，等待重开不丢计数或提前违反 Retry-After。

**失败对照：** 401／能力不符不会无限忙重试；取消后迟到成功不复活，重复回调不重复计用量，辅助链无日志时不得算验收通过。

**停止条件：** 缺真实提供方证据只标未执行；任何业务副作用未知不能因“模型重试”而重新发送业务动作。

**M3-T03：暂停、退出、接管与资源调度**

**目标：** 区分用户操作和进程生命周期，并确保控制请求及时阻止新动作。

**前置：** `M3-T01`、`M1-T07`。

**阅读：** DD02／DD03／DD07／DD08、AC36／AC48、V06、G04。

**改动归属：** Runtime 控制门、agent／SessionResources 调度、desktop 生命周期和 Client 控制呈现。

**执行分工：** 生命周期 subagent 负责控制门和官方桌面活动适配，集成人拥有 Main／Host 协议；原生输入的撤权约定先冻结再交 M4。

**步骤：**

1. 实现业务暂停／恢复／取消，并接入官方隐藏窗口、托盘及标准退出确认；不重建桌面生命周期。用 DD12 的只读 PersistentActivitySnapshot 将全部未结束持久批次（含未加载会话、暂停、退避、环境等待、封存与待恢复）接入退出／更新及会话活动判断，不另建统计 API，首版阻止归档这些会话，不让归档取消轮次等同于取消批次；用户暂停重开仍暂停，批次完成不能从 agent 空闲推断。
2. 控制请求先关闭本地派发门和撤销许可，再保存小控制记录；UI 分开显示已禁止派发、已持久确认和保存失败，在途操作独立核实。
3. 官方 agent／Inbox／Jobs 空闲不等于业务完成；退出检查超时或读取失败保持未知并走明确提示，不能静默作无任务处理。明确退出完成停派与状态保存，关闭普通窗口保持后台工作；需要可见桌面的输入仍遵守环境要求。
4. 建立用户接管、可见桌面需求、锁屏／焦点变化及资源释放协议；长等待释放执行队列，原生租约接口给 M4-T01 接入，不提前声称已验证原生控制。

**交付：** ControlState 转移表、PersistentActivitySnapshot 消费与完整性错误证据、调用取消链和生命周期证据；M4 native／外部浏览器必须接同一门。

**接续：** T04／T05／T06 接收可解释控制状态；M4-T01／T02 接相同门，M5-T02 复用全部批次判断而非另写安装筛选。

**正常验收：** 长 I/O／模型挂起时也可阻止新派发；明确退出保留可恢复任务，重开不会越过用户暂停；关闭或不加载会话仍能从同一快照发现批次，快照不完整不会显示无任务。

**失败对照：** 晚到结果、重复暂停、保存失败、卸载旧句柄和人工操作抢占均不能自动重新派发；对有未结束批次的会话请求归档被拒绝，持久任务和通知不丢失；取消不声称已撤销已发生业务。

**停止条件：** 需等待大附件才能停派、队列死锁或隐藏窗口继续危险原生输入时，暂停依赖路线并修调度。

**M3-T04：任务级无进展检测与有限恢复**

**目标：** 识别持续观察／重规划造成的空转，同时保留长任务和合法等待。

**前置：** `M3-T01`、`M3-T02`、`M3-T03`。

**阅读：** DD08、AC57、V18、实施计划资源预算。

**改动归属：** Runtime 进度事件、watchdog 和会话通知投影。

**执行分工：** 调度 subagent 负责进展判据和有限恢复，独立验收者提供合法长等待／真实空转对照；策略阈值执行前冻结，不由被验代码自动改。

**步骤：**

1. 按分析／规划／执行等阶段定义可验证进展和窗口，区分新增有效事实、完成实例与仅重写文本；策略修订在运行前固定。
2. 排除业务定时、模型退避、用户暂停和待授权；对重复观察／改写计划／恢复无效进行有限升级或重新观察。
3. 持久记录恢复次数和依据，耗尽后阻塞受影响分支并去重提醒，独立项继续；重启不能重置次数，用户解决条件后可明确恢复。

**交付：** ProgressPolicyRevision、StallRecord／RecoveryAttempt、正常与停滞成对材料；M3-T06 查询，M4 时间流程扩展。

**接续：** T06 展示 StallRecord 与人工再入条件；T07 验证跨重开计数，M4-T04 扩展时间业务时必须保留合法等待排除。

**正常验收：** 真实无效循环在固定策略下被发现并停止空转；正常长等待不误判，其他独立用例仍可前进。

**失败对照：** 仅增加 token／反复生成新计划版本不能当有效进展，重开不清零；不得用费用上限或总尝试次数终结整个长任务。

**停止条件：** 不能区分进展和合法等待时保持未验证并修判据，不只增加阈值掩盖误报。

**M3-T05：存储预警、保护性等待与资产清理**

**目标：** 在不能保存证据前保护任务，并让用户安全管理已占磁盘空间。

**前置：** `M3-T01`、`M3-T03`、`M2-T08`。另需 M0-T10 已通过的 AssetLifecycleDecision 及 M1-T03／M2-T05 引用保护交付。

**阅读：** DD07／DD09、AC38／AC55、V12／V16、G08。

**改动归属：** Runtime 存储健康、资产引用与处置服务、Client 清理预览。

**执行分工：** 附件 subagent 负责引用准入和提供方删除，Client owner 接清理预览；普通 Session／fork 消费方和共享 schema 由集成人统一变更。

**步骤：**

1. 监测实际证据卷与控制记录卷，测量材料增长；设置可配置预警、控制预留空间和可选配额，默认不设累计配额，空间不足不等于费用用尽。
2. 不能保存必要材料时停派并持久进入等待，恢复空间后重新核验；故障测试用隔离卷／受控注入，不能故意写满用户系统盘。
3. 按批次预览清理、记录明确确认和版本，再重验活动／基线／其他历史共享引用；使用官方资产生命周期接口，保留最小处置记录，报告内容不被改写。
4. 在 P07 确定的官方附件抽象／提供方归属完成删除与引用生命周期，覆盖普通聊天／fork、快照、导出、活动保存及未提交票据；无法证明引用完整性就保留，不能临到此阶段才假定上游已有清理接口。

**交付：** StorageHealthPolicy、清理预览／确认协议、AssetDisposition 和实际释放证据；与报告缺失引用可互相追溯。

**接续：** T06 展示真实空间与处置；T07 使用隔离故障卷验证；报告、基线、导出消费方接收缺失原因而非被动坏链接。

**正常验收：** 提前预警、保护性等待、空间恢复可继续；只删除确认且无保留引用的资产，实际释放量可核对。

**失败对照：** 预览后新增引用、清理中断、写入失败、共享证据和误算跨卷空闲量均不误删／伪报成功；删证据不得用于凑资源预算。

**停止条件：** 无法证明归属或引用已重新检查时停止清理并保留材料；不以后台自动删历史绕过用户确认。

**M3-T06：实时进度、用量与所属会话提醒**

**目标：** 让用户随时看到可信运行状态，查询本身不增加模型调用。

**前置：** `M3-T02`、`M3-T03`、`M3-T04`、`M3-T05`。

**阅读：** DD05／DD08、AC34／AC58、V18、G15。

**改动归属：** 已提交事实投影、Session 计量消费、Client 状态卡与通知展示转换器。

**执行分工：** Client subagent 负责投影展示，Runtime／计量 owner 提供只读事实；通知展示转换器文件由一个 owner 修改，验收者核对查询前后的请求计数。

**步骤：**

1. 从持久事实展示阶段、当前实例、动态分母、有效进展及活动／等待耗时，给出采样时刻和统计范围。
2. 按 request／attempt 身份对账主模型、辅助、重试、备用路线和缺失 token；缺用量显示未知，不当零、不重复计费，也不强求费用精算。
3. 提醒只投递到所属桌面会话，去重可重连；状态查询走只读 Remote，不为解释状态额外调用模型。

**交付：** LiveRunProjection、UsageSummary、通知去重和重连证据；M5 实际运行直接使用。

**接续：** T07／M5 获得真实进度与计量观察入口；按同一通知 ID 对账持久 outbox、会话和界面，不能三处各自计数。

**正常验收：** 查询与源请求账相符，重开继续相同计数；不同会话不会接收错误批次提醒。

**失败对照：** 重复通知、缺用量、进程重建、迟到失败结果和范围变更仍可对账；查询前后模型调用数不增加。

**停止条件：** 投影依赖模型生成数字、无法说明动态分母或未知被当零时，保持未验收并修数据来源。

**M3-T07：故障矩阵、长历史与阶段预算**

**目标：** 验证恢复系统整体行为，并冻结当前已实现组合的资源数值。

**前置：** `M3-T01`、`M3-T02`、`M3-T03`、`M3-T04`、`M3-T05`、`M3-T06`。

**阅读：** F5、DD13、V04–V07／V16／V18、实施计划预算字段。

**改动归属：** 官方集成／故障测试、测量脚本和证据记录；不建平行测试框架。

**执行分工：** 独立稳定性 subagent 执行故障矩阵和测量，功能 owner 修缺陷，主 agent 冻结预算；采样进程与受管进程清单由验收者复核。

**步骤：**

1. 完善 F5：模型、持久化、附件、通知、双 Host、暂停、停滞及延迟入账，在关键交界逐个注入并保存故障确已发生的证据。
2. 使用不同历史规模与固定重复生命周期，采集全部受管进程内存、句柄／线程、磁盘增长和本地控制延迟；合法等待与活跃负载分别计量。
3. 根据测量提出数值、负载和采样规则，复核并冻结当前 ResourceBudgetRevision；全量 24 小时和新增路线在后续独立验收。

**交付：** F5 故障矩阵、独立业务核对、测量原始序列、已实现组合预算及 M3 GateEvidence。

**接续：** M4 所有路线取得当前预算、失败语义和历史负载；新增进程组合必须追加测量，不能直接继承旧上限。

**正常验收：** 故障后任务状态、业务次数、材料和通知均能对账，正常等待不被误伤；预算包含峰值、斜率和释放残留等可判定值。

**失败对照：** 只检查工具自报、不验证故障施加、缺采样或执行后提高阈值均不通过；加速模拟不得写成实际 24 小时。

**停止条件：** 存在重复业务、丢事实、无进展误判或预算仍无数值时，不放行稳定性依赖；明确失败项与负责卡。

**阶段交接门槛**

RecoveryMatrix、停滞、空间与用量对照通过；真实业务无重复，保存能力不足时不新增派发；冻结当前组合的资源数值。阶段检查保留尚未完成的原生／外部路线，M4 新增后重新测量，不能拿本阶段预算覆盖未经测量的新组合。

## 考虑过的替代方案

**已记录的取舍。** 将 Jobs 作为业务权威，或在固定总重试次数后停止，不满足持久任务要求。

## 验收标准

执行本提案中的正常和失败对照，并满足[统一验收标准](../testing/2026-09-28-web-testing-acceptance.zh.md)及相应任务的证据要求。文档迁移不代表这些条件已通过。

## 风险

未知动作结果、存储故障和所有者竞争可能造成重复副作用，必须通过故障验证恢复。
