## 问题

增加测试执行前，需要在官方桌面上建立最小共享应用基础。

## 提案

交付状态：packages/web-test/web-test 已有身份／入口原型；M0 与完整 M1 准入仍未通过。用户已撤销等待上游内嵌载体的指令。下方开发准入表允许在各子项前置满足后开展基础实现，不再限于原型诊断。任务接口、改动归属、独立复核、检查和交接格式以[agent（智能体）开发与协作指南](2026-09-28-web-testing-agent-guide.zh.md)为准。改动归属须经 RepositoryMap 解析为真实路径，并在派发时登记。前置完成指交付物已被消费方和独立复核者接收；提交代码或口头宣布完成不等于满足前置，下方明确的分项依赖除外。

本阶段 7 张卡。基础子项按 T01-A → T02-A → T03-A 推进，随后分目录完成 T04-A／T05-A，再完成 T06-A。整卡依赖和 T07 的浏览器前置仍适用于完整验收。所有业务只通过官方服务和唯一 Runtime，工程检查随各实现子项执行。

**M1-T01：官方桌面复用与测试插件装配**

**目标：** 用真实 DSH 入口形成本应用可启动、可卸载的最小结构。

**前置：** 整卡验收须取得完整 `M0-T08` 准入；此前 T01-A 可按开发准入表开工。

**阅读：** DD01／DD05、TD01／TD10、G01／G02／G04／G13。另读 M0-T08 当前的有效性、集成成本及有限准入决定。整卡验收前确认 P06–P08 相关门槛，不能由 T01-A 完成推定通过。

**改动归属：** 自有 profile／bundle、Client 插件及必要包清单；沿用 M0 RepositoryMap。

**执行分工：** 集成主 agent 拥有 profile、包清单和构建入口；Client subagent 仅改指定测试插件与 typed locale，不创建第二套窗口／聊天框架。

**步骤：**

1. 按官方新增包流程建立当前需要的装配，不提前创建全部终态包；核对 workspace 依赖范围并禁止新增 as unknown 断言；已有身份原型的 dataRootName／profileName 字段不改变 DSH_HOME 或桌面 profile；须实现并验证实际独立身份、数据根与配置选择后才能宣称隔离，同时保留官方默认产品。
2. 复用官方窗口、聊天、布局、快捷键、托盘及标准退出界面，只增加测试入口、业务卡片和浏览器必要接入；不复制桌面基础框架。产品文字进入 typed locale；无后端能力时明确不可执行；不装配上游无限制侧栏终端及服务，普通对话仍可用。
3. 本应用首次启动前，在自身装配中显式禁用 desktop-product-telemetry 与 product-analytics 的采集／导出。按 DD12 验证生效 profile、目的地址、队列和导出状态；所选 desktop 基座默认启用二者。普通反馈、模型请求、被测网络、更新与引导分别检查，不继承官方生产收集或发行地址。
4. 注册／释放由唯一所有者负责；验证真实 Loader 解析、活动包 manifest 及源码／产物导出，单独 ctx.plugin 装配不足。以同一 profile／构建对照不加载／加载 web-test 的真实普通模型请求，按 DD11 诊断 REQUEST_EXTENSION。最终会话集成仍归 T04／T06，装配本身不代表聊天交付。

**交付：** 可启动的本应用 profile、包依赖和归属图、装配／卸载证据；T02 至 T07 在此结构中实现。

**接续：** T02 获得可加载的定义与服务落点；T04／T06 复用官方 UI 入口，T07 复用已选浏览器承载位置。

**正常验收：** 真实桌面载入自有插件，官方默认产品和配置不被覆盖；卸载不残留注册项。

**失败对照：** 缺依赖、错误配置和重复装配有确定失败；不靠源码 fallback 或旧构建产物“通过”。

**停止条件：** 对应 M0 路线未通过时扣留整卡验收和依赖浏览器的集成；继续开发准入表允许的基础子项。拒绝需要复制 agent loop 或绕开 Loader 的路线。

**M1-T02：共享标识、领域 schema 与 Remote 约定**

**目标：** 给 Runtime、Client、策略和执行器建立唯一类型边界。

**前置：** 整卡验收依赖 `M1-T01`；T02-A 按开发准入表消费已接收的 T01-A。

**阅读：** DD01／DD05／DD06、G02／G03／G11／G15。

**改动归属：** web-test 定义包、服务声明、必要生成源及所属测试。

**执行分工：** 约定 subagent 提出实际消费方需要的类型；集成人冻结 ContractRevision 并单独生成。Runtime 和 Client owner 分别核对消费示例，不并行编辑公共 schema。

**步骤：**

1. 定义当前消费的 branded ID、修订号、schema、命令身份、状态和错误判别；规划／执行／断言／报告身份分开，不一次预造所有未来 API。
2. 按 Typert Remote／RemoteScope 暴露业务操作和查询，由官方流程生成 Client 类型及运行描述；不新建业务 Electron IPC 或手写镜像 DTO。
3. 明确调用方拥有取消、事件订阅和释放；工具给模型的参数只暴露任务需要的信息，结果含包装／多字节文本也服从输出边界。
4. 依据实际消费方声明预期依据／诊断字段及恢复封存关联；附件生命周期消费 P07 已验证约定，不假设现成删除方法。

**交付：** ContractRevision、Remote 接口与生成物、错误表、请求去重及事件约定；T03／T05 与 Client 直接消费。

**接续：** T03／T05 接收已生成且可运行的接口；任何下游新增字段先走同一约定 owner，禁止临时 any／镜像 DTO 解阻。

**正常验收：** Host 生成后 Client 干净编译并完成真实调用；边界值按 schema 解析，错误可区分。

**失败对照：** 非法 ID／多余分支、超界结果、卸载后的句柄和旧接口调用被拒绝；纯类型文件不得引入运行副作用。

**停止条件：** 需要手改生成物、复制公共类型或未明确取消所有者时先修约定；产品语义冲突回到对应设计。

**M1-T03：唯一领域写入者与最小持久状态**

**目标：** 建立以后每次测试动作必须经过的持久化权威。

**前置：** 整卡验收依赖 `M1-T02`；T03-A 按开发准入表消费已接收的 T02-A 与 P02 证据。

**阅读：** DD06／DD07／DD09、P02 结论、G07／G08／G12、V04／V05。

**改动归属：** web-test-runtime 的领域服务、实际 storage domain 声明和兼容记录。

**执行分工：** 持久化 subagent 独占 Runtime 仓储、控制根与提交代码；附件 owner 提交票据适配，由集成人按约定合入。锁／恢复由独立审查者核对反例。

**步骤：**

1. 取得控制根稳定身份和 Windows 独占锁；锁身份不随应用标识或数据代际更换，覆盖别名和不同登录会话，不凭超时接管。
2. 按 M0 决策实现创建预留／子记录／入口发布及必要 Head；Runtime 唯一提交业务状态，Session 保留原有会话权威。命令重送可得到同一结果。
3. 附件等长 I/O 在小控制提交外准备，提交前重验期望版本；建立最低限度事实、outbox 和严格读取，不预建无依据的大型事件框架。
4. 消费 StorageDesignDecision 实现最小合格结构，并按 P07 建立持久保留票据与引用发布基础；普通 Session／fork 的接入归官方消费方，不以 Runtime 单写假设替代全体引用协调。

**交付：** 领域仓储 API、提交／创建协议、初始恢复证据及真实持久历史样本，供模型配置、项目和执行器调用；历史样本作为 F4 起点保留。

**接续：** T04–T07 取得真实持久 API 和失败语义；M2-T04 使用相同动作意图接口，F4 保存本阶段真实数据。

**正常验收：** 创建、关闭、重开读到同一实体；两个 Host 同根只有一个写入者，成功提交才发布结果。

**失败对照：** 入口发布中断、重复命令、损坏 schema 和附件未落盘不多建或伪完成；独占失败不打开第二写入通道。

**停止条件：** 依赖不存在的事务、直接 SQL 或无法防双写时停止依赖实现并复核 P02。

**M1-T04：首启模型配置与通用路由**

**目标：** 让用户在会话内安全完成首次配置，并给分析、视觉和辅助请求提供能力匹配路线。

**前置：** 整卡验收依赖 `M1-T02`、`M1-T03`；T04-A 按开发准入表消费其已接收基础子项及主模型证据。

**阅读：** DD05／DD11、R17／R18／R56、AC56、V17、G05／G15；M0 主模型结论。

**改动归属：** Client 配置卡片、正式配置服务、ctx.llm 路由使用方；复用底座凭证机制。

**执行分工：** 模型 subagent 负责路由与官方配置复用，Client owner 提供卡片扩展点；可与 T05 分目录并行。凭证服务和公共配置 schema 由集成人合入。

**步骤：**

1. 先盘点官方模型编辑器、秘密输入控件和凭证服务的可复用导出；由会话与卡片完成配置，必要时只新增薄适配，不另建凭证库。验证官方控件不能直接嵌入时的合法替代，不能把唯一入口悄改为独立设置页。配置提供方、模型及能力；秘密不经过聊天消息、工具展示或导出。
2. 按 RC 的 DeepSeek Messages-only 配置及其他提供方各自协议真实测试连接，拒绝旧 DeepSeek protocol 配置，区分错误密钥、不可用模型、模态不符与临时错误；未配置轻量决策模型时选合法替代路线，缺必要能力时保持未就绪。
3. 按任务类型选择已配置能力，保存版本／实际选择；rc.2 提供方依赖及 catalog 变化影响的路线须经真实请求复验，列入 catalog 不等于连接或能力通过。toolUpdate、缓存与模态能力仅按实际适配器声明启用，不宣称各提供方具有相同缓存收益。更换和删除凭证使受影响任务进入可恢复等待，不能清除任务或让进行中请求悄然切模型。

**交付：** 安全配置流程、RoutePolicyRevision、实际连接证据及凭证生命周期结果；M2 分析和 M3 重试消费同一入口。

**接续：** T06 接收可从会话调用的配置动作；M2-T02／M3-T02 获得稳定 RoutePolicyRevision、错误分类和凭证失效事件。

**正常验收：** 全新数据目录可完成一次真实主请求；合法无轻量决策模型配置可工作，记录实际模型。

**失败对照：** 错误凭证／模态不匹配有可恢复说明；检查聊天、日志、错误、导出无原始密钥，删除活动凭证不丢任务。

**停止条件：** 仅有假连接、需要把密钥写进普通消息或主路线未通过 M0 时不得标记配置就绪。

**M1-T05：只读保护、环境声明与授权原语**

**目标：** 在第一条业务变更前建立所有调用路径必须遵守的策略。

**前置：** 整卡验收依赖 `M1-T02`、`M1-T03`；T05-A 按开发准入表消费其已接收基础子项。

**阅读：** DD03／DD04／DD07、R12／R25／R54、AC12／AC54、V08／V15、G06。

**改动归属：** web-test-policy、实际工具／命令执行入口和领域授权记录。

**执行分工：** 策略 subagent 独占策略判定和执行前拦截，独立审查者设计热启用／审批越界反例；与 T04 并行时不改同一 profile／schema。

**步骤：**

1. 登记被测代码根及解析后的受保护路径，明确上传／下载／临时材料目录；检查链接、替换和不明命令，禁止任意 shell、编辑器及无限制桌面入口。
2. 定义每入口环境声明、数据范围及修订；测试授权不适用于生产／未知。具体流程授权含记录／次数／有效范围，环境变化失效重验。第三方授权独立存在。
3. 让普通对话、skill（技能）、PTC、MCP、直接服务、重试和未来原生执行器共用不可放宽的执行前判定；官方 approval 与此限制同时生效，模型不是唯一守门者。
4. 覆盖会话中热启用新工具、官方引导启用编码工具、Creator／默认预设变化及自动审阅拒绝后人工批准等路径。rc.2 关闭 `developerTools` 不会移除 Creator 或默认预设选择，须验证实际装配及执行前策略，不能依赖 UI 可见性；既有 Windows ACL 诊断也纳入已启用 Skill 清单。审批仅能放行产品允许的动作，不能覆盖源码只读、任意终端／编辑器禁止等硬限制。
5. 必需业务确认与用户问题等待状态分开；超时、pending、跳过和取消都不授予权限。迟到答案须核对调用／问题、拟执行动作及当前项目／环境／计划修订，才可接收其明确授权；过期或不匹配答案拒绝，必要时重新澄清。独立工作可继续，依赖该确认的动作保持阻塞。

**交付：** PolicyDecision 约定、EnvironmentDeclaration／ActionAuthorization 记录及跨入口拒绝矩阵；T06 展示，全部执行器调用。

**接续：** T06／T07 只调用已验 PolicyDecision；M2／M4 每个新执行器登记接入点及拒绝证据，不自行实现更宽松副本。

**正常验收：** 确认测试环境后，范围内业务动作可获许可；只读观察无须虚构生产写入授权。

**失败对照：** 源码写入、越界数据、过期授权、生产准备／清理及间接发信都不能借一次授权通行；Creator／默认预设变化不能绕过这些限制，timed 问题到期或过期回复不能授权动作。独立核对文件与业务状态。

**停止条件：** 效果不可判断则阻塞具体动作，不能解除保护；保护级别变动必须交用户决定。

**M1-T06：原生对话、项目接入及会话命令**

**目标：** 形成用户日常使用的自然语言入口，支持关联项目和不关联项目。

**前置：** 整卡验收依赖 `M1-T03`、`M1-T04`、`M1-T05`；T06-A 按开发准入表消费其已接收基础子项。

**阅读：** DD04／DD05、AC01／AC06／AC20／AC26／AC54／AC56、G03／G15。

**改动归属：** Client 会话／卡片、项目领域服务、原生 agent 装配及 Remote 调用方。

**执行分工：** Client subagent 负责会话命令与卡片，项目服务 owner 负责材料身份；主 agent 将二者接入官方 agent，不让自然语言解析直接执行副作用。

**步骤：**

1. 贯通原生 DSH 普通对话，按当前上下文开放受控工具；实际展示接入当前 UI host、所选 Session 和主面板可见性接口，不重建已删除的 SidebarRightBinding API。不关联项目时不得读取或沿用另一项目的私有上下文。
2. 接收多代码根和多个已启动 URL，记录可达性、登录／环境声明及用户补充要求；不可达时保留记录，不自行装依赖、启动或部署被测项目。
3. 定义查询、生成用例、开始、暂停、恢复、取消的自然语言到类型命令映射；本阶段未实现动作明确不可用。卡片与文本走同一 Remote，状态查询不能启动测试。
4. 登记实际 `tool-ask-user` 模式；省略配置和 `mode: legacy` 仍为阻塞，timed 须显式选择。复用官方问题／答案路径与 T05 有效性判定；选用 timed 时验证超时／pending、重连／重开、迟到答案、取消及重复投递，不臆造授权，也不为已结束调用补造工具结果。依赖动作在取得有效明确确认前保持等待。

**交付：** 项目接入流程、命令解析及会话卡片、真实对话／项目隔离证据；M2 在此接入用例和运行。

**接续：** T07 消费项目面板与 URL／角色状态；M2-T02／T03／T09 消费项目输入和类型命令，查询与执行入口保持可区分。

**正常验收：** 用户可通过对话接入项目、修正 URL／声明，重开读取相同资料；普通对话可独立使用。

**失败对照：** 模糊开始命令提出具体澄清；坏地址、缺材料及无项目上下文不编造就绪，查询不会产生业务变更。timed 问题未回答仅能推进独立工作；项目／环境／计划变化后的过期答案不能启动动作。

**停止条件：** 必须用传统配置大向导才能使用、对话旁路策略或卡片绕过领域服务时先修入口。

**M1-T07：内置浏览器观察、身份与视口**

**目标：** 交付安全的实际浏览器观察基础，为 M2 动作和 M4 复杂能力扩展提供同一提供方。

**前置：** `M1-T02`、`M1-T03`、`M1-T05`、`M1-T06`、已接收的 P01 载体／Broker 路线、适用 P03 证据及完整 M0 准入。基础子项许可不满足这些浏览器前置。

**阅读：** DD02 及能力矩阵、DD03、AC35／AC40、V01、P01／P03。

**改动归属：** 单一 web-test-browser 提供方、必要 TargetBroker／desktop 改动及观察面板。

**执行分工：** 桌面 subagent 负责目标与观察；只读审查者核对隔离，集成人处理 Host 协议。T06 已完成后接入面板，不以临时 UI 假设作为前置。

**步骤：**

1. 通过已验证 Broker 建立 BrowserCarrierDecision 选定的 Electron 载体，观察 DOM／AX／原图，记录目标、文档／frame、观察代次和浏览器版本；Host 内控制面不交页面。
2. 身份分区包含批次、激活代次与角色上下文，生命周期结束释放；视口与桌面窗口、DPI 分开记录，改变尺寸必须重新观察。
3. 连接 T06 的项目面板，呈现真实页面及观察缺口；测量初始受管进程资源，为预算提供数值候选，不把只读观察算完整交互支持。

**交付：** BrowserObservation／TargetHandle 约定、目标资源生命周期证据、观察 UI、ResourceMeasurement 初版及 DD02 对应状态链接。

**接续：** M2-T04 获得含身份和代次的观察接口；M4-T01／T02 扩展同一提供方，资源测量交 M3-T07。

**正常验收：** 页面、frame、视口和截图可对应；重开后重新取得目标，正常跨域业务不被宿主隔离误伤。

**失败对照：** 旧令牌、被替换 DOM、错误应用窗口 ID 和页面访问宿主控制面无权限；观察不完整不能伪报完整。

**停止条件：** 依赖全局调试端口、共享用户浏览器档案或没有实际隔离证据时不开放下游动作。

**阶段交接门槛**

从真实桌面完成安全配置、普通对话、项目接入、环境声明和页面观察，关闭后能读取资料；越界与泄漏对照有效。T06 与 T07 联调及基础资源测量必须完成，不得用空 UI 代替阶段通过。保留此时产生的真实历史用于后续兼容验证。
