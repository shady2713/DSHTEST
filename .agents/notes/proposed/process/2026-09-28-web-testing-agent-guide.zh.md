## 问题

接手 agent 需要明确的事实归属、写入权、依赖证据和授权范围。

## 提案

适用对象：接手本项目的开发主 agent 及其 subagent。用户已撤销等待上游内嵌浏览器的决定；既有开发授权覆盖有界的本地浏览器接入及[准入 M1 子项](2026-09-28-web-testing-tasks-m1.zh.md#development-admission)，须满足对应证据和停止条件。M0 仍未通过；原型存在或准入子项实现都不代表整卡、阶段或产品验收。提交、推送、PR、发布、部署和外部消息仍须明确授权。

当前接续缺口：基座已有内嵌 webview 和桌面装配；P01 缺受控自动化接入及真实验证，完整 P03 浏览器生命周期验收仍被阻塞。rc.1 审计的缓存 Electron 44 连 `--version` 都以 `0x80000003` 退出，须按 R0 复核当前运行环境再判断 API；具体探针顺序由 [M0-T03](2026-09-28-web-testing-tasks-m0.zh.md)维护。保留 P06 局部结果，按协议核对最新复测；人工参照仍按用户决定延期至 M5，不宣称节时收益。P07 普通 Session／fork 与真实导出读票据集成按当前证据复核。历史与当前证据分别登记于同一 TaskRegister，不把旧基座通过转写成新基座通过，也不把已被替代的停工决定当作现行指令。

## 接手与事实来源

先读[上游根规则](../../../../AGENTS.md)、[固定基座](2026-09-28-web-testing-upstream-baseline.zh.md)、本文件、当前[任务卡](2026-09-28-web-testing-tasks-m0.zh.md)及其相关需求、接口和验收。随后读取真实仓库的全部适用规则、代码和前置交接证据。不能凭对话摘要、候选包名或上一位 Agent 的“完成”文字开工。

本应用是单人 Windows 桌面 Web 测试工具。用户提供全部项目代码和已启动网址；应用先生成并确认用例，实际操作页面、受控原生窗口及许可的后端入口，形成报告，不修改被测源码/配置/依赖。授权研发本应用后可修改本应用仓库；产品的只读限制不能误套到研发工作区，也不能因研发有 shell 就向产品开放任意终端。

需求范围由[产品需求](../feature/2026-09-28-web-testing-requirements.zh.md)唯一规定，报告语义由[测试用例与报告规格](../feature/2026-09-28-web-testing-test-case-report-spec.zh.md)规定；[验收](../testing/2026-09-28-web-testing-acceptance.zh.md)决定通过条件。接口见[总体架构](../architecture/2026-09-28-web-testing-architecture.zh.md)与 DD，阶段门槛及 P01–P08 时间盒见[里程碑计划](2026-09-28-web-testing-milestones.zh.md)。任务卡拥有前置、步骤、分工和交付；[覆盖表](../testing/2026-09-28-web-testing-development-coverage.zh.md)拥有 AC/G/V 的责任映射。

实现按用户升级授权采用 dsh-v0.2.0-rc.2，不自动追随后续发布。按[增量升级审查](2026-09-28-web-testing-upstream-baseline.zh.md#rc2-incremental-upgrade)核对桌面 CLI、用户问题模式、模型路线、预设／侧栏接口及继承规则变化；受影响运行证据保持待复验。CODE_ROOT 为当前 DSH 仓库根，DOC_ROOT 为 CODE_ROOT/docs/developer/web-testing；详细规范仍为 proposed Agent Notes。保留 .artifacts/web-testing 历史证据及其原基座和输入，不能视为新组合通过的证据。为当前组合更新 M0-T01 的基座、RulesMap、RepositoryMap、CheckPlan 和集成登记；复用现有工作区，路径不硬编码个人用户名。

本套规范按 feature、architecture、process 和 testing 归入 proposed Agent Notes；proposed 表示产品或实施计划尚未实现，不撤销已确认需求。语言、配对及根目录与应用 README 入口遵循[基座文件](2026-09-28-web-testing-upstream-baseline.zh.md#document-languages-and-entry-points)。上游规则和代码原位保留；根 README 保留上游正文，仅增加应用导航链接。实现后按官方生命周期改写相应决策，并在所属包中维护已实现约定；不要初始化另一套 Harness 治理。

## 主 agent 与 subagent

默认采用主 agent＋最多 3 个并发 subagent；这是资源安排建议，不是最低数量。没有独立任务、工具不支持 subagent 或仅有一个可改目录时串行完成。复杂度高、耗时长且能够隔离的工作才委派，不为填满槽位拆小任务。

| 角色 | 责任 | 不得代替的职责 |
|---|---|---|
| 主 agent／集成人 | 解释需求、判定依赖、维护约定与写入权、集成、控制阶段范围、处理用户问题、最终验收 | 不把 subagent 自报通过当最终结论；不把业务/权限取舍交给实现者自行放宽 |
| 实现 subagent | 完成一张卡或一段明确交付，编写相关正常/失败对照，交付文件与证据 | 不更换底座、不暗增公共接口、不修改其他任务文件、不自签最终验收 |
| 探查／材料 subagent | 上游接口查证、限定实验、可复位样例及独立答案 | 不把预期写入执行 Agent 的上下文，不凭 mock 证明实际运行 |
| 独立审查 subagent | 对照需求、实际差异和证据找反例，检查越界、缺口、恢复与升级影响 | 默认只读；不同时悄改实现/验收，不能替用户批准新范围 |

默认让两个槽位用于互不重叠的实现或探查，第三个用于审查/材料。若三项探查独立，可先用三个槽位做探查，完成后再派独立审查。主 agent 在子任务运行时推进自己的集成、只读审查和后续准备，不反复轮询无变化状态；使用完成通知或有超时边界的等待。

每张任务卡的“执行分工”和“接续”说明具体委派边界。任务编号不对应永久 Agent：同一 Agent 可接连续相关任务，但任务职责、修改范围和证据必须重新界定。不得未经主 agent 安排向下递归扩张团队。

## 派发与文件所有权

派发前在单一 TaskRegister 写明 taskId、依赖证据版本、允许读写路径、接口修订、预期产物、测试入口、占用设备及停止条件。写入范围必须是 RepositoryMap 已解析的真实文件/目录；候选包名只能用于定位，不代表已有 API。约定未定时可以并行只读探索或提出具体草案，不能各自实现一套不兼容类型。

| 共享对象 | 唯一写入安排 |
|---|---|
| 根/package 清单、pnpm-lock、tsconfig、Cordis profile/bundle | 主 agent 或明确指定的集成人；子任务提交所需差异，由持有人落地 |
| 公共 ID/schema、Typert Remote、Host 协议、领域格式与迁移 | 约定持有人修改并通知所有消费方；消费方未重编译/验证前不算完成 |
| 生成文件、目录清单、翻译配对与 snapshot 期望 | 由相应源文件持有人按官方入口生成、审阅；不得手改或同时运行写同输出的生成器 |
| Test Runtime 同一状态机/提交核心、Browser provider 同一目标实现 | 同时一个实现任务写；其他任务读已接受约定或只读审查 |
| Windows 桌面、测试账户、浏览器档案、数据根、独占锁与故障材料 | 每个实验明确归属；抢焦点、故障注入、安装、资源测量在同一设备上串行 |

同一工作区不得并发写同一文件，不能靠“稍后合并”抵消覆盖风险。隔离 worktree/检出可用于独立任务，但不消除共享依赖、协议和集成责任；无提交授权时使用可审阅 diff 或文件交付，不为合并工作流自行 commit/cherry-pick。主 agent 核对当前改动、哈希和所有者后合入本地工作区，不覆盖无关用户修改。

需要扩大 writeSet 或更改公共约定时，subagent 先提出具体原因和消费方影响；主 agent 在已授权范围内重新分工并解锁，不必为普通实现选择反复询问用户。只有产品范围、保护程度、基座整体变更、缺失必要信息或外部权限需要用户决定。审查发现的问题由主 agent 交回原持有人或显式变更持有人，避免审查与实现相互覆盖。

## 推荐执行波次

此表是调度建议，任务卡的精确前置与分项证据是准入依据。表中“可并行”还要求文件、设备、数据和接口互不冲突；任一不满足就串行。已授权范围内，主 agent 可自行派发就绪任务，不需要用户逐卡确认。

| 阶段 | 推荐安排 | 合并与验收点 |
|---|---|---|
| M0 准备 | 主 agent 先完成 T01；材料代理完成 T02，另一代理可只读核对上游接口 | 固定 BaselineManifest/RulesMap/RepositoryMap/CheckPlan，独立材料具备复位与答案 |
| M0 第一组 | 核对 T01 记录及当前 T07 普通请求对照；T08 记录阶段未准入和基于证据的 M1 子项许可。诊断 Electron 运行环境，T04 存储可独立推进 | 保留现有修复，历史失败经复现后才列为当前故障；T07 验证上游已含 #4595／#5214，先恢复 Electron 再判断 guest／CDP 行为 |
| M0 第二组 | T03 接入有限 Host／Main broker，验证现有 webview，并以相同场景对照独立 WebContentsView；P01／P05 对应证据通过后完成 T05 浏览器生命周期 | 受影响 T04／T07／T10／T11 分项独立复验；T06 外部浏览器／原生证据不能证明 P01，单页面成功不能关闭完整浏览器矩阵 |
| M0 收口前 | T09 产品有效性、T11 恢复更新在独立答案／设备下可并行；人工参照仍延期至 M5 | T08 现在可作阶段中评审；完整准入决定等待全部必需证据，含 P06／P07 未关闭项 |
| M1 | 按[准入子项表](2026-09-28-web-testing-tasks-m1.zh.md#development-admission)及实际前置证据，从装配／隔离推进到被消费的定义／存储、配置／策略及普通对话 | 公共 Remote／schema／profile 单持有人，未实现浏览器动作保持不可用；真实浏览器观察／动作及整卡、阶段验收仍遵守全部前置 |
| M2 | T01 材料 → T02 分析 → T03 用例 → T04 执行 → T05 断言 → T06 后端 → T07 数据 → T08 报告 → T09 集成 | 主链依赖强，保持串行；旁路 subagent 只做已冻结约定的审查、材料和失败对照，不提前构建下游假接口 |
| M3 | T01 恢复后，T02 模型重试与 T03 控制在不同文件时并行；其后 T04 停滞与 T05 空间可分工；T06 → T07 | Runtime 共享状态机和提交协议始终单写；故障实验不争用同一数据根 |
| M4 | T01 原生、T02 外部浏览器、T04 时间、T05 回归、T06 Skills 在前置满足后按最多 3 个槽位滚动；T03 待 T01/T02；T07 待 T05 及轻量路线；T08 待 T03/T04 | T09 统一材料与独立答案；T10 汇总能力与完整资源预算。Cua/原生焦点测试串行，模型收益使用同一冻结材料 |
| M5 | T01 构建安装 → T02 更新；T03 全验与 T04 24 小时仅在独立环境和同一候选组合时并行；T05 → T06 | 24 小时负载不得被另一验收修改或占用；候选代码/依赖改变时分析并重做受影响证据 |

允许的分项依赖仅限明确记录的情况。M0-T05、M0-T09 可消费 T07 已通过的主路线，轻量子路线未通过不阻止这两项；T07 整卡仍保留未完成状态。M0-T08 可以记录 M0 未通过，并在核实证据后许可[表内 M1 子项](2026-09-28-web-testing-tasks-m1.zh.md#development-admission)；这不等于整个 M1 或真实浏览器操作准入，完整准入仍须核心 P01／P02／P03、P05 主路线及 P06／P07／P08 证据。M4-T07 必须收到轻量路线已通过证据。其他前置未验收不得自行解释为完成。

## 材料、接口与交接

M0 产物是后续任务的真实输入，不是描述性占位：BaselineManifest、RulesMap、RepositoryMap、CheckPlan、IntegrationSurfaceRegister、FixtureManifest、ProbeResult、BrowserCarrierDecision、StorageDesignDecision、ProductEffectivenessResult、AssetLifecycleDecision、RecoveryUpdateDecision。名称是文档约定，实际文件位置由 T01 按官方规则确定，禁止杜撰已存在的服务 API。

后续主线为：共享定义/Remote → 唯一领域提交/策略 → 受控目标执行/事实 → 断言/报告；模型配置 → ctx.llm → Session 记录 → 持久重试；用例/规则版本 → 执行实例/动作槽位 → 历史回归。下游必须核对前置的实际类型、错误、取消、持久化、生成与版本，不复制公共定义。

验收材料代理掌握独立 Oracle；测试工具及其执行模型不能读取隐藏缺陷清单或验收日志。建立测试执行上下文时使用新鲜上下文，只传被测项目、公开需求、已确认规则和必要工具；禁止 fork 带隐藏答案的讨论历史。修正材料与保留验证材料分开，见过答案后的样例不再充当陌生验证集。样例改动只发生在研发自有材料副本，不能违反被测项目只读边界。

每次子任务交付使用以下字段，主 agent 验收后再更新单一 TaskRegister：

| 字段 | 内容 |
|---|---|
| taskId/status/owner | 任务、负责人、待开始/进行中/待外部条件/待审查/已验收/需返工；分项状态单列 |
| baseline/inputs | 基座 SHA、PatchManifest、当前 diff/文件摘要、依赖交付和接口版本 |
| writeSet/changes | 实际修改文件、生成物、持久化及上游差异；范围变化理由 |
| contracts | 新增/改变的公共输入输出、错误、取消、资源归属与消费方 |
| evidence | 真实命令、cwd、环境、退出码、正常/失败对照、证据位置、外部可观察事实 |
| gaps/resources | 未完成/未执行/失败分开；阻塞原因、恢复条件、活跃进程/设备/未结算操作 |
| next/review | 可启动消费方、禁止启动项、审查意见与处置，不替下游宣布已通过 |

长任务在阶段交接或上下文切换前更新一个紧凑检查点：目标与范围、固定版本、已接受结果、当前文件持有人、运行作业、待办和证据位置。大日志独立保存并引用；恢复先核实进程和工作区，不重复发起未知状态动作。已过且输入未变的检查复用，新改动、失败或新证据才重跑相关部分；正式交付仍完成全部适用门槛。

## 验证与阶段准入

任务自验之后，由非实现者检查需求、差异和失败对照；主 agent 再检查集成状态及必要跨模块场景。审查不是要求每个小改动重复全仓测试，而是检查证据确实覆盖其风险。失败不能通过改期望、减少用例、放宽覆盖或关闭保护解决。

CheckPlan 以固定提交脚本及适用规则为准。以下是定位入口，不是已经执行的记录；参数、平台、密钥及依赖由 M0 核对。

| 变化类别 | 入口与证据 |
|---|---|
| 源码、类型和包 | typecheck、lint、duplication、适用 hygiene/constraints；官方 Host 构建/约定生成先于 Client 使用 |
| 行为和覆盖 | 所属测试、test:coverage、顶层不变量；遵守逐文件要求与真实 Loader 组合 |
| 模型与用户可见行为 | test:snapshot、test:expected、test:web 等适用入口；录制/刷新期望必须审阅，不偷偷重录 |
| Session/持久格式 | verify-persistence-changes 与对应格式/发布检查，读取旧真实材料和中断样本 |
| UI/正式文档 | typed locale、相关 UI 检查、test:docs、doc-sync、双语和生成一致性 |
| 发行/Windows | 实际构建 smoke、适用平台检查、package:desktop:win:x64:unsigned；原生 Win10/11 安装与操作 |

命令使用 `pnpm run <入口>`，但不得把含 POSIX 环境变量语法的脚本片段直接复制到 PowerShell。真实模型请求只使用授权提供方与凭证，不把密钥写入聊天、日志或交接。缺环境/凭证标为未执行，继续独立任务；必须门槛缺证据时停止其下游，不以纯 mock 或截图演示取代真实验证。

Windows 原生输入和安装不能由 WSL 通过替代。浏览器矩阵、24 小时资源阈值、模型质量/收益和全部 AC/G/V 按[覆盖表](../testing/2026-09-28-web-testing-development-coverage.zh.md)追踪；阶段完成与产品完成分别判定。M5 不能把本工具的必需能力缺口包装成“被测项目未验证”。

## 可直接使用的派发指令

接续派发覆盖恢复浏览器接入、M0 复验及明确准入的 M1 子项，同时区分阶段验收。以下为未来用户可复制的指令，当前整理文档不执行它。

