# Agent Note: 验收标准与追踪

Status: proposed

[English](2026-09-28-web-testing-acceptance.md) | 中文

## 问题

完整产品范围与 DSH 工程要求需要独立且可追踪的通过标准。

## 提案

状态：现行验收标准；历史探针不代表最终产品组合已经通过验收。对应[需求 R01–R58](../feature/2026-09-28-web-testing-requirements.zh.md)、[技术设计 TD01–TD12](../architecture/2026-09-28-web-testing-architecture.zh.md)、[报告规格](../feature/2026-09-28-web-testing-test-case-report-spec.zh.md)及[基座与上游升级](../process/2026-09-28-web-testing-upstream-baseline.zh.md)。AC01–AC58 验收产品需求，G01–G16 细化其中的 DSH 工程要求；两者不能互相替代。本文件没有测试运行结果，不代表应用已实现或通过验收。

**验收对象与判定规则**

这里验收的是“测试工具本身”。工具运行后发现被测项目缺陷，是正确结果；工具不具备承诺的操作能力，是工具的交付缺口。能生成一份包含“未验证”的报告，不足以证明相应操作能力完成。

每项验收最终保存：标准编号、所用软件和模型版本、环境、前置条件、精确输入、实际操作、期望、实际结果、证据引用和执行时间。未执行、环境不足、标准尚未满足分别记录，不以“看起来可行”代替通过。设计中的必需场景均应有证据，缺陷处置不能覆盖原始执行事实。

应用交付验收与真实用户项目的覆盖分开：固定验收材料可以包含明确植入的问题和正确行为，以验证工具发现问题及避免误报；不能由这组材料的通过推导所有真实项目都不存在漏报。工具研发的代码覆盖率按所选 DSH 工程规则执行，也不等于被测项目的代码覆盖率。

固定材料的必检功能、适用执行组合、已知缺陷和正确对照由验收方预先确定，不能直接把本工具自己生成的清单当作标准答案。需独立核对实际业务状态和证据；模型声称发现问题或生成了报告不足以通过。后文的跨项对照场景细化既有 AC 条目，不新增产品需求编号。

M0 的 P06 使用预登记陌生项目业务子集与人工参照，按实施计划的有限样本门槛决定是否继续；M2／M4 扩充保留集，M5 复核。P06 不能替代全量 AC，也不据其小样本宣称普遍零漏报。开测、检查脚本通过、模型接通、产品有效性、默认路线收益和升级兼容分别判断。

| 材料组 | 覆盖目的 |
|---|---|
| F1 页面与输入 | 表单、富文本、表格、弹窗、分页、iframe、Shadow DOM、Canvas、拖拽、上传下载、中文输入法和视觉正常／异常对照。 |
| F2 完整业务系统 | 多代码目录、多网址、用户与管理角色、同一业务记录、正常和驳回分支、数据可见性及共同编辑。 |
| F3 后端与时间 | 已有接口或管理入口、异步处理、日志及只读数据、已接受但处理失败、真实定时观察窗口。 |
| F4 历史与版本 | 有来源的旧记录和附件、两个业务版本、旧用例与截图基线、行为变更与未变更对照。 |
| F5 运行故障 | 模型限流和断流、凭证错误、应用与浏览器中断、记录提交失败、通知断连、旧目标、重复请求、空间不足及无实质进展循环。 |
| F6 可选专项 | 明确的性能目标与测量值、受控负载以及已知的会话或对象访问控制问题，包含无问题对照。 |

| G14 正式文档／AC04 | 入库文档按事实所有者、文档种类及当前行为组织；包 README 写明 Model Experience 和 Known Limitations；JSDoc 同步，受配对规则覆盖的文档有英中正文与正式配对记录，生成目录由源生成。 | test:docs、doc-sync（文档同步门禁） 和改动涉及的链接、文档编译、预算、配对、目录及网站检查；记录实际执行，不能伪造伴随记录；[文档规则](../../../../docs/AGENTS.md)、[配对规则](../../../../docs/i18n/README.zh.md)。 |

| G16 升级证据／AC03、AC04 | 升级核对规则及引用、生成物、格式与桌面组合；无 Git 冲突仍需语义审查，底座修改逐项处理。退出／更新检查包含未加载会话的全部持久批次，关闭应用后的待恢复／暂停任务也阻止不合格安装；检查至切换间不接收新任务，失败保留原程序／数据恢复路径，不自动取消任务。受影响的官方性能检查和平台 CI 仍适用；普通更新与恢复更新分别验证；旧逻辑卡住不妨碍合法封存升级，未知动作跨批次核实，成本登记与升级演练相符；按 DD12 审计实际遥测／统计默认值、首启禁用、队列与收集端；所选 desktop 基座已含这些服务，应用行为须另有实证 | 按[上游继承策略](../process/2026-09-28-web-testing-upstream-baseline.zh.md)保存规则、冲突、检查、CI 及兼容结果，完成 V14 安装对照；未执行不计通过；[测试政策](../../../../docs/testing.zh.md)。 |

并发执行的验证材料必须各自拥有端口、目录、浏览器目标和子进程，失败或超时后也释放；只在单独运行时成功不能算稳定。模拟仅用于外部服务和非确定性输入等恰当位置，loader、实际执行者及应检验的下游行为不能全被替身替换。工程记录需保留实际命令、执行基线、环境、退出状态、证据位置及未执行原因，不只保存“全部通过”文字。

**必须单独验证的执行能力**

AC09、AC35、AC40 不能只用一个普通登录表单验收。以下能力逐项记录支持路径及实际结果，暂不支持的首版承诺项属于交付缺口。

| 能力 | 关键验证 |
|---|---|
| 输入语义 | 空值、空格、长度边界、中文与特殊字符、连续及首尾换行；Tab、Enter、Shift+Enter、Esc 的真实语义。 |
| 中文输入法与剪贴板 | 候选、组合输入、确认、取消及粘贴分别测试；粘贴中文不能替代输入法验证。 |
| 多目标页面 | iframe、跨域子页面、Shadow DOM、新标签和窗口、导航返回；角色与目标不串用，旧引用不继续操作。 |
| 复杂控件 | 富文本、Canvas、拖拽、可滚动列表和菜单；操作结果可观察，并使用对应的真实交互路径。 |
| 原生文件流程 | 选择、取消、另存为、文件名和实际内容；直接设置文件路径不能替代原生选择框验收。 |
| 页面视觉 | 长文本撑破布局、遮挡、溢出、截断、弹窗层级和多视口，正常对照不误报。 |
| 权限及原生对话 | 项目适用的浏览器权限提示、打印或原生提示，记录同意、拒绝或取消后的实际行为。 |

**跨项对照场景**

| 关联标准 | 对照场景与必须观察到的结果 |
|---|---|
| AC09、AC29、AC40、AC46 | 同一用例计划两个角色、两个适用视口，只完成部分组合；其余仍是实例及断言缺口。复试不增加分母，几次不完整流程不能拼成完整通过。 |
| AC10、AC29 | 对照未选专项、范围内无服务跳过及用户中途移出一项：分类和分母分别正确，旧计划与已发生结果保留；工具不能自动移出失败项。 |
| AC05、AC15、AC21、AC44 | 扫描期间改变源码、执行中修改 skill 引用材料、执行后删除原文件：采集一致性有说明，运行不静默换规则，历史定位读取保存版本或明确缺口。 |
| AC12、AC35、AC39 | 被测页、iframe、弹窗和报告材料包含调用宿主或执行脚本的内容：不能取得应用权限；真实页面自己的合法脚本及正常业务流程仍能运行，导出文本保持数据语义。 |
| AC22、AC42、AC52 | 两个角色在同站点登录互不覆盖；同一角色的跨入口身份按用例工作。干净上下文与可追溯旧 Cookie／存储分开验证，不能清空旧状态后报告旧状态兼容通过。 |
| AC08、AC09、AC37 | 同 URL 重渲染替换操作目标、页面延迟完成但未超过明确业务时限：旧引用被拒绝，新观察后操作；未加载完的截图不被直接判为布局缺陷。 |
| AC25、AC37 | 已确认外部服务缺失、服务状态未知、发送成功但回执丢失三个场景分别处理；未知不冒充缺失，不重复发送超出授权次数。 |
| AC27、AC50 | 请求只生成用例，同时用例需要新增准备数据：只列出准备步骤，业务环境不发生变更；正式执行时准备动作在已保存计划之后。 |
| AC33、AC38、AC39 | 报告先保存，清理中断后恢复并产生新版本；同时导出前一版本且期间一份证据不可读：旧报告不被覆盖，等待不误标结束，导出不能声称材料完整。 |

**恢复验证矩阵**

| 中断或错误位置 | 必须观察到的行为 |
|---|---|
| 首次创建意图／子实体头／资源入口发布之间中断 | 同 commandId 恢复原资源，不多建项目或批次；未发布入口不启动执行。 |
| 意图尚未提交 | 不派发业务动作；恢复后可以重新准备。 |
| 意图已提交、尚未派发 | 重新核对前置条件后执行一次。 |
| 派发过程中失联 | 标为结果不明确，先查目标状态；不能直接重放。 |
| 业务成功、结果尚未提交 | 查明已成功后保存恢复依据并继续，不重复新增或发送。 |
| 材料写入成功、RunHead 未提交 | 不把孤立材料当权威结果；处理后再推进。 |
| RunHead 已提交、会话通知未完成 | 补投对应通知，进度不丢失，界面不生成重复批次。 |
| 通知已经追加、投递确认未保存 | 重投可按 deliveryId 识别；投影与送入模型的通知不重复触发业务，日志保留实际事实。 |
| 两个 Host 尝试恢复同一批次 | 只有有效写入者能提交和派发；旧所有者不能继续操作，不产生两个执行中的同一批次。 |
| 暂停、取消或接管后模型迟到返回 | 已失效的派发许可不能用于新动作；实际已发生操作的回执保留，用户状态不被改回执行中。 |
| 在途请求或大附件一直没有返回，用户要求暂停或取消 | 立即禁止新派发并撤销许可；控制保存优先，不等待上述请求，在途结果另列。 |
| 暂停／取消时控制存储卡顿或失败 | 保持禁止派发；区分待保存／失败／已保存，不声称未持久化控制能够跨重启保持。 |
| 模型重试再次提出未结算动作，或旧请求在动作已结算后重送 | 关联原动作；已消费槽位返回原结果或拒绝旧修订，不能换 ID 重复执行业务。 |
| 查询暂时不存在记录，但原请求仍可能异步生效 | 保持结果未知；没有终态拒绝或未交付依据，不转为确认未发生、不盲目补发。 |
| 业务结果未知且已确认无进一步观察条件 | 受影响实例阻塞并保留未知事实，其他独立实例继续；不能无限空查、盲目重发或把未知结果当未发生。 |
| 权威记录损坏或版本不可读 | 明确保存或兼容问题，禁止跳过坏记录后显示空历史或完整通过。 |
| 工具请求已入日志，准备／调度失败后步骤关闭 | 已有结果保留；官方机制补齐未开始或结果未知的工具结果后，真实后续模型请求合法且可继续。UNKNOWN 动作仍经原 operationId 核实；日志写入失败或既有闭合坏历史不能假称已修复。 |
| 仅日程消息或默认 Jobs 记录显示已完成 | 不能据此完成测试实例；核对权威 RunHead、真实断言和业务结果，重复唤醒不重复派发。 |
| 模型流只返回部分输出 | 不执行未完成决策，记录失败并按类别恢复。 |
| 浏览器重建、页面代次变化 | 旧元素和坐标被拒绝，重新观察后操作。 |
| 异常模拟尚未解除 | 恢复核对模拟状态，隔离影响并解除；不污染后续用例。 |
| 用户暂停已持久保存后重启 | 保持暂停；用户明确继续后才核验并推进。 |
| ctx.llm 辅助请求处于退避等待时重启 | 恢复原等待与重试计数；重新核验观察和控制状态，不重新叠加 SDK／工具重试。 |
| 永久凭证错误 | 提示所属会话并保留任务，不高速无限重试。 |
| 日志或证据无法持久化 | 停止新增业务变更派发，说明保存问题；不伪造已保存结果。 |

**长任务与速度评估设计**

必须完成至少一轮实际持续 24 小时的验收任务，期间包含明确的等待、临时 API 故障、页面重建和应用重开；核验进度、资源、证据和恢复结果。另以可控时间测试调度逻辑，但不能用模拟时间的通过代替真实长时间运行证据。24 小时是本应用提出的验收样本时长，不是 DSH 官方要求、用户任务上限或插件硬编码默认值，也不是已经运行的测试。

V07 的资源通过标准必须引用已冻结的 ResourceBudgetRevision，包含参考硬件与负载、全部受管进程统计范围、内存峰值／增长、句柄释放、各采集模式磁盘增速及本地控制延迟的数值。测量与冻结职责归[实施与验证计划](../process/2026-09-28-web-testing-milestones.zh.md)：M0／M1 采集基线，M3 冻结已实现组合，M4 补充新路线并在 M5 前冻结完整组合，正式验收按原值判断。历史测量不代表当前组合已有冻结预算，不填任意数值；预算缺失或运行后改阈值不能通过。M0 探查通过也不能代替本文件的完整运行验收。

模型收益按 DD11 的 A 通用模型、B 确定性执行＋歧义处理、C 轻量参与三组比较，固定用例、输入、环境、断言和数据复位。样本、重复次数、质量门槛、主要收益指标及容差运行前冻结，首轮与回归分列。计入候选构造、复核、重试、错误动作、检出／误报、未验证和人工活动时间；用量未知单列。能力接入可通过而收益未获证明，此时不能默认启用 C 或声称提速；最终仍须交付至少一条真实合格轻量路线。

**交付判定与当前状态**

- 所有适用的首版能力均需通过相应标准；用户未选的专项不在普通业务批次执行，但专项能力本身仍有 AC11 交付标准。
- 固定验收材料中事先明确的必检问题应有正确证据和结论，正确对照不应被无依据标为缺陷；不扩展为对未知真实项目的全检出保证。
- 未授权修改源码、超范围真实外部操作、错误报告通过、恢复导致重复业务操作、历史结果被覆盖或归属错误，均不能通过相关交付项。
- Windows、真实浏览器与原生输入、真实 loader 组合及模型提供方的必要验收不能全部用模拟结果替代。测试环境缺失时标记未执行，不计为通过。
- 用户评审确认、文档覆盖核对、技术试验、工程测试和产品验收分别记录。文档通过审阅不等于技术探查、工程检查或产品验收通过；没有真实执行证据的项保持未执行。

详细设计对应的 V01–V18 场景见[DD13](../architecture/2026-09-28-web-testing-design-models-release.zh.md)，补充实际输入、故障和必须观察的结果，不另增产品需求编号。C01 已确认当前账户下的应用层受控操作；Windows 最低构建和安装路线的确认状态由 DD12 维护。

验收状态：AC01–AC58、G01–G16 和 V01–V18 尚无已验收的最终产品组合，历史分项证据保留其版本范围；C01–C03 为已确定的产品边界，I01–I05 为待实施验证的关键集成点。实际状态与证据只在实施任务记录维护，本文件作为通过标准，不用文档审阅关闭实测项。
