## 这次改了什么

Windows 复验确认的四个缺陷各有对应修改，逐条都有变异检查证明测试有效。

**归属判定。** 浏览器调用按实际被调用的 mount 解析 owner，凭据与 owner 的
runKey / role / generation 逐项比对。此前按 session 取首个合格运行，
两个运行各自声明 `buyer` 时会把一份凭据交给另一个角色的浏览器。

**凭据不回落。** 带了凭据就按凭据判定。此前一个无效凭据会被洗成准备路径。

**收养路径。** 环境预挂载的浏览器被收养时必须一并改写归属；只改挂载不改归属，
owner 仍指向那个 runKey 为空的运行，于是每次带凭据的调用都被拒，取消也选不中它。

**释放路径。** `releaseRun` 按 owner 选目标；`releaseAll` 按真实挂载键释放；
`releaseRole` 先读后删并清认领与归属；启动中取消的挂载自行释放后报错。

**Windows 权限。** `mkdir` 的 mode 在 Windows 上不生效，`chmod` 只切换只读位，
新目录保留继承来的 ACL。改为用 `icacls` 加固插件自己的数据根，账号取
`%USERDOMAIN%\%USERNAME%`——不带域限定时，域账号机器上会授权给另一个主体。
证据目录准备时在 Windows 上明确告警，不再沉默声称目录仅属当前用户。

## 门禁

```sh
cd dsh-plugin-web-test
bash scripts/check-delivery-identifiers.sh 0.8.1   # 记录里的提交/哈希/版本与包一致
bash scripts/check-candidate-tarball.sh            # 候选包自身
```

`check-delivery-identifiers.sh` 现在接受版本参数，并把包内文档改为与**记录里的
提交**比对。此前它拿包的文档和今天的工作区比，候选包一旦交付、文档再更新，
就会永远报「已过期」——那是接线错误，不是包有问题。
