## 0. 撤回结论

**撤回“S0–S6 全部完成”的结论。** 这些交付阶段被按名称罗列，仿佛每个都已完成；实际上只有 S0 端到端测量过。**“明确记录未实现”不等于“需求已完成”**，本表不再把已记录的缺口当作完成度，也没有任何一行通过缩小范围或放宽完成条件来显得已完成。

业务清单仍以 [产品需求 R01–R58](../feature/2026-09-28-web-testing-requirements.md) 为准，交付顺序仍以[可安装插件方案](../architecture/2026-10-04-web-testing-installable-plugin-plan.md) 的 S0–S6 为准，用例与报告字段仍以[用例与报告规范](../feature/2026-09-28-web-testing-test-case-report-spec.md) 为准。

### 状态取值

| 取值 | 含义 |

### 平台依据

本表出现两个平台，二者不可互相替代。

- **Ubuntu 24.04 / Node 24.15.0 / pnpm 11.7.0，未修改的 DSH 0.2.0-rc.2**——§4 的宿主证据，全部在本轮之前采集。
- **Windows，本轮**——依赖安装、`tsc`、打包、Typert 生成与 68 个单元测试均在本机通过。**本轮没有发生 DSH 宿主运行**，因此没有任何需求从本轮获得宿主证据。本机安装的 `dsh` 为 `0.1.5-rc.1`，而本包声明 `0.2.0-rc.2`，无法针对兼容宿主执行安装件验收。

## 4. 本轮之前测得的证据

在未修改的 DSH 0.2.0-rc.2（Ubuntu 24.04）上逐条取得，且因所覆盖代码路径未发生变化而继续有效：

1. 插件通过插件管理器从 tarball 安装进干净 profile，宿主以零失败插件启动。
2. 设置中出现本地化的“Web 测试”分区，并通过类型化 Remote 渲染宿主实时数据。
3. `webTest/status`、`webTest/putProject`、`webTest/listProjects` 往返成功；非法参数被严格编解码器以 `gateway/input-invalid` 拒绝。
4. 业务数据落在插件自有 SQLite 数据库；宿主 JSON 后端从未被写入；进程重启后数据可读。
5. 把存储的版本戳改为 99 后，存储拒绝打开并指出版本不匹配，而不是读成空。
6. `web-test` 预设在真实模型轮次中执行：`web_test_*` 与 `mcp__playwright-mcp__*` 被放行，而组合中确实存在的 `bash` 被拒绝。
7. 官方 Playwright MCP provider 驱动系统 Chrome 完成最小测试并返回真实截图。
8. 活动运行期间禁用 `include:web-test` 会停止派发并排空存储；重新启用后服务恢复且数据完好。

更早轮次得出、仍然有效的结论保留在本文件的 git 历史中。

## 5. 宿主限制与已记录的偏离

1. **存储不走 Storage Domain。** 域路由是宿主 `Config` 级决定，可安装 bundle 无法改写宿主所属行。插件改用 `ctx.storage.backend.get('sqlite').kv.open(...)` 打开自有单元，自行保证单写者与精确版本匹配。
2. **Typert 产物由脚本生成。** 官方生成器在独立工作区中解析不到服务贡献。插件以官方产物相同的格式直接生成 `typert.host.js` 与 Remote 贡献，不引入第二套 RPC 协议。
3. **浏览器归会话所有。** 浏览器行位于预设内，因为在宿主层挂载 provider 会把浏览器工具暴露给所有普通会话。因此禁用会停止派发并排空插件存储，但无法收回活动会话的浏览器，且宿主未公开会话关闭接口。
4. **插件拥有自己的行。** `dsh-storage-sqlite`、官方 Playwright MCP provider 及其同级 `dsh-browser-use` 未随未修改的 CLI 分发，因此插件把它们声明为自己的安装依赖。
5. **`single` 布局的单元无法重新盖戳。** 后端拒绝除描述符版本以外的任何版本，也不提供用更高戳覆盖更低戳的方式，因此提升记录版本会搁置每一个既有数据库而不是迁移它。v3 之后新增的字段因此带有记录在案的默认值，而本模式不认识的戳仍然拒绝打开。代价：早于该字段的构建会忽略它。本轮通过读取缺少后续字段的记录、以及拒绝 99 戳两项实测确认。
6. **报告只有中文。** Markdown、HTML、JSON 共用同一次派生，但只有一套措辞。Client 分区由 locale 拥有；导出的报告不是，且选择 locale 未实现。
7. **报告未本地化但已转义。** 用例自身的措辞来自模型阅读任意被测页面，因此 HTML 导出会转义它们；这是安全属性，不是本地化属性。

## 6. 本轮发现并修复的缺陷

| 缺陷 | 为何重要 | 修复 |
|---|---|---|
| 干净树上 `pnpm run build` 失败 | 解决方案配置只引用 host 面，`lib/types/client/*.js` 从未生成，客户端 bundle 无法解析入口。已发布构建不可复现。 | 解决方案根现在同时引用两个面；工作区程序仍只引用面配置。 |
| 发布的 tarball 混入早期构建的 chunk | `clean: false` 配合内容哈希的 chunk 名，使 `lib/shared` 里每个共享 chunk 都留下两份，包装中同时带着陈旧代码与当前代码。 | 清理列表只包含各 bundle 自身的产物，保留 tsc 的 `lib/types` 与 Typert 产物。 |
| 本包完全没有测试 | `package.json` 声明了 `test: vitest run` 却没有依赖也没有测试文件，该命令无法运行。R04 与方案 §12 都要求覆盖记录校验、状态转换与报告统计。 | 三个文件共 68 个测试，通过真实 `Storage` hub 与复现了版本戳与关闭语义的内存后端驱动真实 store。 |
| 一个被 hold 的运行会停掉宿主内所有会话 | `heldRun()` 返回任意被 hold 的运行，于是被暂停的运行会拒绝另一个会话的无关工作。这违反 R48。 | hold 限定到运行所属会话；没有记录归属的运行仍会停掉所有人，因为插件无法判断它会中断谁的工作。 |
| hold 文案指向不存在的工具 | 它让模型调用 `web_test_resume_run`，而该工具从未注册且被策略拒绝。模型无法执行的拒绝是死路。 | 文案改为请求操作者处理，重启中断则单独解释。 |
| 重启对账摧毁了持久等待 | 在每个被中断运行上清空 `waitingUntilMs`，会让 R51 的持久截止时间恰好在其存在意义的那次重启中失效。由为该规则编写的测试捕获。 | 已在等待的运行继续等待；暂停与待答问题同样不由重启来改写。 |
| `report_case` 接受非执行中运行的结果 | 被暂停、已取消或被中断的运行可以记录它从未执行过的步骤的结果。 | 记录结果要求运行处于执行中。 |

## 已考虑的备选方案

- **把浏览器行移到 bundle 根行**：已否决；会把浏览器工具暴露给普通会话，违反按会话选择加入。理由见 §5.3。
- **继续使用 Storage Domain**：已否决；需要改写宿主所属行。理由见 §5.1。
- **为新字段提升记录版本**：已否决，理由见 §5.5；不认识的版本戳仍必须拒绝打开，而已认识的旧版本戳在升级后仍必须可读。
- **重启时自动恢复被中断的运行**：已否决。重启无法核对环境、登录，也无法确认业务操作是否落地，自动恢复恰恰是需求禁止的盲目重试。资格检查尚未实现（R37），在实现之前该运行等待操作者处理。
