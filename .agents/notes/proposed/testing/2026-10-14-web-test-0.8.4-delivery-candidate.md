## 一、ACL：Windows 报告的四类「失败却报告成功」

Windows 用目标提交原样提取的函数、真实文件系统和真实 icacls 在新建合成
目录验证，发现函数成功返回但 Everyone 授权仍在，四组用例都如此。

**A 解码。** `icacls /save` 写的是 UTF-16LE，本机没有字节序标记。按 utf8 读
会在每个字符之间得到替换字符，扫描标识符的结果为空，于是修改前的枚举和
修改后的检查都认为「没有任何人可访问」，函数对一个根本没读过的目录报告
成功。现在按字节判断编码——无标记的 UTF-16LE ASCII 文档每个 ASCII 字节后跟
一个 NUL，这是字节本身的性质，不依赖任何声明。

**B 别名。** 真实 SDDL 不写数字标识符：系统是 `SY`，管理员组是 `BA`，
Everyone 是 `WD`。原来的解析器只找数字，把一个真实 dump 读成「没有授权」。
身份是最后一个 `;` 分隔的字段（它并不带自己的括号），现在按字段解析，别名
表解析成数字，比较只有一种表示。

**C 属主。** 默认属主是 `DOMAIN\USERNAME`，而枚举结果是数字标识符，两种拼写
永远不相等，于是命令生成器对**属主自己的标识符**发出了 `/remove:g`。属主现在
也走 `whoami /user` 取标识符，grant 与 remove 用同一种拼写，grant 对数字
标识符加 `*` 让工具按标识符而不是账号名解释。

**D 保留策略。** `/inheritance:r` 删掉继承授权，机器的系统与管理员条目就在
其中。把它们留在比较列表里只能阻止被删除，不会写回去——那是声明而不是实现。
现在在删除之后显式补发两条授权。

另外：读不出任何条目的 dump 现在明确失败，而不是当作空 ACL；恢复失败不再被
吞掉，目录不会被留在没有属主条目的状态却报告成功。

## 二、角色切回：保住前轮的越权修复

上一轮把「本代次已核验的角色」的准备窗口永久关闭，挡住了跨代次的越权，也
一并挡住了切回——`assume_role` 的内部身份复验要 navigate 与 evaluate，而
`readAccount` 的这两次调用不递上任何凭据，于是被守卫当作准备调用拒绝。
结果 buyer → seller 成功，再切 buyer 被拒，`activeRole` 留在 seller。

现在给这次检查自己的凭据：绑定运行、角色、代次、Agent，用途固定为读回该角色
账户；守卫只放行目标角色挂载上的 `browser_navigate` 与 `browser_evaluate`，
且 evaluate 的函数体必须就是那个探针；`requireAuthority` 单独校验运行在跑、
代次未变、角色已声明；用完即销毁，成功失败都销毁。

没有任何入口接受外部传入的值，模型伪造不了。凭据也不是 authority——持有它
只能看，不能以该角色行事。

## 三、工具成功路径 11/12

`begin_operation` 之前被归为「需要真实浏览器」。它并不需要：浏览器只参与决定
角色持有哪个账户，而那个决定已经在记录里。用真实 store 备好运行、声明角色与
已核验身份，再签发真实 authority，工具完全跑得通——返回值通过它自己声明的
output schema，render 也接受同一个返回值。

现在只有 `assume_role` 一个走不通。

## 四、门禁与文档

`check-candidate-tarball.sh` 原来要求重打包字节完全相同，因此在 Windows 上
卡死：tar header 带文件的权限位，原包对三个文件存 0600，Windows 上打的包存
0644，内容一样但字节不同。现在分开检查并分别报告：

- **字节一致**：只在产出原包的那台机器上成立
- **内容一致**：包里每个文件逐一相同，与谁打的包无关

**没有为了让数字对上而替换已交付的包。** 交付记录的 SHA-256 是那个包的凭据。

验收单指向 0.8.4 自己的记录；写清门禁用 `--untracked-files=no`，检查的是
跟踪文件的改动范围，**不覆盖未跟踪的新增文件**。

## 未验证 —— 需要 Windows

1. **`icacls` 的真实执行**，包括 `/remove:g` 与 `/grant:r` 的 `*SID` 参数形式。
   Windows 上此前的参数对照也没有成功，因此「给 SID 加星号」**是有依据的
   实现选择，不是已验证的修复**
2. **另一实际身份的有效读写拒绝**，从未执行
3. **浏览器进程**在取消、单行禁用、整包禁用后是否真的退出
4. `assume_role` 的成功路径，以及角色往返在真实浏览器上的表现

**本次关于角色的证据是方法组合证据**——实际 `WebTestStore`、注册的
`execute`、`readAccount` 与 `guardReason`，存储介质、浏览器响应与挂载使用
内存替身。**这不是桌面端到端证据。**

桌面安装。Windows 上用 **Git Bash**；本机裸 `bash` 指向未就绪的 WSL 入口。
