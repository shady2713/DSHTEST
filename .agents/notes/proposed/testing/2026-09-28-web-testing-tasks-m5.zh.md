# Agent Note: 开发任务：M5 验收与发行

Status: proposed

[English](2026-09-28-web-testing-tasks-m5.md) | 中文

## 问题

最终候选需要原生安装、完整独立验收及真实长时证据。

## 提案

正式最终候选验收仍待执行；任务状态由协作指南及其 TaskRegister 维护。任务接口、改动归属、独立复核、检查和交接格式以[agent（智能体）开发与协作指南](../process/2026-09-28-web-testing-agent-guide.zh.md)为准。改动归属须经 RepositoryMap 解析为真实路径，并在派发时登记。前置完成指交付物已被消费方和独立复核者接收；提交代码或口头宣布完成不等于满足前置，明确标注的分项依赖除外。

本阶段 6 张卡。T03 与 T04 可在同一冻结候选上由独立验收 subagent 并行取证，使用隔离材料和数据根；资源验收设备不得叠加功能验收或构建负载。没有独立设备则顺序执行。24 小时是实际验收时长，不是工作量承诺或任务运行上限。工程检查贯穿开发，本阶段做最终组合核对，不是第一次执行检查。

**M5-T01：候选构建与原生 Windows 安装矩阵**

**目标：** 证明真实安装产物具备承诺能力，源码启动不能替代交付验证。

**前置：** `M4-T10`。

**阅读：** DD12、AC02／AC03、V13、G02／G13、CheckPlan。

**改动归属：** 官方构建／打包及本应用 profile、安装元数据和产物测试。

**执行分工：** 发行 subagent 执行官方构建与安装，集成人独占依赖锁、profile 和产物；可分派不同 Windows 设备验证同一候选，分别保存 hash 与环境。

**步骤：**

1. 冻结候选实际 SHA／工作区摘要、依赖锁、profile、Electron／浏览器／SDK／模型策略及预算；按官方 Host→Client→Web／desktop 顺序生成，使用声明 exports。
2. 走当前官方 unsigned Windows x64 本地包路线，保存安装包校验和和 BOM；如需实际构建依赖，按规则取得，不提前启用签名／自动更新。
3. 核实所选基座与全部登记本地改动的准确组合、独立产品更新地址及持久任务预检；发行包不得从官方生产渠道自动覆盖本应用。
4. 在 Windows 10 22H2／19045+ 与代表性 Win11 x64 Home／Pro 组合完成安装、启动、浏览器和原生输入，检查多屏／DPI／锁屏恢复及退出。

**交付：** ReleaseCandidateId、BOM、带 hash 的本地安装产物、原生环境矩阵及冒烟测试证据；T02–T05 使用同一候选。

**接续：** T02–T04 只使用签明 ReleaseCandidateId 的产物；输出安装包、源码状态、补丁清单和 BOM 的一致映射。

**正常验收：** 干净设备按说明安装可运行实际业务；系统范围、manifest（元数据清单）和报告一致，本应用配置与官方产品隔离。

**失败对照：** 缺生成物、从旧 lib 运行、WSL 冒充原生、安装门槛暗中提高及关键平台无设备不能计通过。

**停止条件：** 缺必需系统组合或产物校验失败时记录未执行／失败，不能把另一台系统成功当全平台结论。

**M5-T02：手动更新、预检与迁移恢复**

**目标：** 让跟随 DSH 升级和本地安装更新在真实历史及任务状态下安全可判定。

**前置：** `M5-T01`、`M3-T01`。另需 `M0-T11` 的 RecoveryUpdateDecision 和 `M3-T01` 的封存／关联核实交付。

**阅读：** DD09／DD12、基座与上游升级、AC03、V14、G12／G16。

**改动归属：** 安装预检／稳定协调入口、官方持久类型变更记录、迁移与恢复测试。

**执行分工：** 恢复发行 subagent 使用隔离数据和真实旧新安装包，独立者核对原任务及 UNKNOWN；系统安装修改限指定验收环境，不触碰用户日常数据。

**步骤：**

1. 使用真实前代程序／数据验证预检，包含有来源的 V3 Session 材料经官方支持流程迁移到所选 V4 writer；不得用新 V4 记录伪装旧格式；通过同一 PersistentActivitySnapshot 将运行、暂停、退避、等待、未加载会话、封存及应用已退出但可恢复的全部持久任务纳入安装资格判断，不能强行取消它们。
2. 通过同一控制根锁和安装意图协调检查至切换，新任务不得在间隙进入；旧格式读取／检查归明确版本，不让旧程序误读新数据。
3. 保存旧程序及可恢复原数据，注入检查后并发、安装／迁移中断和失败；验证回到明确可用组合，恢复不等于仅 Git checkout。
4. 在真实旧新安装包执行故障恢复更新：旧调度缺陷无法结束且含 UNKNOWN／暂停；用户选择后独立封存与备份，允许通过已验证恢复预检，安装后先 recovery-only，再按资格关联新批次。旧未知动作不能以新 runId 重发；未撤权、未知格式、备份／迁移失败保留旧组合。

**交付：** UpdatePreflight、PersistentActivitySnapshot 预检及读取失败对照、迁移与恢复说明、真实历史读取和 V14 成对证据；后续交付手册复用。

**接续：** T03／T04 取得经验证的安装候选与恢复资格；T06 接收普通更新与故障恢复两份操作流程及失败还原方法。

**正常验收：** 满足资格的手动更新保留历史并能继续合法任务；失败有已验证的原组合恢复路径。分别证明普通更新保护、故障恢复更新可安装、业务可否续测；不能以“有任务就拒绝所有更新”通过。

**失败对照：** 退出应用后仍有待恢复任务、快照不完整／陈旧、检查后新建、锁身份变化和半迁移状态均不能绕过预检；不自动取消用户任务。

**停止条件：** 无法保留恢复路径或数据格式兼容未证明时，不进行覆盖式更新／宣称支持降级；如需破坏性操作另取明确授权。

**M5-T03：58 项产品与详细场景正式验收**

**目标：** 对全部产品承诺逐项取证，区分工具缺口与被测项目未验证。

**前置：** `M5-T01`、`M5-T02`、`M4-T09`。

**阅读：** AC01–AC58、V01–V18、报告规格、封版 FixtureManifest 和独立 Oracle。

**改动归属：** 正式验收执行记录及必要所属测试；发现缺陷交回原功能 owner。

**执行分工：** 独立产品验收 subagent 执行 AC／V，功能 owner 只接收缺陷并修复；可与 T04 并行，必须隔离业务数据、账号、端口及资源验收机器。

**步骤：**

1. 逐项按标准运行正常／错误对照，记录候选 hash、环境、材料、操作、独立预期、实际和证据；每条标准的多个条件都需覆盖。
2. 复现报告中的已知缺陷与未验证项，核对代码只读、环境与第三方授权、动态覆盖、版本历史、skill（技能）、模型路由和原生限制。
3. 将通过／失败／未执行／有依据不适用分开；V07 正式 24 小时结果引用 T04，不因本卡先完成而宣布它通过。发现缺陷返工后按影响重验。
4. 完成 P06 延期的人工参照对比，核对扩充独立保留材料、三类预期依据及人工负担记录；“实现一致”不等于业务通过，固定 fixture（测试前置数据）全过不外推所有项目零漏报。

**交付：** AC01–AC58 实际验收表、V 场景证据索引、缺陷／复测记录；本卡完成不替代 T04／T05。

**接续：** T05 汇总本卡与 T04，缺陷回到对应 M1–M4 owner；报告的复现验证由未参与该缺陷实现的 agent 完成。

**正常验收：** 每个通过项都有可独立复核证据，正确与错误对照有区分能力，报告能由另一位 AI（人工智能）理解和复现。

**失败对照：** 缺 key 自跳过、产品能力缺失写成项目问题、只跑部分条件、自改预期迎合实现和未经授权缩范围均不能全通过。

**停止条件：** 必需项失败或缺证据时保持待验收，定位主责与再入条件；普通本地修复在已授权开发范围执行，不自动发布。

**M5-T04：真实 24 小时持续运行与资源验收**

**目标：** 用实际长时间负载验证任务恢复和已冻结资源数值。

**前置：** `M5-T01`、`M5-T02`、`M4-T10`。

**阅读：** V07、AC15／AC16／AC37／AC51／AC55／AC58、ResourceBudgetRevision、F5。

**改动归属：** 官方持续运行测试及采样记录、独立业务观察。

**执行分工：** 独立稳定性 subagent 持续监测，主 agent 保持检查点与异常接收；不占用全部槽位阻塞其他独立审查。采样和注入独立于被测自报。

**步骤：**

1. 运行前固定候选 hash、参考机、负载、并发、录像、材料、种子、采样和阈值；无数值预算不启动正式判定。
2. 实际持续至少 24 小时，包含预定的限流、断网、重开、定时等待和长历史；记录真实时间和故障施加，不能用快进模拟替代。
3. 汇总全部受管进程峰值／斜率、句柄释放、磁盘增速和控制延迟；对账外部业务次数、报告、用量和源码状态，缺采样单列。

**交付：** 完整时间序列、24 小时证据、预算逐项结果、恢复与业务对账；T05 最终工程关卡引用。

**接续：** T05 取得同一候选完整 24 小时时间序列；中断或候选变更时明确有效范围与重跑判据，不能拼不同构建时段。

**正常验收：** 所有已冻结指标达标，临时故障恢复后继续，合法等待不误报，业务无重复／事实无丢失。

**失败对照：** 只报最终内存、漏独立浏览器进程、删证据减磁盘、事后加阈值或缩短时长均不通过。

**停止条件：** 触发保护性等待不等于测试失败已确定，记录并按判据判断；候选实现变动需评估证据失效范围，不能混算不同构建的 24 小时。

**M5-T05：官方工程检查、文档与升级演练**

**目标：** 证明实现遵守实际 DSH 规则并能跟随升级，而非只符合这套外部设计文档。

**前置：** `M5-T03`、`M5-T04`。

**阅读：** G01–G16、实际各级规则／skill、CheckPlan、基座与上游升级中的符合性门槛、基座与上游升级。

**改动归属：** 所属实现／测试／生成物／正式文档／兼容记录；每项按官方 owner 修改。

**执行分工：** 工程审查 subagent 执行官方门槛，集成人处理共享生成与最终组合；升级演练使用独立工作区，其结果不自动切换已冻结发行基座。

**步骤：**

1. 汇总阶段检查并运行候选所需完整检查，包含类型／lint／duplication／hygiene、覆盖、不变量、真实录制快照／期望／Web、构建和适用平台 CI；缺环境列未执行，不能调低门槛。
2. 检查新增包 README、Model Experience／Known Limitations、JSDoc、typed locale 和正式文档双语／配对／目录／预算；Session 改动核对相关 SDK，持久类型完成检测与变更记录。
3. 在独立本地候选工作区进行一次适用的上游升级演练，记录规则差异、窄改动重应用、语义冲突、生成与历史回归；目标版本执行时重新核实，无合适新版本则写明演练范围，不虚构升级。所选 desktop 基座已含遥测与 product-analytics，按 DD12 验证本应用首启前禁用、收集端、已排队事件及导出状态。工具启用、审批、日程、模型缓存及失败步骤修复同样检查行为变化。
4. 必要修复生成新候选，按影响重跑相关产品／资源证据并更新 BOM；保留未影响证据的复用理由，最终所有有效证据指向一致组合。
5. 对 IntegrationSurfaceRegister 每个内部修改／公共扩展核对升级触发、生成与回归证据，记录实际维护成本并与 M0 估算比较；规范符合、产品有效和升级兼容分别给结论。

**交付：** G01–G16 适用性与实际输出、正式文档、升级差异与回归证据、最终候选一致性清单。

**接续：** T06 只接收候选一致且所有适用检查有结果的交接包；必要修复导致新候选时标明哪些产品／资源证据须重验。

**正常验收：** 规定检查真实通过且失败反例可被拒绝，每文件覆盖按实际基线满足；无 Git 冲突仍有语义核对记录。

**失败对照：** 只给命令名、伪造配对记录、CI 偷重录、删失败测试、把全仓均值当每文件覆盖或缺平台假通过均拒绝。

**停止条件：** 任何适用必需工程检查未运行／未通过，或最终候选与验收不一致时，不宣布可交付；不自行提交、推送、发 PR（Pull Request）。

**M5-T06：发行交接与个人使用说明**

**目标：** 交付可安装、可验收、可维护且限制透明的本地产品与交接材料。

**前置：** `M5-T05`。

**阅读：** 全部阶段 GateEvidence、最终 AC/G/V 结果、BOM、能力矩阵、更新与恢复说明。

**改动归属：** 正式交付文档、产物与证据清单；不新增发布通道。

**执行分工：** 主 agent 负责最终交付清单与结论；未参与主体实现的接手 agent 按说明完成安装、配置和报告复现，独立核对文件与证据链接。

**步骤：**

1. 整理最终安装包／hash、源代码基线／必要 diff、依赖锁、配置及模型路由说明、材料和实际检查索引；敏感凭证不入包。
2. 写首次配置、项目接入、测试／生产声明、用例澄清、人工接管、报告交修复 AI、历史回归、磁盘清理及手动更新／恢复说明；注明 unsigned 本地安装的实际提示。
3. 核对首版边界与全部已确认需求，区分被测项目本身未验证和工具交付缺口；每个限制引用真实能力矩阵及证据。交付后续升级任务模板。

**交付：** ReleaseManifest、用户手册、维护／升级交接包及最终验收结论；本地交付路径可核对。

**接续：** 交付用户可安装的本地包和可继续维护的源／证据；后续 agent 从基座与升级记录接续，不依赖聊天历史或临时 subagent 上下文。

**正常验收：** 不依赖聊天历史的用户／AI 能完成安装配置、一次完整测试、报告复现和指定更新恢复；所有产物指向同一最终候选。

**失败对照：** 缺必需能力、错误系统支持、秘密泄漏、证据链接失效或使用说明与实际不符均不能标整体完成。

**停止条件：** 仅在 AC/G/V 及必要材料齐备后可判完成；没有发布授权不上传、部署、自动分发或发送第三方消息。

**阶段交接门槛**

最终同一候选具备全部 AC01–AC58、适用 G01–G16 和 V01–V18 的真实证据，包含原生 Windows 安装、实际 24 小时、历史升级与恢复。产品必需能力未验不能判交付完成；交付本地包不等于获准发布。

## 考虑过的替代方案

**已记录的取舍。** 源码启动不能代替安装证据；压缩时间或拼接不同候选结果不能代替最终 24 小时验收。

## 验收标准

执行本提案中的正常和失败对照，并满足[统一验收标准](2026-09-28-web-testing-acceptance.zh.md)及相应任务的证据要求。文档迁移不代表这些条件已通过。

## 风险

平台不可用或证据缺失会阻止验收，本地交付不授权发布。
