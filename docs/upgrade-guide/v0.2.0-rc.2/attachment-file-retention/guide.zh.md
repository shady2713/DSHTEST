# 普通文件附件保留

[English](guide.md) | 中文

## 变更

附件服务新增显式的普通文件暂存、所有者引用保留、读取保护及保守删除。JSONL Session 发布现在要求 `commitFileReferences` 完成后，包含文件的批次才能持久化。缺少附件提供方或提交保留引用失败时，该批次拒绝。分叉会话以自己的 Session id 保留继承文件；关闭句柄不会释放已持久化所有者的文件。

Session 日志导出要求在每份引用普通文件的日志进入流之前取得 `acquireFileReadLease`。完成、失败和取消都会释放已取得的保护；拆卸会报告释放失败。其 Host 插件现在要求附件服务，因此缺少提供方时下载路由不注册（404），不再返回 500。提供方替换会重建导出持有者。即使保留策略始终保留文件，定制附件提供方也须实现新增方法。图片保留行为不变。

本地提供方现在要求暂存上传、更新所有者与删除操作使用 storage domain 服务。一个活动提供方独占规范根目录；竞争提供方以 `ATTACHMENT_STORE_OWNED` 失败。旧式保存与历史文件保持未知所有权。显式删除报告移除的规范对象字节，而非物理可用空间。

## 迁移

1. 为定制 `AttachmentStore` 实现补齐 `@deepseek-ai/dsh-attachment` 声明的暂存、所有者、读取租约及删除方法。保留所有权未知的文件，不要把缺少清单视为零引用。
2. Session 事件包含普通文件引用时，为 JSONL 持久化挂载附件提供方。在发布引用前持久提交所有者，仅在引用已持久地不可访问后才释放所有者。为分叉会话保留独立所有权。
3. 为导出插件挂载附件提供方。更新定制导出消费方，在发布引用文件的日志前取得 `FileReadLease`，并在成功、失败及取消时释放每份租约。全部文件读取完成前须持续持有保护，并在拆卸时报告释放失败。
4. Host 上传、持久化与导出消费方将私有文件发布器或读取器绑定到真正拥有 Service 的上下文。将生产者清理保留在绑定的 drain 中，使阶段票据能在提供方关闭前释放。在 Web testing policy 下，模型或直接服务调用不能修改所有者记录或释放其他生产者的阶段票据。
5. 验证引用保留失败不会发布新 Session 产物、分叉会话独立保留共享字节、导出读取期间删除会被拒绝，以及生产者清理在提供方撤出前完成。保留既有 Session 代际与尚未建立清单的历史文件。
