# 原生浏览器输入要求文档可见

[English](guide.md) | 中文

## 变更

受控 Desktop 浏览器动作之前检查原生窗口及 guest 焦点，没有检查当前文档是否可见。导航或重载后，已聚焦窗口可能仍拥有隐藏文档；已派发的输入可能无法到达该文档。

现在，所属窗口及 guest 准备好接收输入时，元素重新验证会拒绝隐藏的当前文档。动作在发送原生事件前返回 `not-executed` 及 `stale-observation`。后台 owner 仍可先恢复窗口，再进行第二次元素重新验证。可见文档输入及既有导航限制仍可使用。[Desktop README](../../../../apps/desktop/README.zh.md) 说明输入要求与恢复限制。

## 迁移

1. 消费 `desktopBrowserControl` 结果时，分别处理 `not-executed` 和 `unknown`。仅有新观察不能证明文档可以接收输入；不要对隐藏文档反复提交同一动作。
2. 将 `unknown` 导航结果视为该动作的结束。保留其不确定状态，并停止对该文档继续输入。可信 owner 可能需要显式重建 guest 或所属窗口，取得新租约和绑定，观察新文档后再开始另一动作。本变更不会自动修复 Electron 的隐藏文档状态。
3. 验证确实隐藏但已聚焦的文档会被拒绝，且不接收输入事件。确认可见文档动作仍会到达页面，后台窗口恢复后会在派发前进行第二次元素验证。
